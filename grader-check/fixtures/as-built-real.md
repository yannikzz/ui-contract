# as-built — 现状记录

> 记录界面**现在实际是什么样**，不是它应该是什么样。
> 本文件不具规范性。什么是正确的，以 `layout.md` 为准。

放在仓库根，与两份规范并排，让对账过程可见。

---

## §1 这份记录是怎么来的

| 来源 | 可靠性 | 覆盖 |
|---|---|---|
| 直接读代码 | 事实 | `src/` 下全部 9 个文件、`tailwind.config.js`、`design.md`、`package.json`、`tsconfig.json` |
| 从 `design.md` 读结构参数 | 事实（文档事实，非代码事实） | §4「布局骨架」的四个数值 |
| 推断 | **假设，需确认** | 见下文每处 (推断) 标注 |

**没有设计稿参与。** 本文件全部来自代码与既有文档，无线框图、无 Figma。因此不存在「稿子与代码打架」的情况需要用户裁决。

**未运行过任何构建或类型检查**：仓库没有构建配置、没有 `node_modules`、`package.json` 无 scripts。所有关于「代码能跑成什么样」的陈述都是读出来的，不是跑出来的。

## §2 现状区域树

用代码实际用的名字，**包括不好的名字**——改名会毁掉对账所依赖的映射。

```
<div class="flex h-screen bg-surface-sunken">   AppLayout 根，无名
├── <nav>                                        Sidebar
└── <main class="flex-1 overflow-auto">          无名，直接吃 children
    └── <div class="p-4">                        每个页面各自声明一遍
        ├── <FilterBar>
        └── <div class="rounded-md border ...">  页面内容
```

| 当前名字 | 声明于 | 今天实际装什么 | 有几处构造它 |
|---|---|---|---|
| （根 div，无名） | `src/layouts/AppLayout.tsx:6` | Sidebar + main | 1 |
| `Sidebar` | `src/components/Sidebar.tsx:3` | 标题「运营后台」+ 3 个裸 `<a>`（用户/订单/设置） | 1 |
| `<main>`（无名） | `src/layouts/AppLayout.tsx:8` | `children`，不加任何结构 | 1 |
| （页面外壳 `<div class="p-4">`，无名） | 5 个页面文件各一处 | FilterBar + 一个内容盒 | **5**（复制粘贴，无共享容器） |
| `FilterBar` | `src/components/FilterBar.tsx:2` | `JSON.stringify(props)` —— 未实现 | 1，被 5 处调用 |
| （内容盒，无名） | 5 个页面文件各一处 | 字符串占位符 | **5** |

**没有任何区域携带运行时标记**（无 `data-region`、无 `testID`、无等价物）。整棵树靠 className 和 JSX 嵌套认人。

**没有右侧属性面板。** `design.md` §4 规定了 360px 的属性面板，代码里不存在。`OrderDetailPanel.tsx` 名字像面板，但它放在 `src/pages/` 下，结构与其他 4 个页面**逐字符相同**（同样的 `p-4`、同样的 FilterBar、同样的内容盒）——它是一个页面，不是一个面板 (推断：文件名表达的是意图，代码表达的是现状，两者不一致)。

**没有覆盖层、没有路由、没有导航高亮。** `Sidebar` 里是三个裸 `<a href>`，会触发整页跳转 (推断：无路由库依赖，也无 Router 组件)。

## §3 现状结构参数

| 参数 | 值 | 声明于 | 有几份拷贝 |
|---|---|---|---|
| 侧边导航宽 | `220px` | `src/components/Sidebar.tsx:3`（`w-[220px]` 任意值）**且** `design.md` §4 | **2**（代码一份、文档一份，目前一致） |
| 侧边导航收起宽 | `56px` | 只在 `design.md` §4 | 1（**代码里没有实现**） |
| 主区最小可用宽 | `640px` | 只在 `design.md` §4 | 1（**代码里没有实现**） |
| 属性面板宽 | `360px` | 只在 `design.md` §4 | 1（**代码里没有实现**） |
| 页面内边距 | `p-4` | 5 个页面文件 | **5**（复制粘贴） |
| 表格行高 | `40px` | 只在 `design.md` §6 | 1（**代码里没有表格**） |

发现：**四个结构参数里有三个只活在文档里。** 220px 是唯一同时存在于代码与文档的，而它在代码里是一个 Tailwind 任意值（`w-[220px]`），不是 token——即改 token 文件不会改到它。

`tailwind.config.js` 里**没有任何间距、宽度、阴影 token**，只有 colors / fontSize / borderRadius。

## §5 差距

这是本文件存在的理由。「关闭成本」列是回答存量策略问题的唯一依据。

| 现状 | 规范将要求什么 | 关闭成本 | 阻塞吗？ |
|---|---|---|---|
| 无任何区域运行时标记 | 每个结构容器经 `Region` 渲染，带 `data-region` | 新建 `src/ui/region.tsx` + 改 `AppLayout`/`Sidebar`：**约 0.5 天** | **是**——白名单没有落点就什么都强制不了 |
| 5 份复制粘贴的页面外壳 | 由 `stage.header`/`stage.filter`/`stage.body` 承担，页面不自己声明外壳 | 5 个文件各改 ~6 行：**约 0.5 天** | 否 |
| `FilterBar` 是 `Record<string, unknown>`，5 个调用方各传各的 | 筛选条是 `stage.filter` 的唯一内容，props 需收敛 | 需要先定义筛选模型，**约 1–2 天**（含业务讨论） | 否 |
| `OrderDetailPanel` 在 `pages/`，实为聚焦槽切面 | 它是 `order` 类型在 `aside.body` 里的切面，不是页面 | 移动文件 + 重写为面板内容：**约 0.5 天**，但依赖 aside 先存在 | 否 |
| 右侧属性面板不存在 | `aside` 区域 + 单槽类型枚举（用户/订单） | 新建：**约 2–3 天**（含切换、重置、角标补偿） | 否，但这是 `list-detail` 页型成立的前提 |
| 导航收起 / 最小宽降级未实现 | `layout.md` §3 的降级级联 | **约 1–2 天**（要实测尺寸，不是断点） | 否 |
| 四类非常态全缺 | 每个页型声明四类的落位 | 规则本身零成本（写进规范）；实现随页面走 | 否 |
| `w-[220px]` 是任意值 | 结构参数由 `layout.md` §3 单点声明，代码引用而非重打 | 1 行：**约 10 分钟** | 否 |
| `design.md` §4 整节是结构内容 | 搬去 `layout.md`，原处留一行指针 | **约 10 分钟** | **是**——留着就是第二个结构权威 |
| token 文件无阴影、无正文色阶、无行高 token | `design.md` 引用 token 而非字面值 | 需要设计定值，**未知**（见 §5b） | 否，但引用会悬空 |

**合计可估部分：约 6–9 天。** 其中阻塞项 0.5 天 + 10 分钟。

### §5b 无法估算的差距（缺值，不是缺工）

以下三项**没有值可搬**——`design.md` 声明了「有几档」却从未给出值，`tailwind.config.js` 里也没有。规范会引用一个不存在的 token，这个洞得由人补，不能由我发明：

| 缺什么 | 现在写在哪 | 现状 |
|---|---|---|
| 阴影的值 | `design.md` §3「阴影只有一档」 | 档数有了，**值没有**。token 文件无 `boxShadow` |
| 正文色阶 | `design.md` §2 只给了主色/面/描边/状态色 | **完全没有文字颜色**。四级字号有了，四级文字颜色没有 |
| 表格行高 token | `design.md` §6「行高 40px」 | 值有了但没进 token 文件，且 token 文件无 spacing 段 |

## §6 命名冲突

同一个词不同意思，或两个词一件事。现在找便宜，以后找贵。

| 代码里的名字 | 白名单里的名字 | 冲突性质 | 处理 |
|---|---|---|---|
| `Sidebar`（组件） | `nav`（区域） | 两个词一件事 | 组件可继续叫 `Sidebar`，但它渲染的容器必须是 `<Region id="nav">`。**组件名与区域名是两个命名空间**，不要求一致 |
| `FilterBar`（组件） | `stage.filter`（区域） | 两个词一件事 | 同上 |
| `AppLayout`（组件） | `app-shell`（区域） | 两个词一件事 | 同上 |
| `<main>`（HTML 元素） | `stage`（区域） | **同词不同义**——HTML 的 `main` 语义与本规范的 `stage` 不重合 | 白名单**故意不使用 `main` 这个名字**，避免与 HTML 元素混读。见 `layout.md` §2 |
| `OrderDetailPanel`（在 `pages/`） | `aside.body` 里的 `order` 切面 | **名字说面板，位置说页面** | 迁移时归位到聚焦槽；这是 §5 里那一行 |
| `panel`（`design.md` §4 用词「属性面板」） | `aside` | 同一件东西两个词 | `design.md` 对齐白名单时统一为 `aside` |

**没有发现「同词不同义」的高危冲突**，除了 `main` 一处，而那一处通过不启用该名字规避了。
