# 视觉规范 —— 招聘流程看板

> **分工。** 本文档拥有**视觉层** —— 换一套品牌皮肤时会变的一切：颜色、字体、间距刻度、圆角、阴影、交互态样式、组件变体。
> 结构层归 `layout.md`：区域树、区域名白名单、列宽、页型、内容分流、非常态落位。
> **切线只有一条：换品牌皮肤时会不会变。** 会变 → 本文档。不会变 → `layout.md`。两者零重叠（唯一的耦合点在 §3 标注了 ⚠）。
> **本文档不含区域树，不含列宽。**
>
> **本文档写规则，不写取值。** 每一个颜色值、尺寸、圆角档、间距档都住在 **token 文件**里，token 文件是代码中唯一的**值权威**。这里只写 token 的名字。
>
> ⚠ **本项目目前还没有 token 文件。** 下面所有 token 名都是按"应该叫什么"写的；值由建这个文件的人按这些名字填进去（见 §token 名字的来源 → 「值落在哪里」）。本文档**不会**把值偷偷写回自己身体里 —— 那会造出第二个值权威。
>
> **同时，本文档是「名字权威」。** token 文件持有值，**哪些名字存在，由本文档裁定**。没有这句话，某个外部约定会悄悄变成权威，而且输出里看不出来 —— 两种方式生成的 token 文件长得一模一样。

命名遵循：**shadcn 核心集（19 个名字，去掉 `sidebar-*` 与 `chart-*`）** · 见 §token 名字的来源

## token 名字的来源

名字是**借**来的，不是发明的，只为一个理由：**同一个概念在不同技术栈里保持同一个名字。** 每个项目自己发明，同一块表面在这里叫 `muted`、在那里叫 `subtle`，资产层每接一个栈就要维护一张翻译表。

借用集是 shadcn 的，**刻意去掉两组**：

| 去掉的 | 为什么 |
|---|---|
| `sidebar-*`（8 个） | 它们是**信息架构的载体**。带上它们，等于把一套导航形状塞给一个从没做过这个决定的项目 —— 本方法最强硬的一条禁令 |
| `chart-1..5`（5 个） | 数据可视化配色。本文档没有任何一章覆盖图表 |

### 借用集只覆盖了一章半，不是整份文档

| 章节 | 覆盖情况 |
|---|---|
| §7 圆角 | **完全覆盖** —— 一个基准加一套派生 |
| §2 表面与层次表 | **覆盖**，除了禁用态 |
| §2 文本层级 | **部分** —— 借用集只有两级，本章需要四级 |
| §2 品牌色与语义色 | **部分** —— 借用集只有 `destructive`，success / warning / info 不在里面 |
| §3 字体 · §4 间距 · §5 交互态 · §6 图标与身份标识 · §8 动效 | **完全没有覆盖** |

没覆盖的章节，本项目自己命名，在声明表里标 `this project`，并遵守配对规则。紧挨借用集的东西照抄它的形状 —— 写 `success` / `success-foreground`，不写 `colorSuccess`。

### 值落在哪里

| | 记录什么 | 冲突时 |
|---|---|---|
| `tokens.input.json`（本轮产出，在仓库根） | 用户把旋钮拧到了哪儿，是**输入记录** | **不算数** |
| token 文件（**尚未存在**） | 当前正确的取值，是**值权威** | **赢** |

**谁来补上这个缺口：** 由 `ui-contract-assets` 按 `docs/ui-contract/config.md` 路径表里记录的格式（CSS 自定义属性）把 `tokens.input.json` 的值落进 token 文件。本文档和它下游的任何一步都**不会**把值写回本文档。

`tokens.input.json` 的键就是上面声明表里的名字。换技术栈只改**格式**（CSS 自定义属性 / `theme.extend` / 主题对象），**永远不改名字** —— 这才是跨栈统一命名真正兑现的地方。

## §1 设计哲学

### 品牌方向（本轮选定）🌡

**方向 B —「疏 · 柔 · 克制」：安静的文档感 —— 沉稳、耐读。**

三个属性轴上的坐标：间距偏疏、圆角偏柔、配色克制（中性色为主，一个品牌色）。

**当时同时摆出的代价，原样记在这里：** 看板一屏能放下的候选人卡比"密"的方向少约三分之一；5 个阶段列并排时，`main.body` 会更早撞上 720px 最小可用宽度、更早触发 `layout.md` §3 的降级。换来的是：连着读 20 份简历、连着写 5 条评价时眼睛不累 —— 这是本产品每天真正在做的事。

**🌡 这是假设，不是事实。** 生成出来的品牌在真实用户看过之前都只是一个假说。
**复核条件：** 用真实的阶段数量和真实的候选人卡内容跑一遍 —— 如果 5 个阶段列在常见窗口宽度下放不下，回头考虑「密 · 锐 · 克制」的方向 A，而不是在这里偷偷把间距刻度整体调小（那会让 §4 的间距语义表失效）。

### 三条原则

原则的检验标准是：拿一个本规范没覆盖的组件来，能不能靠它推出这个组件该长什么样。

**一、一屏之内，只有一个东西是「主动作」。** 🔒

品牌色 `primary` 只出现在 §2 枚举的位置。它一旦被拿来做装饰，「这里可以点 / 这里正在发生」这个信号当场死掉，用户就得靠逐个试探来找可点的东西。

这条原则和 `layout.md` §6「动作只有一个家」是同一件事的两面：结构上动作只有一个宿主，视觉上屏幕上只有一个东西是品牌色的。

**二、间距承载信息，不靠手感调。** 🔒

每一档间距对应一种**关系**（紧密绑定 / 同组不同项 / 小节内 / 组间 / 区块内边距）。要决定两个元素隔多远，先问它们是什么关系，再查 §4 的表 —— 不是眯着眼睛看哪个顺眼。

**三、状态用形状和位置表达，颜色只做加强。** 🔒

任何一个状态，去掉颜色之后必须仍然可辨（靠文字、图标形状、位置）。这条同时解决两件事：色觉障碍的同事能用，以及打印/截图/低质量投屏时不丢信息。

检验方法：把界面转成灰度，还能不能干活。不能就不合格。

## §2 颜色

### 表面与层次

这张表定义**空间层次** —— 谁在谁上面。

| 层 | token | 用在哪 |
|---|---|---|
| 应用底 | `background` | 最底层 |
| 下沉底 | `surface-sunken` | `main.body` 的底，把卡片托起来 |
| 卡片面 | `card` / `card-foreground` | 候选人卡、配置分组、`app.focus` 的切面主体 |
| 浮层面 | `popover` / `popover-foreground` | `app.overlay`、命令面板、下拉 |
| 弱化填充 | `muted` / `muted-foreground` | 表头、分组底、只读区 |
| 悬停填充 | `accent` / `accent-foreground` | 见 §5 |
| 描边 | `border` · `input` | 容器描边 / 输入控件描边，两者**不可互换** |
| 禁用 | `surface-disabled` / `foreground-disabled` + `opacity-disabled` | 见 §5 |

### 文本层级

**四级封顶。不许再加第五级。** 加到第五级，相邻两级就再也分不出来了，层级本身也就不再传达任何信息。

| 级 | token | 用在哪 | 与相邻级的区别 |
|---|---|---|---|
| 1 主要 | `foreground` | 候选人姓名、页型标题、正文 | 比 2 级**更深** |
| 2 次要 | `foreground-secondary` | 摘要行、字段值、说明 | 比 1 级浅一档，仍然完全可读 |
| 3 弱化 | `muted-foreground` | 时间戳、计数、占位、表头 | 比 2 级明显更浅；**不承载必须读到的信息** |
| 4 禁用 | `foreground-disabled` | 禁用控件的文字 | 唯一一级刻意不满足正文对比度阈值 —— 它的意义就是"读不动 = 不能用" |

**方向固定：数字越大越浅。** 不要在某个局部反过来。

### 品牌色与语义色

| token | 含义 | **允许出现的位置（枚举，此外一律不许）** |
|---|---|---|
| `primary` | 品牌色 = 「这是这一屏唯一的主动作」 | ① 每一屏**恰好一个**主按钮 ② `app.nav` 里当前所在的导航目的地 ③ `app.focus` 里当前选中的切面标签 |
| `destructive` | 破坏性动作、错误 | 破坏性按钮、内联错误块的描边与图标、必填校验失败的字段 |
| `success` | 通过 / 已完成 | 状态标签、状态点、`main.footer` 提交成功后的原地反馈 |
| `warning` | 待处理 / 超期 | 状态标签、状态点、队列段徽标的超期变体 |
| `info` | 进行中 / 中性提示 | 状态标签、状态点、内联提示块 |

三条规则，缺一样界面就会糊：

- **品牌色只出现在上面枚举的三个位置。** 拿它做装饰、做分隔线、做图标底色，"可点"这个信号当场失效。
- **语义色只承载状态，面积受限** —— 小标签、状态点、低透明度的浅色底。**绝不整行、整卡、整个大按钮地铺语义色。** 一屏上铺三张彩色卡片，用户读到的是"出事了"，而不是"这三个人处在三个阶段"。
- **`primary` 和 `info` 不可互换。** 前者的意思是"点我"，后者的意思是"这是当前状态"。它们在色相上可能接近，但语义正交 —— 混用之后，用户会去点状态标签。

### 对比度阈值

**正文文本对其背景，最小对比度 4.5:1。**

这个数字**只写在这一处**。两个消费者从这里读它：调值仪表在用户拧旋钮时实时校验，体检脚本在几个月后有人手改了 token 文件之后重新校验。两者都不硬编码这个数字 —— 它们连代码都没法共享（一个是 HTML 模板，一个是 shell 脚本），本文档是它们唯一能共享的东西。

唯一的豁免：文本层级 4（禁用）。它刻意不满足，理由见上表。

### 暗色模式 —— 待定 ✏

**本版本不做，是刻意的，不是漏了。**

暗色模式不是"同一套值换个方式渲染"，它是**第二套完整的值**。支持它会让 token 文件从一张扁平的表变成表的表，同时改变四样东西：本文档的引用写法、体检脚本的悬空名检查、声明表的形状、调值仪表的布局。

「从亮色推导出暗色」是最诱人也最糟的做法：推导出来的暗色几乎一定要手工修，而第一次手工修就推翻了"它是推导出来的"这个前提，最后留下一套半推导半手改、谁也分不清的值。

真要做的时候，遵守一条原则：**保持同样的空间层次，而不是把亮色反过来。**（下沉底仍然比卡片面更"远"，不是更亮。）

## §3 字体

### 字族

| 用途 | token | 回退链 |
|---|---|---|
| 正文 / UI | `font-sans` | 系统 UI 字体优先，中文回退到系统中文字体 |
| 等宽 | `font-mono` | 用于 ID、时间戳、代码片段。**不用于正文** |

**只有这两个字族。** 出现第三个就是漏网，全局改回来。

### 字号刻度

五档。**每一档都有职责，不许写表外的像素值；新字号必须先进这张表，再进代码。**

| token | 职责 | 用在哪 | 限额 |
|---|---|---|---|
| `text-xl` | 页型标题 | `main.header` 的标题 | **每屏至多 1 个** |
| `text-lg` | 对象名 | `app.focus` 标识条里的候选人姓名 | 每个区域至多 1 个 |
| `text-base` | 连续阅读的正文 | 简历摘要、评价正文、说明文字 | —— |
| `text-sm` | UI 默认 | 按钮、表单标签、列表行、导航项。**大多数文字是这一档** | —— |
| `text-xs` | 元信息 | 时间戳、计数、状态标签 | 不承载必须读到的信息 |

### 行高

| token | 用在哪 |
|---|---|
| `leading-tight` | 标题、单行文本、列表行 |
| `leading-normal` | UI 文本、表单 |
| `leading-relaxed` | 连续阅读：简历摘要、评价正文 |

### 行长上限

> ⚠ **`measure-max` 与 `layout.md` §3 的 `app.focus` 默认宽度（400px）耦合。**
> `text-base` 变大，或 `measure-max` 收窄，400px 就装不下可读的候选人摘要了。**改其中任何一边，都必须回头看 `layout.md` §3。** 这是两份规范唯一耦合的地方。

### 字重

三档。

| token | 用在哪 |
|---|---|
| `weight-regular` | 正文、字段值 |
| `weight-medium` | 按钮、导航项、表头、**状态标签（唯一允许的字重）** |
| `weight-semibold` | 标题、对象名 |

**状态标签只用 `weight-medium`。** 它们字号最小（`text-xs`），字重就是可读性的全部依靠；一处写 regular 一处写 semibold，同一排标签会看起来轻重不一，像是在暗示优先级。

## §4 间距

**基准栅格 4px**（值在 token 文件里）。**唯一允许的半档是 `space-0-5`**，此外一律不许出现表外的值。

### 间距语义表

每一档对应一种**关系**。要决定两个元素隔多远，先确定它们是什么关系。

| token | 关系 | 典型场景 |
|---|---|---|
| `space-0-5` | 紧密绑定，几乎是一个整体 | 状态点与它的文字、图标与它的标签 |
| `space-1` | 同一元素的内部呼吸 | 状态标签的内边距 |
| `space-2` | 同组内的不同项 | 一行里的多个字段、按钮组里的按钮之间 |
| `space-3` | 小节内的行距 | 表单里相邻两个字段、列表行的内边距 |
| `space-4` | 小节之间 | `app.focus` 里两个切面小节之间 |
| `space-5` | 组之间 | 看板卡片之间、配置分组之间 |
| `space-6` | 区块内边距 | 卡片内边距、`main.body` 的内边距 |
| `space-7` | 大区块之间 | 看板列之间、`main.header` 与 `main.body` 之间 |

**这一章写刻度的语义，不写区域树，也不写字面量。** 各区域的内边距可以按 token 名列表，但结构关系归 `layout.md`，数字归 token 文件。

## §5 交互态

阶梯：**静止 → 悬停 → 按下 → 选中 → 聚焦 → 禁用**

| 元素 | 悬停 | 按下 | 选中 | 键盘聚焦 | 禁用 |
|---|---|---|---|---|---|
| 按钮 | `accent` 填充 | 轻微缩小 | —— | `ring` 焦点环 | `surface-disabled` + `opacity-disabled` |
| 列表行 / 看板卡片 | `accent` 填充 | 轻微缩小 | `state-selected` 填充 + `border-width-emphasis` 左侧描边 | `ring` | —— |
| 导航项 | `accent` 填充 | —— | `primary` 文字 + `state-selected` 填充 | `ring` | —— |
| 切面标签 | `accent-foreground` 文字 | —— | `primary` 文字 + 下边框 | `ring` | `foreground-disabled` |
| 输入控件 | `input` 描边加深 | —— | —— | `ring` | `surface-disabled` |

### 两条硬规则

- **悬停永远比选中「轻」。** 选中比悬停多**一个视觉维度**（颜色 + 字重，或颜色 + 填充），不是同一个维度上加深一点。同维度加深，用户分不出"我鼠标在这"和"这是我选的"。
- **按下用轻微缩小，按元素尺寸分档。** **不许放大** —— 放大反馈会让相邻元素被短暂遮住，看起来像是布局在抖。

### 「选中 + 悬停」这个复合态，必须显式处理

这是本章最常见的实现 bug：把鼠标移到一个**已经选中**的行上，选中态看起来**降级**了 —— 因为悬停样式覆盖掉了选中样式。

| | 做法 | 结果 |
|---|---|---|
| ❌ 错 | 悬停样式直接覆盖选中样式 | 选中的行一被悬停就"看起来没选中了"，用户以为自己点掉了 |
| ✅ 对 | 选中态**保留**，悬停在它之上再叠一层（选中填充不变，额外加描边或轻微提亮） | 两个信息同时可读："这是我选的" + "我鼠标在这" |

### 焦点环

`ring` **只在键盘导航时出现**（用 `:focus-visible` 一类的机制）。鼠标点击不该触发焦点环 —— 否则每点一下都留一圈框，用户会以为出了什么事。

## §6 图标与身份标识

**只用一个图标库，不混用。** 混用之后同一个概念会有两种画法（两种"日历"图标），而且线宽对不齐。

| 刻度 | token | 用在哪 |
|---|---|---|
| 图标 | `icon-sm` | 行内、状态标签里 |
| | `icon-md` | 按钮、导航项 |
| | `icon-lg` | 空态插图位 |
| 身份标识 | `avatar-sm` | 列表行、看板卡片上的面试官头像 |
| | `avatar-md` | `app.focus` 标识条 |
| | `avatar-lg` | 覆盖层里的候选人 |

**图标和身份标识是两套刻度，不要混。** 它们的视觉重量规律不同：图标是线条，头像是实心块，同样尺寸下头像看起来重得多。

圆角：图标不带圆角（它是图形本身）；身份标识用 `radius-avatar`，**不与容器圆角刻度共用** —— 容器圆角随品牌方向变，头像形状不该跟着变。

**身份标识靠图形区分，不靠背景色区分。** 给每个人、每个职位配一个颜色，是把界面搞花的最快路径 —— 五个人以后你就在色相不够用和"这个绿色是谁"之间二选一。用首字母、用头像图片。

---

## §7 圆角

| token | 用在哪 |
|---|---|
| `radius-sm` | 状态标签、徽标、输入控件、按钮 |
| `radius-md` | 卡片、看板卡片、配置分组 |
| `radius-lg` | `app.overlay` 面板、命令面板 |

**原则：容器越大，圆角越大。** 最大的那一档**只给顶层容器**，绝不给内部区块 —— 大圆角套小圆角，内圈会看起来是方的，两层的曲率对不上。

派生关系：三档都由 `radius` 推导（值在 token 文件里）。改 `radius` 一个值，三档一起变 —— 这就是它作为基准的意义。

**硬规则：表外的圆角必须先进这张表，再进代码。** 在功能代码里随手写一个圆角值，等于在 token 文件之外开了第二个值权威。

## §8 动效

**三条原则：快、克制、可预期。**

| token | 场景 |
|---|---|
| `duration-instant` | 悬停、按下 —— 快到感觉不出有过渡 |
| `duration-fast` | `app.focus` 展开收起、下拉展开、状态色变化 |
| `duration-slow` | `app.overlay` 进出场 |

缓动：`ease-standard`（进出场）· `ease-out`（离场）。**只有这两个。**

允许的过渡类型：不透明度、颜色、位移、尺寸。**不许**：旋转、弹跳、循环动画、任何超过 `duration-slow` 的东西。内部工具每天要用八小时，第三次看到弹跳就开始烦。

**状态色变化必须走过渡。** 候选人从「待面试」跳到「已通过」，颜色瞬间切换会让人怀疑自己是不是看错了 —— 尤其在它是别人的操作触发的时候。走一个 `duration-fast` 的颜色过渡，眼睛就能确认"它刚刚变了"。

## §9 组件用法

### 取用顺序

**先查现有组件库 → 用变体扩展 → 最后才新建。**

新建之前必须回答：现有组件加一个变体为什么做不到？答不上来就是没查。

### 按钮层级

| 变体 | 视觉重量 | 样式 | 用在哪 | 限额 |
|---|---|---|---|---|
| 主按钮 | 最重 | `primary` 实心填充 + `primary-foreground` | 这一屏唯一的主动作 | **每屏至多 1 个** 🔒 |
| 次按钮 | 中 | `secondary` 填充 + `secondary-foreground` | 并列的次要动作 | 每个动作区至多 2 个 |
| 弱按钮 | 轻 | 无填充，`foreground-secondary` 文字，悬停出 `accent` | 密集位置的动作、取消 | —— |
| 破坏性按钮 | 特殊 | `destructive` | 删除、拒绝、撤销 | 每屏至多 1 个，且**不能同时是主按钮** |

「每屏至多一个主按钮」是 §1 原则一的直接落地。两个主按钮，用户就得停下来读两遍才知道该按哪个。

### 状态标签 —— 必须绝对一致

状态标签在这个产品里到处都是（看板卡片、列表行、`app.focus` 标识条、时间线）。**它们必须长得完全一样，否则用户会以为不一样的那个是特殊的。**

**唯一规格：** `text-xs` + `weight-medium` + `radius-sm` + `space-1` 内边距 + 语义色的低透明度底 + 语义色文字。

**只有颜色可以变。** 禁止：改几何形状、加描边、加图标、改尺寸、改字重。

需要一个新状态？加一个语义色的映射，**不要**造一个新形状的标签。

### 长得像但意思不同的形状

| 形状 | 意思 | |
|---|---|---|
| 小圆角方标签（`radius-sm`） | **状态** —— 对象当前处在哪一步 | 不可互换 |
| 药丸形徽标（全圆角） | **计数** —— 有多少件事等着你 | 不可互换 |

**这两个不能换着用。** 一个说"它是什么"，一个说"你还有多少要做"。形状是它们唯一的区分手段 —— 混用之后，`app.nav` 里的队列计数会被读成状态，`layout.md` §7 那套徽标规则也就白写了。

## §10 反模式

| 别做 | 因为 | 改成 |
|---|---|---|
| 到处加阴影来做层次 | 阴影一多，层次就没了 —— 什么都浮着等于什么都不浮 | 用 §2 表面表做层次；阴影只给两处：拖拽中的卡片、`app.overlay` |
| 随手加渐变 | 渐变没有 token，它是一个逃出值权威的口子；而且它在不同屏幕上的表现差异极大 | 用 `muted` 之类的实色填充 |
| 拿品牌色做装饰（分隔线、图标底、标题色） | "这里可以点"的信号当场死掉，用户改用逐个试探的方式找按钮 | 品牌色只出现在 §2 枚举的三个位置 |
| 整行、整卡铺语义色 | 一屏三张彩色卡片，读到的是"出事了"，不是"这三人在三个阶段" | 小标签、状态点、低透明度底（§2） |
| 用 toast 做动作结果的确认 | toast 会飘走，用户切个窗口回来就找不到了，事后也查不到 | 原地反馈优先（`layout.md` §8）；只有结果在视野外时才用 toast |
| 骨架屏做成和真实内容尺寸不一样 | 内容到了以后布局跳一下，用户刚要点的东西移位了 | 骨架保持区域尺寸不变（`layout.md` §8） |
| 在功能代码里写表外的字号 / 圆角 / 间距值 | 每一个都是 token 文件之外的第二个值权威，改品牌时它们不会跟着变 | 先进表（§3 / §4 / §7），再进代码 |
| 只靠颜色区分状态 | 色觉障碍的同事用不了；截图、打印、低质量投屏时信息全丢 | §1 原则三：形状 + 位置 + 文字承载信息，颜色只加强 |
| 悬停样式直接覆盖选中样式 | 悬停已选中的行时，选中态看起来降级了，用户以为自己点掉了 | §5「选中 + 悬停」的正确做法 |
| 给身份标识按人/按职能配色 | 五个人以后色相就不够用，而且没人记得住哪个绿色是谁 | 靠图形区分（§6） |
| 把 `primary` 和 `info` 换着用 | 一个意思是"点我"，一个意思是"这是当前状态"；混用之后用户会去点状态标签 | §2，两者语义正交 |
| 在本文档里写死一个颜色值或尺寸 | 造出第二个值权威，token 文件就不再是权威了 | 写 token 名字 |
| 把声明表里的 `borrowed` / `this project` / `not used` 翻译成中文 | 体检脚本锚定这三个关键词，翻译掉之后它什么也找不到而且**不报错** —— 检查静默失效 | 保持 ASCII，中文写在表头或表旁 |
