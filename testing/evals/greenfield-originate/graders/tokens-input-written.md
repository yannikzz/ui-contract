`originate` 派生出来的值必须**落成文件**，不能只在 `design.md` 里被描述。

这条判据是从一次实测里长出来的，不是设计出来的：五次有效 with run 里 `design.md` 落地 5/5，
而 `tokens.input.json` 只有 2/5——跳过的那几次在 trace 里提到这个文件 12 次和 8 次，
想到了、没写。

⚠ **这条判据的理由 2026-08-25 换过一次，结论没变。**

原来的理由是：ADR-0001 决定 B 的复议条件挂在「用户覆盖生成品牌的比例」上，而这份文件
v1 与调完之后那个 diff 是那个数字唯一的来源，40% 的落地率等于那条复议条件六成时间没数据。
**那个理由已经撤销**——文件移进工作台后不再提交，没有版本可 diff；而那个数字从来没有
任何东西在计算它，ADR-0007 也早就记着 diff 分不出用户的选择和 agent 的误读。

现在的理由更直接：它是调色器具的起始状态。**不写这个文件，Step 3 的器具就没有旋钮可拧。**
落地率仍然是这条判据要盯的东西，只是它保护的不再是一条复议条件，而是下一步能不能开始。

**值本身不靠它了**：`originate` 现在直接写 token 文件，那才是权威。所以这条判据红了，
不再意味着值丢了——意味着调校环节断了。

⚠ **加上这条，这个用例的满分会从 1.00 掉到 0.75，直到产品那边的修复生效。**
那是**真红**，不是判据太严——缺口是量出来的。同一次测量还给出了修复方向：进了
`## Before you call this document done` 清单的东西落地 5/5，只在正文里被描述的落地 2/5，
所以这条判据的对侧修复是把它写进那份清单（已做）。下一次实跑会说这两件事有没有用。

## 这一条只问「写没写」，不问「写在哪」

`**/` 是**故意的松**，与 `tokens-input-at-pinned-path` 成对：前者答「文件存在吗」，
后者答「在钉死的那个位置吗」。两条一起才把三种状态分开：

| 本条 | `-at-pinned-path` | 读法 |
|---|---|---|
| ✓ | ✓ | 正确 |
| ✓ | ✗ | **写了，但放错地方**——黑名单那条 regex 判据同时会 throw，原因在这里，不在判据 |
| ✗ | ✗ | 根本没写 |

不合成一条，是因为合了之后「没写」和「写错地方」会长得一模一样，
而 2026-08-22 那两轮的全部代价正是花在分不开这两件事上。

⚠ **`**/` 这个写法本身也是栽过一次才有的。** 原来写的是 `path: tokens.input.json`——
一个只匹配仓库根目录的 glob，而当时产品**还没有**规定落点，`ui-contract-design/SKILL.md`
反而明写「Artifact paths come from `docs/ui-contract/config.md`'s paths table …
**Never assume a path the config contradicts**」。**判据假设了一个产品明确规定不许假设的路径。**
被它误判的那次（run3）把文件写在 `docs/ui-contract/tokens.input.json`，是**正确行为**，
判据报了 missing。这一条同时污染了此前所有「落地率」数字（2/5、7/8、2/3），那些数字
测的不是「产品写不写」，而是「产品把它写在哪」，全部作废。

那个理由**今天已经不成立了**：ADR-0009 把这个文件从可配置路径表里豁免出来、钉死在
`docs/ui-contract/tokens.input.json`。所以「不许假设路径」不再是保留 `**/` 的理由，
上面那张三态表才是。

VERIFIED 2026-08-21，双向，在同一次跑里正负都出现过——**但那次的正负两个方向都可能是
路径造成的**。2026-08-22 复验 3/3（正方向）。

2026-08-24 读到 **2/3**，而这一次的红**是真的**：run2 根本没写这个文件（沙箱里找过，
全树没有），不是判据路径的问题——`tokens-input-at-pinned-path` 同时红，两条一起读就是
「没写」。所以这一轮同时给了正负两个方向的干净样本，**双向结清**。

⚠ 但那次 run 是超时被砍的（900s），所以「没写」的成因是「没来得及」还是「想不到写」
分不开。这条判据本身已验，产品那一侧的结论要等一轮不超时的 run。
