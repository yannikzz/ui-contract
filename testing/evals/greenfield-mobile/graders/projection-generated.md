结构半场里**该做**的事之一：投影建起来，落在工作台。

ADR-0013 决策一把线框重新定义成 `layout.md` 的**投影层**——用户在交接时点头，点的是
`layout.md`，而投影是他判断这份结构成不成立的**唯一手段**。ADR「排除的备选」里明写过：把投影
一并推到第二条链上，交接时交回的就只有一份 Markdown，用户没有可看的东西。所以它是达成项。

决策六：⏳ 未结算也要先建。投影可再生，重投一次的成本接近零。

## 这一条补的是一个不存在过的判据

`testing/evals/README.md` 曾写着「ADR-0013 的**四条**达成判据看这三个包的产物了」，并据此
把「`assets` / `wireframe` / `enforce` 产物无人守」那笔代价勾销。**但四条里只有三条存在**，
缺的就是这一条——于是 `ui-contract-wireframe` 的产物实际上仍然无人守，而记分板上那笔账
已经销了。这正是 `CLAUDE.md` 记的第三类事故：*一份 PR 描述了一种机制并附了统计，
两者都不存在，因为没有任何东西在比对散文和代码*。

## ⚠ 这条判据守的是「有没有产出」，不是「产出对不对」

2026-08-28 首次实测它是**永远红**的：完工清单要求 dev server 起来、`check-colours.sh` 跑过、
type-check 跑过，三件都要 `Bash`，而套件刻意不给，于是 agent 判断「跑不起来就不建」，
一个投影文件都没写。

ADR-0014 把投影分成了两级——文件层不依赖任何工具，运行层跑不了就点名——所以这条判据此后会
**变绿**。但它从「永远红」变成的不是「守住了」，而是**「永远绿」的风险**：它看的是工作台里
有没有文件，而分级之后无 `Bash` 的跑也会写文件。

**假红显眼，假绿不显眼。** 所以写在这里而不是只写在 ADR 里：这条判据绿了，只说明投影被产出了；
它跑不跑得起来、密度对不对，这条判据一个字都没说。那部分今天无人守（ADR-0014 代价 4）。

## 锚：`config.md` 的 `workbench` 默认路径

**什么能过**：用户把工作台配到别处，或者投影落在 `.ui-contract-local/` 下另起的目录名
（`preview/`、`线框/`）。这条和 `asset-layer-staged` 同一形状，锚在默认值上而不是规则上——
规则是「投影在工作台里」，而工作台路径可配，判据读不到 `config.md`。改路径时它误判为红，
那是**响的**失败，比绿着漏判好。

**不锚文件后缀**：投影的技术栈随项目变（React / Vue / React Native 都端口过），
`*.tsx` 会在非 React 项目上误红。目录位置是三种栈共同的部分。
