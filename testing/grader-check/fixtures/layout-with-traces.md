# 结构规范 — layout.md

> **给编码 agent 的三句话：**
> 1. 改动任何界面结构之前，先走 §1 落位决策树。**落位成功就直接实现，不需要改本文档。**
> 2. 落不了位就**停下**。不要自行开新区域、新页型、新覆盖层。走 §9 变更流程。
> 3. 代码里出现的每一个区域标记都必须在 §2 白名单里。表里没有的名字就是违规。

适用范围：React Native 移动端记账应用。单人开发。
配套文件见 `docs/ui-contract/config.md` 的路径表。

## §0 与视觉规范的分工

**切线只有一条：换品牌皮肤时它会不会变？** 会变 → `design.md`。不会变 → 本文档。

| 项 | 归属 | 为什么 |
|---|---|---|
| 区域树、区域名、嵌套深度 | 结构 | 换皮肤不变 |
| 底部导航条有几个 tab | 结构 | 换皮肤不变 |
| tab 的图标长什么样、选中态怎么描 | 视觉 | 换皮肤就变 |
| 悬浮按钮**存在**、它承载哪个动作 | 结构 | 换皮肤不变 |
| 悬浮按钮的直径、阴影、圆角 | 视觉 | 换皮肤就变 |
| 屏顶栏**至多放 2 个动作** | 结构 | 这是容量约束，不是样式 |
| 屏顶栏的高度值 | 视觉（值在 token 文件） | 换皮肤就变 |
| 列表行**是同构的**（每行结构一致） | 结构 | 这是可扫描性的结构前提 |
| 列表行的行高、分隔线 | 视觉 | 换皮肤就变 |
| 「超支」这个状态**显示在哪** | 结构 | 位置是结构 |
| 「超支」这个状态**长什么样**（颜色、图标） | 视觉 | 形态是视觉 |
| 内边距、外边距、圆角、字号、色值 | 视觉（值在 token 文件） | 全部 |
| 分析块**能有几种**（枚举上限） | 结构 | 这是准入闸门 |
| 分析块内部用什么图表 | 视觉 | 换皮肤就变 |

硬规则：

- 本文档**不含任何色值、字号、圆角、间距值**。结构参数（区域数量、各类上限、最小可用尺寸）除外。需要数值的地方写「见 `design.md`」。
- `design.md` **不含区域树、区域名、页型定义**。
- `design.md` 只写**规则**，数值一律在 token 文件里。这不是新的切线，只是多跳了一层。
- **既有代码不是权威。** 代码和文档打架，改代码。

⚠ **唯一的跨规范耦合点：** `screen-body` 的底部避让内边距 = 悬浮按钮高度 + 底部导航条高度 + 两者的外边距（见 §3 结构事实 2）。改动 token 文件里这几个值，必须回来看 §3；写 `design.md` 时必须在对应章节补上对称的 ⚠ 标注。除此之外两份规范零重叠。

## §1 落位决策树

整份文档的入口。拿到一个新界面需求，从这里一路走到一个**具体的区域名**。

### 前置约定

对**已有区域里已有元素的属性变化**（比如某行多显示一个字段），不需要走树，只需要满足该区域的「禁止放」那一列。树处理的是**新东西该放哪**。

### 短路

先看这几条，命中就结束。**引用短路时永远引条件名，不要引序号**——后面往这个列表里插行的时候，代码注释里写死的「短路 3」会静默地指向另一条，而且没有任何东西会报错。

| 短路 | 条件 | 去处 |
|---|---|---|
| **瞬时反馈** | 操作结果的瞬时反馈（保存成功、已删除、可撤销） | `overlay-root`（toast 形式）。**不进** `screen-body` |
| **破坏性确认** | 继续之前必须让用户确认，且后果不可逆（删除一笔、清空数据） | `overlay-root`（dialog 形式） |
| **新建一笔** | 任何「新建一笔交易」的入口 | `fab`。**不得在任何别处再开第二个入口**，理由见 §10 |
| **屏级取数范围** | 只影响当前屏「看哪一段数据」的选择（月份、年份、周期切换） | `screen-scope` |
| **导航状态提示** | 需要在底部导航上提示某种状态（预算超支、有未处理项） | 走 §7 徽标规则。**点，不是数字** |
| **条目手势** | 作用在某个列表条目上的手势（左滑删除、长按多选） | 归属该条目所在的区域（通常是 `screen-body.list`），并遵守 §3 手势规则 |
| **全局配置** | 全局配置、分类管理、数据导出、备份、关于 | 设置屏（`stack-detail` 页型），入口在 `screen-header` |

**「全局配置」这条短路的条件是封闭枚举**：全局配置、分类管理、数据导出、备份、关于。新增项要走 §9 才能加进这条枚举。它**不是**兜底——「不知道放哪所以放设置」是 §10 明令禁止的反模式，兜底只有一个，是下面的「停」。

### 树干

```
新需求
│
├─① 它是某个一等对象（交易 / 分类 / 预算）的完整切面，需要占满一屏来读或改吗？
│    ├─ 是，且以「编辑 / 新建」为主 ──→ sheet-form 页型的 screen-body
│    │                                   （提交类动作放 screen-footer）
│    └─ 是，且以「阅读 / 管理」为主 ──→ stack-detail 页型的 screen-body
│
├─② 它是对既有数据的聚合结果吗？（一个算出来的数 / 一张图，不是原始条目）
│    ├─ 是 ──→ screen-body.analysis-slot
│    │          须过 §5 准入；枚举已满 → 停 → §9
│    └─ 否 ↓
│
├─③ 它是同构条目的流吗？（每一条结构一致，能被扫读）
│    ├─ 是 ──→ screen-body.list
│    └─ 否 ↓
│
├─④ 它是改变当前屏「看哪一段数据」的控件吗？（搜索 / 筛选 / 排序 / 周期）
│    ├─ 是 ──→ 入口放 screen-scope；
│    │          展开后的面板放 overlay-root（sheet 形式）
│    └─ 否 ↓
│
├─⑤ 它是一个新的常驻目的地吗？（不带任务在手也会回来、有自己的状态）
│    ├─ 是 ──→ 走 §7 导航准入
│    │          通过且未达上限 → nav-bar
│    │          未通过 或 已达上限 → 停 → §9
│    └─ 否 ↓
│
├─⑥ 它是当前屏的屏级动作吗？（作用于整屏，且不是「新建一笔」）
│    ├─ 是 ──→ screen-header（至多 2 个，超出走 §3 溢出规则）
│    └─ 否 ↓
│
├─⑦ 它是非常态呈现吗？（空 / 加载 / 局部失败 / 整屏失败）
│    ├─ 是 ──→ 走 §8
│    └─ 否 ↓
│
└─ 都不是 ──→ **停。走 §9。**
```

②和③的判别标准（防止两个落点）：**看它显示的是算出来的值还是原始条目**。「本月支出合计」是聚合 → ②。「本月的每一笔支出」是条目流 → ③。一个屏上两者都有是正常的，它们是两个区域。

### 什么都没匹配上怎么办

**停下。不要挑一个最像的区域塞进去。** 走 §9 提交一次区域申请。

兜底是「停」，不是任何一个真实区域。一旦某个真实区域被当成兜底，它半年后就是个杂物抽屉——而杂物抽屉正是这份文档要防的东西。

「停」是一片叶子：它离开本文档去走变更流程，**不会绕回树里**。

### 反向自查

你要是正准备做下面任何一件事，说明你已经走偏了：

1. 加第 4 个底部 tab —— 先看 §7 的上限和「达到上限怎么办」
2. 在 `screen-header` 里放金额、结余、任何数据摘要 —— 那是 `screen-body.analysis-slot` 的活
3. 给 `fab` 加长按菜单、或者让它展开成多个动作 —— `fab` 只承载一个动作，见 §10
4. 在 `screen-body` 里放一个常驻的提交按钮 —— 提交动作的宿主是 `screen-footer` 或 `fab`
5. 因为「实在不知道放哪」而把东西放进设置屏 —— 设置屏的内容是封闭枚举，不是兜底
6. 叠第二层 sheet —— 见 §4 覆盖层规则
7. 在列表行里放操作按钮 —— 见 §6 动作单一宿主

## §2 区域名白名单

命名约定：**kebab-case**；嵌套用 `.` 连接；**最大深度 3**。
同一个名字在本文档、类型定义、代码里必须**逐字符一致**。

### 常驻外壳（跨屏存在，不属于任何一屏）

| 区域名 | 职责 | 允许放 | **禁止放** | 尺寸约束 |
|---|---|---|---|---|
| `app-shell` | 根容器，挂载外壳三件套与当前屏 | 只放 `nav-bar` / `fab` / `overlay-root` / 当前屏 | 禁止放任何业务内容；禁止放任何文案；禁止放条件渲染的业务逻辑 | 全屏 |
| `nav-bar` | 底部导航条，承载常驻目的地 | tab 项（图标 + 文字）、状态点 | **禁止放数字角标**（会被读成待办，见 §7）；禁止放「新建一笔」；禁止放第 5 个 tab；禁止放非目的地的动作 | 上限 4 个 tab，当前用 3 |
| `fab` | 全局唯一的主动作按钮 | 只放「新建一笔」 | 禁止放第二个动作；禁止长按展开成动作菜单；禁止放只对某一个 tab 有意义的局部动作；禁止在 `stack-detail` / `sheet-form` 上出现 | 见 `design.md` |
| `overlay-root` | 覆盖层挂载点，与屏栈正交 | sheet / dialog / toast | 禁止放常驻内容；禁止放导航目的地；禁止承载「必须被看到才算完成」的主流程 | 见 §4 叠放规则 |

### 屏内区域（每一屏一棵树）

| 区域名 | 职责 | 允许放 | **禁止放** | 尺寸约束 |
|---|---|---|---|---|
| `screen-header` | 屏顶栏：这屏叫什么 + 屏级动作入口 | 屏标题、返回 / 关闭、至多 2 个屏级动作入口（设置入口在这里） | 禁止放「新建一笔」；**禁止放金额、结余、任何数据摘要**；禁止放筛选控件本体（只放入口）；禁止随内容变化而改标题 | 动作至多 2 个 |
| `screen-scope` | 当前屏的取数范围选择 | 周期切换（月 / 年）、筛选与排序的**入口及其当前值** | 禁止放统计结果（那是 `analysis-slot`）；禁止放与本屏无关的全局设置；禁止放多于一行 | 单行 |
| `screen-body` | 屏主内容，**全屏唯一的滚动区** | `screen-body.list`、`screen-body.analysis-slot`、表单字段、`empty-state` | 禁止放常驻动作按钮（归 `screen-footer` 或 `fab`）；禁止放 toast；禁止出现第二个独立滚动容器（嵌套滚动会让手势归属不可预测） | 弹性；底部内边距必须避让 `fab` + `nav-bar`（见 §3 ⚠） |
| `screen-body.list` | 同构条目流 | 结构一致的条目行（交易行、预算行、分类行） | **禁止放异构卡片**（破坏可扫描性）；禁止放分析图表；**禁止在行内放操作按钮**（见 §6 动作单一宿主）；禁止在流中间插入运营位 | — |
| `screen-body.analysis-slot` | 分析块槽，有限枚举 | §5 枚举内的分析块 | 禁止放枚举外的块；禁止放交易明细列表；禁止放动作按钮；禁止放广告 / 推荐位 | 枚举上限 6，当前用 4 |
| `screen-footer` | 提交 / 确认动作区 | 1 个主动作 + 至多 1 个次动作 | 禁止放表单字段；禁止放说明文案；禁止放导航；禁止放第三个动作 | 至多 2 个动作 |
| `empty-state` | 区域级空态 | 一句说明 + 至多 1 个动作 | 禁止放教程 / 引导流程；禁止放插画之外的装饰；禁止占满整屏（它是**区域内**的空态，不是屏空态） | ≤1 个动作 |

### 这张表的代码形态

白名单在代码里有两个形态，都在资产层 `src/ui/contract/`：

  | 'fab'
  | 'overlay-root'

  | 'screen-body.list'

## §3 外壳骨架

```
app-shell                          全屏
├── <当前屏>                        弹性，占据除 nav-bar 外的全部高度
│   ├── screen-header              固定高度
│   ├── screen-scope               单行，可选
│   ├── screen-body                弹性，唯一滚动区
│   │   ├── screen-body.analysis-slot
│   │   ├── screen-body.list
│   │   └── empty-state
│   └── screen-footer              固定高度，可选
├── fab                            浮于当前屏之上，锚定在 nav-bar 上方
├── nav-bar                        固定高度，贴底（含安全区）
└── overlay-root                   正交层，覆盖以上全部
```

### 从图上看不出来、但会改变扩展规则的结构事实

1. **`fab` 和 `nav-bar` 属于 `app-shell` 层，不属于任何一屏。** 所以切 tab 时它们不重建，**屏级代码不得直接修改它们**——想让 `fab` 在某屏消失，是页型的属性（见 §4 矩阵），不是那屏自己去藏。
2. ⚠ **`screen-body` 的底部内边距必须避让 `fab` + `nav-bar`。** 这两者浮在屏之上，不占布局流；不留避让，列表最后一条永远被压住，而且这个 bug 只有滚到底才看得见。这是本规范与 `design.md` **唯一**的耦合点：那三个高度值在 token 文件里，改它们必须回来看这条。
3. **`overlay-root` 与屏栈正交。** sheet 打开时当前屏**不卸载**；系统返回手势的优先级是：先关最上层覆盖层 → 再退屏栈 → 再退出应用。
4. **`stack-detail` 保留 `nav-bar`、隐藏 `fab`。** 保留导航条是为了不丢失位置感（你还在「明细」这个 tab 里）；隐藏悬浮按钮是因为在一笔交易的详情屏上「新建一笔」语义混乱——用户会以为是「在这里加一笔」。

### 降级

移动端的降级触发条件**不是视口断点**，是**内容区的最小可用尺寸**。理由：断点不知道键盘是否弹起、系统字号是否被放大，会在不需要的时候降级。

| 触发 | 降级动作 | 降级后必须留下什么 |
|---|---|---|
| 键盘弹起（`sheet-form`） | `screen-footer` 吸附到键盘上方；`screen-body` 压缩并保证当前聚焦字段可见；`nav-bar` 与 `fab` 隐藏 | 主动作按钮必须仍然可点——把提交按钮顶到键盘后面是本项目最容易犯的错 |
| 系统字号放大 / 窄屏，`screen-header` 放不下 2 个动作 | 第 2 个动作收进溢出菜单 | 返回 / 关闭**绝不可**进溢出菜单 |
| `nav-bar` 空间不足 | tab 文字可隐藏 | **信号条规则：图标 + 状态点必须保留。绝不允许降级到零。** 降到零就等于把「预算超支」这个信号埋了 |
| 内容过长 | `screen-body` 滚动 | `screen-header` / `screen-scope` / `nav-bar` / `screen-footer` **不随滚动隐藏**。v1 不做隐藏式顶栏，理由：位置稳定比多露两行内容值钱 |

**手动 vs 自动，谁赢：用户赢，两个方向都是。** 用户手动折叠的分析块，空间恢复后**保持折叠**；用户手动展开的，空间不足时才自动折叠。自动降级是兜底，不是意见。

### 手势规则（属于本规范）

| 手势 | 归属 | 规则 |
|---|---|---|
| 系统返回（侧滑 / 返回键） | `app-shell` | 优先级见结构事实 3。**不得被业务屏拦截**，除非 `sheet-form` 有未保存改动（此时弹 dialog 确认） |
| 条目左滑 | `screen-body.list` | 至多暴露 2 个动作，其中破坏性动作必须走「破坏性确认」短路 |
| 长按 | `screen-body.list` | 进入多选态。多选态下 `fab` 隐藏，`screen-footer` 出现批量动作区 |
| 下拉刷新 | `screen-body` | 只有 `screen-body` 可以有。**不得**在嵌套容器上再挂一个 |

### 上下文形态

本产品只有**一种**上下文形态：单一账本、单一用户、本地数据。没有共享空间 / 私人空间之分，没有多层级容器。

若将来引入多账本，那是一次**全局作用域**的引入，不是加一个 tab——它会改变 §1 树干的第一层（「这是哪个账本的？」会成为最有判别力的问题）。走 §9，别自行开始。

## §4 页型

| 页型 | 结构 | 用于 | 判别特征 |
|---|---|---|---|
| `tab-root` | 单列，`nav-bar` 之上 | 明细、统计、预算 | 是导航目的地；不能被关闭，只能被切换 |
| `stack-detail` | 单列，栈内推入 | 交易详情、设置、分类管理 | 有返回；退栈后回到来处 |
| `sheet-form` | 单列，从底部升起 | 记一笔、编辑预算、编辑分类 | 有关闭；有提交语义；完成后自行消失 |

### 页型 × 外壳部件矩阵

| | `screen-header` | `screen-scope` | `screen-body` | `screen-footer` | `nav-bar` | `fab` |
|---|---|---|---|---|---|---|
| `tab-root` | ✅ 带屏名 | 可选 | ✅ | ❌ | ✅ | ✅ |
| `stack-detail` | ✅ 带返回 | 可选 | ✅ | 可选 | ✅ | ❌ |
| `sheet-form` | ✅ 带关闭 | ❌ | ✅ | ✅ 必有 | ❌ | ❌ |

这张矩阵的作用是**终止「这屏为什么没有那个东西」的反复讨论**。想破例，走 §9。

### `stack-detail` 与 `sheet-form`：结构相同，语义不同

两者都是「单列 + 顶栏 + 主体」，最容易被混做一个。四点区别：

| | `stack-detail` | `sheet-form` |
|---|---|---|
| 内容性质 | 一个已存在对象的完整切面 | 一组待提交的字段 |
| 会不会清空 | 不会——对象一直在 | 会——提交后内容作废 |
| 有没有动作区 | 可选。有也是「编辑 / 删除」这类**跳转或破坏**动作 | **必有**。且是「保存 / 取消」这类**提交**动作 |
| 完成后去哪 | 用户自己退栈，回到来处 | 自动关闭，回到打开它的那一屏，并给一条 toast |

混用的后果很具体：把「记一笔」做成 `stack-detail`，用户填完字段按系统返回，改动静默丢失——因为退栈没有提交语义。

### 覆盖层

`overlay-root` 是与屏栈正交的一层。

| 形式 | 覆盖范围 | 触发 | 关闭与状态恢复 | 能否叠放 |
|---|---|---|---|---|
| `sheet` | 部分屏或全屏，底层屏不卸载 | 用户主动（`fab`、筛选入口、条目点击） | 下滑 / 点遮罩 / 返回手势；底层屏状态原样保留 | **最多 1 层。**需要第二层时，要么替换当前 sheet，要么改用 `stack-detail` |
| `dialog` | 居中，遮罩全屏 | 破坏性确认、需要人工介入的失败 | 只能通过明确选择关闭；**不响应点遮罩** | 可以覆盖在 sheet 之上；dialog 之上不得再有 dialog |
| `toast` | 不阻塞，浮于一切之上 | 「瞬时反馈」短路 | 自动消失；带撤销的可点 | 同时只显示 1 条，新的替换旧的 |

**什么够格被提升进覆盖层：** 需要打断当前流程、且完成后用户要回到原地的东西。不够格的例子——需要长时间阅读的内容（→ `stack-detail`）、需要多步填写的流程（→ `sheet-form` 或多个 `stack-detail`）。

## §5 分析块槽

移动端没有侧边栏焦点槽。本产品对应的扩展槽是 **`screen-body.analysis-slot`**——这是这个应用最会长东西的地方（「月度统计」六个月后会变成十二种图），所以它必须有闸门。

### 枚举

上限 6，当前 4。

| 类型 key | 承载的一等对象 | 初始切面 | 可宿主屏 |
|---|---|---|---|
| `month-summary` | 交易（按周期聚合） | 收入 / 支出 / 结余 | 明细、统计 |
| `budget-progress` | 预算 | 已用 / 剩余 / 是否超支 | 预算、明细 |
| `category-breakdown` | 交易 × 分类 | 各分类占比 | 统计 |
| `trend-over-time` | 交易 × 周期 | 逐周期趋势 | 统计 |

**每个分析块必须声明它的宿主屏。** 不声明的话，「明细页顶部要不要放个月度结余」这种问题每次都要重新吵一遍。

### 准入规则

只有**一等对象的聚合切面**能进。典型的不够格的东西，以及它们该去哪：

| 不够格的 | 为什么 | 去哪 |
|---|---|---|
| 单笔交易的详情 | 那是对象本身，不是聚合 | `stack-detail` |
| 设置项 | 不是任何对象的切面 | 设置屏，走「全局配置」短路 |
| 「本月还没记账」提示 | 那是空态 | `empty-state`，见 §8 |
| 运营位 / 推荐 / 广告 | 不是本产品的对象 | 停 → §9 |
| 「正在同步」 | **过程状态不是对象** | §8 加载态 |

### 内部结构

所有分析块共用同一组段，**每段可选**：

`标题行` / `主值` / `图形` / `明细跳转`

三种典型组合，**后续讨论一律用这些名字**：

- **数值块** = 标题行 + 主值 —— 例：`month-summary`
- **图形块** = 标题行 + 主值 + 图形 —— 例：`category-breakdown`、`trend-over-time`
- **入口块** = 标题行 + 主值 + 明细跳转 —— 例：`budget-progress`

### 新增一个类型的门槛

三条一等对象测试，全过才行：① 有自己的身份 ② 能被单独打开 ③ 生命周期跨越单次会话。
再加两条本槽特有的：④ 必须声明宿主屏 ⑤ 枚举已满（6）时，**先做合并决策**，不得直接加第 7 个。

说明白一点：**过程状态不是对象。**「正在同步」「导入中」「本月已超支」都是某个对象的状态。不守这条，枚举会随着每一个流程步骤膨胀。

### 顺序与切换

v1 里分析块的**顺序由宿主屏定义，用户不可拖拽**。理由：可拖拽要持久化布局状态，是单人开发承受不起的复杂度，而且一旦允许拖拽，「默认顺序」这个结构决策就失效了。
用户可以折叠单个块，折叠状态持久化（见 §3「手动 vs 自动」）。

## §6 内容分流

| 内容 | 去处 | 形式 | 为什么 |
|---|---|---|---|
| 单笔交易 | `screen-body.list` | 同构行 | 同构才可扫读；这是「账本列表」的全部价值 |
| 聚合结果（合计、占比、趋势） | `screen-body.analysis-slot` | 分析块 | 有准入闸门，防止无限增生 |
| 待填写的字段 | `sheet-form` 的 `screen-body` | 表单 | 提交语义集中在 `screen-footer` |
| 提交 / 确认动作 | `screen-footer` 或 `fab` | 按钮 | 动作单一宿主，见下 |
| 破坏性动作 | 条目左滑 或 `stack-detail` 的 `screen-footer` | 手势 / 按钮，均需二次确认 | 不可逆的东西不能一步到位 |
| 瞬时反馈 | `overlay-root` | toast | 不污染内容流 |
| 全局配置、分类管理、导出、备份 | 设置屏 | `stack-detail` | 低频，不该占常驻位置 |
| 状态信号（超支、未处理） | `nav-bar` 状态点 / 条目行内联 | 点 / 内联标记 | 数字会被读成待办，见 §7 |

**兜底：** 不属于以上任何一类，就是**停 → §9**。不要发明第 9 种形式。

### 动作单一宿主

交易的操作（编辑、删除）只有两个宿主：**列表条目的左滑手势**，或**详情屏的 `screen-footer`**。

- **列表行内不放按钮。** 理由很具体：行内按钮让行变高，一屏能看的笔数从十几条掉到六七条——而「一眼扫完这个月」正是账本列表存在的意义；而且滚动时误触率高，误触的还常常是删除。
- **列表行上的信息代替按钮**：金额、分类、日期、超支标记，这些是让用户判断「要不要点进去」的依据。
- **不给「轻量」操作开例外。**「多轻算轻」是条模糊线，agent 会各自发明阈值，然后行内又长满按钮。
- 「一个组件、多个入口」和「两套实现」是两回事：编辑一笔交易只有一个 `sheet-form`，从详情屏和从左滑都打开它。**不要为左滑单独做一个简化版编辑。**

## §7 导航准入

用三条属性测每一个候选项，而不是套用别的产品的分类法：

- **它会归零吗？** 会 → 它是**队列**，需要数字角标
- **点它是"发生某事"还是"去某页"？** 发生某事 → 它是**动作**，不该做成页面
- **它永不归零吗？** 是 → 它是**全局库**，**不得带数字角标**（数字会被读成待办）

三条全不通过的（全局配置类），不属于主导航。

### 本产品的判定结果

| 候选 | 归零？ | 动作？ | 永不归零？ | 结论 |
|---|---|---|---|---|
| 明细 | 否 | 去某页 | 是 | **全局库 → nav-bar** |
| 统计 | 否 | 去某页 | 是 | **全局库 → nav-bar** |
| 预算 | 否 | 去某页 | 是 | **全局库 → nav-bar** |
| 记一笔 | — | **发生某事** | — | **动作 → `fab`，不是 tab** |
| 设置 | 否 | 去某页 | 是，但低频且是配置 | **三条测试的意图全不满足 → 不进主导航**，走「全局配置」短路 |

### 段规则

| 段 | 本产品的成员 | 徽标规则 | 放错的后果 |
|---|---|---|---|
| **全局库** | 明细、统计、预算 | **禁止数字角标。** 允许状态点（预算超支、临近超支） | 挂上数字，用户会以为有 N 件事要处理，点进去发现只是「有 N 笔账」——一次之后就再也不信这个角标了 |
| **队列** | 本产品为空 | 若将来有（如「待确认的自动导入」），**需要**数字角标，且必须走 §9 | 把队列做成全局库，用户不知道还有多少没处理 |
| **动作** | 记一笔 | 不适用 | 把「记一笔」做成 tab，底栏就出现一个点了不「去」任何地方的格子——返回手势该退到哪里语义崩坏，而且 tab 的「选中态」对一个一次性动作毫无意义 |
| **不属于导航** | 设置 | 不适用 | 把设置做成第 4 个 tab，等于把 25% 的底栏给一个每月点不到一次的目的地，还顺手把「分类管理」这种深层配置提到和日常记账同级 |

### 上限

**全局库段上限 4，当前 3。**

上限的作用不是省地方，是**逼出一次合并决策**。达到上限后再来第 5 个：

1. **停。** 不得自行加第 5 个。
2. 走 §9，在申请里必须回答：**哪两个现有 tab 可以合并**（例：统计与预算合并为「分析」，预算变成统计屏的一个分析块）。
3. **合并与否由用户决定，不由 agent 决定。** agent 的职责是把选项和代价摆出来。

## §8 非常态落位

只写落位规则，不画每一屏。

| 状态 | 去处 | 形式 | **禁止** |
|---|---|---|---|
| **空** | 该区域内的 `empty-state` | 一句说明 + 至多 1 个动作 | 禁止整屏空白；禁止做成教程或引导流程；禁止在有 `screen-scope` 的屏上不说明「是这个月没有，还是一直没有」 |
| **加载** | 区域内占位，**保持该区域原有高度** | 骨架 / 占位行 | 禁止整屏 spinner；禁止布局跳动（加载完高度变了，用户手指已经点下去了） |
| **局部失败** | 该区域内联 | 一行说明 + 重试 | 禁止用 toast 报错然后让区域留空——用户看不到 toast 就以为是没数据 |
| **整屏失败** | `screen-body` 内联错误块 | 说明 + 重试 | 禁止用 dialog 报错；禁止自动退栈 |

### 特殊情况

| 情况 | 去处 |
|---|---|
| 业务级失败（金额格式非法、预算周期冲突） | 表单字段内联，**不是** toast——toast 会消失，用户不知道该改哪一格 |
| 需要人工介入才能继续（数据损坏、存储空间不足） | `dialog` |
| 成功确认 | `toast`。**只有可撤销的操作才用 toast + 撤销**；不可撤销的操作在执行前就该走「破坏性确认」 |

### 新增页型时填这张空表

| 状态 | 去处 | 形式 | 禁止 |
|---|---|---|---|
| 空 | | | |
| 加载 | | | |
| 局部失败 | | | |
| 整屏失败 | | | |

## §9 变更流程

### 落位成功

直接实现。**不需要改本文档。** 这是常态——文档的价值在于让绝大多数需求不用来问。

### 落位失败（走到了「停」）

提交一次**区域申请**，回答这五个问题：

1. 它是**哪个一等对象**的切面？（答不上来，说明它可能根本不是界面问题）
2. **为什么现有区域装不下它？** 具体指出哪个区域的哪条「禁止放」挡住了它
3. 它**会不会清空**？（会 → 可能是队列，走 §7；不会 → 可能是库）
4. 它**需要多大空间**？（需要整屏 → 是页型问题，不是区域问题）
5. **如果不给新区域，最接近的折中是什么？** 必须给出一个能落地的次优解

**五个问题答不上来，说明需求本身没想清楚——那不是布局问题。** 这一条挡掉的东西比它批准的多，这是它的作用。

### 新增一个分析块类型

见 §5 门槛。枚举满了先合并，不加第 7 个。

### 白名单怎么保持同步

**顺序固定：白名单（§2）→ 类型定义（`src/ui/contract/regions.ts`）→ 代码。不可反向。**

反向的后果是：代码里出现一个名字，类型被改成迁就它，白名单最后被改成描述代码——文档就从约束退化成了描述。

**文档和代码打架，改代码。**

### 推翻一条旧结论

**不删。** 移到附录 B，写清楚：原来是什么 / 现在是什么 / 为什么推翻。
被推翻的判断比现行判断更容易被重新踩中，因为它们看起来很合理——它们当初对我也很合理。

## §10 反模式

| 不要 | 为什么 | 改为 |
|---|---|---|
| 因为不知道放哪，把东西塞进设置屏 | 设置屏会变成杂物抽屉，而且是个用户永远找不到东西的杂物抽屉——它没有搜索、没有分组约束 | 走 §1 走到「停」，然后走 §9。设置屏的内容是封闭枚举 |
| 给 `fab` 加长按菜单 / 展开成多个动作 | 隐藏在长按里的动作等于不存在；而且一旦允许 2 个，就没有理由不允许 5 个，`fab` 变成第二个导航 | 第二个动作走 §1 落位。真是屏级动作就进 `screen-header` |
| 在列表行里放操作按钮 | 行变高 → 一屏笔数腰斩 → 「一眼扫完这个月」失效；滚动误触还常常误触删除 | 左滑手势，或点进详情屏用 `screen-footer` |
| 在 `screen-header` 里放本月结余 | 顶栏是导航层，不是数据层。放了之后每屏都想放，而且它没有空态和加载态的位置 | `screen-body.analysis-slot` 的 `month-summary` 块 |
| 把「记一笔」做成第 4 个 tab | 它是动作不是目的地。tab 的选中态、返回栈语义对一次性动作都不成立 | `fab`，见 §7 |
| 用数字角标提示「本月有 N 笔账」 | 数字角标的既有含义是「有 N 件事等你处理」。用错一次，用户就再也不信任何角标了 | 状态点（超支 / 临近超支），见 §7 |
| 嵌套第二个滚动容器 | 手势归属不可预测，用户滑不动内层或滑不动外层，且这个 bug 在模拟器上常复现不出来 | `screen-body` 是唯一滚动区；内层用非滚动布局 |
| 叠第二层 sheet | 返回手势要退几层变得不可预测，而且底下那层的状态没人管 | 替换当前 sheet，或改用 `stack-detail` |
| 把「记一笔」做成 `stack-detail` | 退栈没有提交语义，用户按返回，填的东西静默丢失 | `sheet-form`，见 §4 |
| 隐藏式顶栏（滚动时收起 header） | 位置感丢失，用户要回顶部才知道自己在哪一屏；且和 `screen-scope` 一起收起时，「现在看的是哪个月」也没了 | v1 不做。要做走 §9 |
| 先写线框再补规范 | 规范会退化成对既有代码的描述，而不是对后续代码的约束 | 顺序是 规范 → 资产层 → 线框 |
