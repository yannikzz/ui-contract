# layout.md — 结构规范

> **给 Coding Agent 的三句话：**
> 1. 改任何界面结构之前，先走 §1 落位决策树。走通了直接实现，不用改本文档。
> 2. 走不通就**停下**。不许自己新开一个区域、一栏、一个浮层、一个页型。走 §9 变更流程。
> 3. 代码里每个区域的标记（`data-region`）必须出现在 §2 白名单里。不在表里的名字就是违规。

本文档管**结构**：区域树、栏宽、页型、拓展位枚举、内容落位、切换与降级规则。判据是「换一套品牌视觉时**不会变**的东西」。

视觉（颜色、字号、圆角、间距、阴影、状态样式）在 `design.md`。

参考实现在 `wireframe/`，它是本文档的可运行形态，不是产品代码。

---

## §0 与视觉规范的分工

**切线只有一条：换品牌视觉时会不会变。** 会变的归 `design.md`，不会变的归本文档。目标是同一个数值只住一个地方——出现在两处就是漂移源。

但**不要宣称两份文档绝对零重叠**。通常有一两个真正的耦合点（比如某个间距值决定了栅格能塞下几列，改一个就必须回头看另一个）。这种地方要在**两侧都标出来**：「⚠ 改这里需要同时复查另一份规范的 §X，这是两份文档唯一互相牵动的地方」。点名一个耦合，远比声称零重叠然后让它悄悄漂移安全。

| 项 | 归属 | 理由 |
|---|---|---|
| 导航栏宽度 220 / 图标条 56 | **layout.md** | 换品牌不会变；它是降级计算的输入 |
| 属性面板宽度 360 | **layout.md** | 同上 |
| 主区最小可用宽度 640 | **layout.md** | 降级触发阈值 |
| 区域之间的间隙、区域内边距 | **design.md** | 换品牌会变；间距是关系的表达 |
| 圆角、阴影、边框颜色 | **design.md** | 纯视觉 |
| 状态标签的**形状与颜色** | **design.md** | 视觉 |
| 状态标签**能出现在哪个区域** | **layout.md** | 落位 |
| 表格分页大小、导航段条数上限 | **layout.md** | 结构容量，不随品牌变 |
| 表格列的**优先级顺序**（谁先滚出去） | **layout.md** | 是落位决策，不是样式 |
| 表格行高、斑马纹、hover 底色 | **design.md** | 视觉 |
| 面板滑出的**动画时长与曲线** | **design.md** | 视觉 |
| 面板滑出后**表格是被挤窄还是被盖住** | **layout.md** | 这是结构事实，决定拓展规则 |
| 按钮的视觉层级样式 | **design.md** | 视觉 |
| 一个视图里主操作最多几个 | **design.md** | 视觉权重规则 |
| 某个操作**允许出现在哪个区域** | **layout.md** | 落位 |

**硬规则：**

- 本文档不出现任何颜色值、字号、圆角值、间距值。只出现结构参数（栏宽、最小宽、区域数量、条数上限）。需要引用视觉时写「见 `design.md` §X」。
- `design.md` 不出现区域树与栏宽。
- **冲突时本文档赢，且已有代码不是权威**——代码与文档冲突时改代码，不是改文档去追代码。

## §1 落位决策树

这是整份文档的入口。拿到一个新的界面需求，从这里开始，一路走到一个具体区域名。

### 1.1 短路判断（先过这六条，命中就不用往下走）

| 情况 | 直接去 | 为什么 |
|---|---|---|
| 它是**针对单行/单个对象的操作按钮** | `inspector.foot` | 单行操作只有一个宿主。表格里不存在操作列（见 §6、§10-1） |
| 它是**针对多个选中行的操作** | `main.bulkbar` | 批量操作有专属栏，且只在有选中时存在 |
| 它是**针对当前页整体或整个筛选结果的一次性动作**（新建、导出、同步、批量导入入口） | `main.pagehead` | 页级动作不依附任何一行，也不是去处（§7.2 第 2 条）。**没有这一条时，导出按钮走完整棵树会落到「停下走 §9」，而 §7.4 与 §10-2 都说它有归宿——树与文档矛盾时错的是树**（附录 C-1） |
| 它是**需要读大段内容或需要宽度的东西**（富文本正文、日志全文、大图预览、复杂对照表） | `overlay` 或升格为独立页型 | 塞进 360 宽的面板等于逼用户再点一次才到真正能读的地方 |
| 它是**过程性事件**（每一步在干什么、系统流水） | `inspector.body` 的「变更历史」tab | 过程事件进主区会把主线冲散 |
| 它是**全局配置项**（跟当前看的对象无关） | 「系统」段下的某个 P3 设置表单页 | 配置不进工作流区域 |

**引用这张表时引「情况」列的关键词，不要引行号。** 这张表会往中间插行——附录 C-1 就插过一条，而线框代码里两处按行号写的引用当场失效且没有任何提示。

### 1.2 主干

```
新的界面需求
│
├─ 问 1：它是不是「某个一等对象的一个切面」？
│        （一等对象判据三条见 §5.4；流程状态不是对象，视图不是对象）
│  │
│  ├─ 是 ─→ 问 2：它需要多宽才能读？
│  │        ├─ 360 够 ─→ 进 inspector
│  │        │            ├─ 该对象已在 §5.1 枚举里 ─→ 进它现有的某个 tab（inspector.body）
│  │        │            │                            装不进任何 tab ─→ 停下，走 §9
│  │        │            └─ 该对象不在枚举里 ─→ 停下，提「新增面板类型」申请（§9.3）
│  │        └─ 不够 ─→ overlay（临时查看）或独立页型（长期入口）→ 走问 4
│  │
│  └─ 不是 ─→ 问 3：它是「一批对象的集合视图」，还是「一次有始有终的流程」，
│              还是「一组会保存的配置」，还是「一屏概览」？
│              ├─ 集合视图 ─→ P1 列表页。再问它是哪一部分：
│              │              ├─ 缩小结果范围的控件 ─→ main.filters
│              │              ├─ 表格里的一列 ─→ main.table（列型见 §6.2，没有操作列）
│              │              ├─ 翻页/总数/每页条数 ─→ main.pager
│              │              └─ 都不是 ─→ 停下，走 §9
│              ├─ 有始有终的流程 ─→ P2 向导页（main.steps / main.step-body / main.step-foot）
│              ├─ 会保存的配置 ─→ P3 设置表单页（main.form）
│              ├─ 一屏概览 ─→ P4 概览页（main.grid，卡片占格规则见 §4.4）
│              └─ 四类都不是 ─→ 停下，走 §9。**不要挑一个最接近的页型**
│
└─ 问 4（承接问 2 的「不够」与问 3 定下的页型，**不是问 1 的平行分支**——
         任何一个页型都还要回答「用户怎么到达它」）：
   它是一个新的「去处」（用户要能从导航到达它）吗？
   ├─ 是 ─→ 走 §7 导航准入：先判它属于哪一段，再看该段有没有超上限
   └─ 不是 ─→ 它必须挂在某个已有去处下面。挂不上 ─→ 停下，走 §9
```

### 1.3 走不通怎么办

**停下。不要挑一个最像的区域塞进去。**

不要新开区域、不要新开一栏、不要新开浮层、不要新开页型、不要在白名单里加名字。写一份「区域申请」（§9.3 给了要回答的五问）交给人。

这一条比整棵树都重要：没有它，Agent 会选一个最接近的区域，然后规范就开始漂。

### 1.4 反向自查：如果你正准备做下面任何一件事，说明已经走偏了

1. 在表格行尾加一列图标按钮 / 「更多」菜单 → 违反 §10-1。单行操作只在 `inspector.foot`。
2. 在筛选条里放一个跟「缩小结果范围」无关的东西（导出、新建、批量删除、统计数字）→ 违反 §10-2。
3. 给向导页加一个右侧面板放帮助说明 / 已有数据参考 → 违反 §4.3，`PageWithInspector` 类型会直接拦住你。
4. 新建一条跨栏的顶栏来放「暂时不知道放哪」的东西 → 违反 §10-4。跨栏栏是拓展规则的黑洞。
5. 往属性面板里加第 4、第 5 个 tab 来装一个新功能 → 先证明它是那个对象的切面（§5.3），不是「顺手放这儿」。
6. 在导航里再加一条「回收站 / 归档 / 草稿箱」→ 违反 §7.4。这类东西是同一个页面的 tab，不是三条导航项。
7. 用视口断点写响应式 → 违反 §3.4。降级用主区实测宽度触发。

## §2 区域名白名单

**改本表必须同时改两处**：`src/ui/region.tsx` 的 `RegionId` 联合类型、以及同文件的 `REGION_META`。顺序写死在 §9.4：**改本表 → 改类型 → 写代码。**

命名法：小写字母 + 连字符；点号分层表示「父.子」；**最多两层**。三层说明你在用区域名表达组件树，那不是区域名该干的事。

### 2.1 外壳

| 区域名 | 职责 | 允许放 | 禁止放 | 尺寸 |
|---|---|---|---|---|
| `app-shell` | 最外层容器，只负责把导航和工作区并排 | 只放 `nav` 与 `work` | 任何直接的内容、任何浮动元素 | 弹性，撑满视口 |
| `nav` | 全局去处导航 | `nav.brand` / `nav.groups` / `nav.settings` 三个子区 | 当前页面的内容、筛选条件、任何跟「当前看的对象」有关的东西 | 固定 220；收起态 56 |
| `nav.brand` | 产品标识 + 导航收起开关 | 产品名、收起/展开开关 | 用户头像、全局搜索、通知铃铛（这三个都还没有落位，要放先走 §9） | 固定高 |
| `nav.groups` | 工作流去处，分组排列（工作台 / 内容管理） | 分组小标题、导航项、导航项上的数量角标 | 配置类去处（去 `nav.settings`）、动作型项（点了「发生一件事」的东西，见 §7.2） | 弹性，可纵向滚动 |
| `nav.settings` | 配置类去处，贴底独立成段（系统） | 系统组的导航项 | 数量角标（配置不是队列，带角标会被误读成待办）、工作流去处 | 贴底，高度随内容 |
| `work` | 工作区，页型在此渲染 | 只放 `stage` | 跨栏的标题栏、跨栏的工具条、面包屑（页标题在 `main.pagehead`，见 §3.3-事实2） | 弹性 |
| `stage` | 把主区与属性面板并排，并承载 `overlay` | 只放 `main`、`inspector`、`overlay` | 任何直接内容 | 弹性 |
| `overlay` | 覆盖层，盖住 `stage` 全部 | 需要宽度的临时查看、需要打断的确认、跨对象对照 | 常驻功能（覆盖层里的东西必须能被关掉且关掉后不丢失主流程）、第二层覆盖层（禁止叠层，见 §4.5） | 盖满 `stage` |

### 2.2 主区（`main` 及其子区）

| 区域名 | 职责 | 允许放 | 禁止放 | 尺寸 |
|---|---|---|---|---|
| `main` | 当前页型的主体 | 下列子区，按页型取用（见 §4.2 矩阵） | 跟当前页无关的全局功能 | 弹性；**最小可用宽 640**，低于则触发降级（§3.4） |
| `main.pagehead` | 页标题 + 该页唯一的页级主操作 | 页标题、页级主操作（「新建」「批量导入」这类）、该页的说明性一句话 | 筛选控件（去 `main.filters`）、针对具体某行的操作（去 `inspector.foot`）、统计数字堆（去 P4 概览页） | 全部页型都有 |
| `main.filters` | **只缩小结果范围** | 搜索框、筛选下拉、时间范围、已选条件的清除 | 「导出」「新建」「批量删除」等任何不改变结果集范围的动作、结果数量之外的统计指标 | 仅 P1 |
| `main.bulkbar` | 对选中的多行做操作 | 已选条数、批量操作按钮、取消选择 | 单行操作、筛选控件；**没有选中行时本区不存在**（不是隐藏，是不渲染） | 仅 P1，条件出现 |
| `main.table` | 集合的表格视图 | 选择框列、标识列、文本列、状态标签列、元信息列（列型枚举见 §6.2） | **操作按钮列 / 「更多」菜单列**（见 §10-1）、行内展开的编辑表单、行内的图表 | 仅 P1，纵向滚动 |
| `main.pager` | 表格的位置与容量 | 页码、总数、每页条数切换 | 批量操作、筛选、导出 | 仅 P1，贴底 |
| `main.steps` | 流程进度指示 | 步骤名、当前步、已完成标记 | 可点击跳到任意未完成步（进度指示器不是导航）、表单字段 | 仅 P2 |
| `main.step-body` | 当前步的内容 | 当前一步需要的输入、上传区、预检结果、结果汇总 | 其它步的内容（一次只渲染一步）、下一步/上一步按钮（去 `main.step-foot`） | 仅 P2，纵向滚动 |
| `main.step-foot` | 流程推进 | 上一步 / 下一步 / 完成 / 取消 | 与推进无关的操作（保存草稿以外的业务操作） | 仅 P2，贴底 |
| `main.form` | 会保存的配置 | 分组的表单字段、字段说明、保存/重置 | 表格、列表、跟本组配置无关的其它模块入口 | 仅 P3，纵向滚动 |
| `main.grid` | 一屏概览 | 指标卡、图表卡、短列表卡（占格规则见 §4.4） | 完整表格（表格是 P1 的事，概览页只放短列表卡 + 「查看全部」链接）、筛选条 | 仅 P4 |

### 2.3 属性面板（`inspector` 及其子区）

| 区域名 | 职责 | 允许放 | 禁止放 | 尺寸 |
|---|---|---|---|---|
| `inspector` | 聚焦槽：当前选中的**一个**一等对象的切面 | `inspector.head` / `.tabs` / `.body` / `.foot` | 集合视图、跟选中对象无关的全局信息、第二个对象（一次只有一个，见 §5.5） | 固定 360；仅 P1 |
| `inspector.head` | 让面板自给自足：说清「你在看谁」 | 对象标识、对象类型、关闭按钮 | tab、操作按钮 | 固定高 |
| `inspector.tabs` | 在同一对象的多个切面间切换 | 该类型枚举内的 tab（见 §5.2） | 跳到别的对象、跳到别的页面 | 固定高 |
| `inspector.body` | 当前切面的内容 | 字段键值、关联对象引用行、过程事件流 | 需要宽度才能读的内容（走 §1.1 第 3 条去 `overlay`）、集合表格 | 弹性，纵向滚动 |
| `inspector.foot` | **单行/单对象操作的唯一宿主** | 针对该对象的所有操作 | 批量操作、页级操作（去 `main.pagehead`） | 贴底；无可用操作时不渲染 |

## §3 外壳骨架

### 3.1 区域树

```
app-shell ────────────────────────────────────────── 弹性，撑满视口
├── nav ─────────────────────────────── 固定 220（收起态 56）
│   ├── nav.brand ────────────────── 固定高
│   ├── nav.groups ───────────────── 弹性，可滚动
│   │     ├─ 组「工作台」
│   │     └─ 组「内容管理」（上限 7 条，见 §7.3）
│   └── nav.settings ─────────────── 贴底
│         └─ 组「系统」
└── work ────────────────────────────── 弹性
    └── stage ───────────────────────── 弹性
        ├── main ──────────────────── 弹性，最小可用宽 640
        │   ├── main.pagehead ────── 全页型
        │   └── ...（按页型取用，见 §4.2）
        ├── inspector ─────────────── 固定 360，仅 P1，可关闭
        └── overlay ───────────────── 覆盖 stage 全部，正交于页型
```

### 3.2 结构参数（唯一来源）

| 参数 | 值 | 说明 |
|---|---|---|
| 导航展开宽 | 220 | 设计稿给定 |
| 导航图标条宽 | 56 | 收起后的形态，**不允许收成 0** |
| 属性面板宽 | 360 | 设计稿给定，固定不可拖拽（可拖拽=每个人的界面不一样，截图和口头沟通就失效了） |
| 主区最小可用宽 | 640 | 降级触发阈值 |
| 「内容管理」段条数上限 | 7 | 见 §7.3 |
| 属性面板类型枚举上限 | 5 | 见 §5.4 |
| 表格默认每页条数 | 20 | 用分页不用无限滚动：后台要能说「第 3 页第 5 行」，无限滚动没有这个坐标 |

代码形态在 `wireframe/src/structure.ts` 的 `STRUCT` 常量。**改那些常量等于改本节，必须同步。**

### 3.3 关键结构事实（看图看不出来，但会改变拓展规则）

1. **筛选条属于 `main`，不跨到 `inspector` 上方。** 所以属性面板打开时筛选条会一起变窄。结果是「筛选的范围 = 我看到的表格」由结构保证，不靠人记。反过来如果筛选条跨栏，`inspector` 就得是 `main` 的子级，整棵树和降级顺序都要重写。
2. **没有跨栏的顶栏。** 页标题和页级主操作在 `main.pagehead` 里，跟着主区一起变窄。这是刻意的：跨栏的栏会变成拓展规则的黑洞——所有「不知道放哪」的东西最后都往那儿堆。想要常驻全局搜索/账号入口，那是一次真的结构变更，走 §9。
3. **`inspector` 与 `main` 同级并排，宽屏时在文档流内**（挤窄表格，不遮挡）。**只有窄屏降级后才变成覆盖**（§3.4）。这条决定了「点一行看属性 → 点下一行」这个往返里表格是否可见。
4. **「系统」段贴底、与上面两组结构分离。** 导航项变多时它不会被滚走。它也**不带角标**——配置不是队列。

### 3.4 降级

**触发条件用主区实测可用宽度，不用视口断点。** 断点不知道其它栏的状态，会误收（比如导航已经收起了，空间其实够，断点还是把面板收了）。

级联顺序（每一级算完重新判定，判定函数是纯函数，见 `structure.ts` 的 `resolveShell`）：

| 级 | 触发 | 动作 | 收起后留什么 |
|---|---|---|---|
| 0 | 可用宽足够 | 导航 220 + 面板 360 挤窄并排 | — |
| 1 | 主区可用宽 < 640 | 导航 220 → 56 图标条 | **图标条 + 数量角标必须保留。** 收成 0 会把「有 12 条待审核」这类信号彻底埋掉 |
| 2 | 仍 < 640 | 属性面板由「挤窄」改为「覆盖在主区上」，宽度仍 360 | 面板仍可用，只是遮挡了表格右侧；表格恢复全宽 |
| 3 | 仍 < 640 | **触底，不再降级。** 主区保持 640 最小宽，表格横向滚动 | 列优先级见 §4.6：标识列永不滚出 |

**用户手动操作优先，且双向生效。** 手动收起导航后，窗口变宽也保持收起；手动展开后，窄屏也不自动收（此时接受主区被压缩到 640 以下）。理由：自动降级是兜底，不是主张。偏好用三态表示 `auto | open | closed`，不用布尔——布尔表达不了「跟随自动」。

## §4 页型模板

### 4.1 四种页型

| 页型 | 内容列结构 | 用于哪些页面 | 判别特征 |
|---|---|---|---|
| **P1 列表页** | 页头 → 筛选 →（批量条）→ 表格 → 分页；右侧属性面板 | 内容管理下的各集合页、系统组下的用户/角色等集合页 | 用户在「一批同类对象」里找、比、挑，然后针对某一个做事 |
| **P2 向导页** | 页头 → 步骤条 → 当前步 → 推进按钮；**无属性面板** | 批量导入 | 有始有终、一次性、有明确完成态；中途状态不需要长期保存 |
| **P3 设置表单页** | 页头 → 分组表单 →（保存在表单内） | 系统组下的各配置页 | 打开是为了改一组值然后保存；不增不减，不会清空 |
| **P4 概览页** | 页头 → 网格卡片 | 工作台 | 一屏看状态，看完点进别处；本身不承载深度操作 |

**P1 与 P3 看起来都是「表」，但语义不同，别合并**：

| | P1 列表页 | P3 设置表单页 |
|---|---|---|
| 内容性质 | **会变的数据**（新增、处理完消失） | **固定的配置项**（不增不减） |
| 会不会归零 | 会（空态是正常状态，见 §8） | 不会（空了说明出错了） |
| 有没有底部操作区 | 没有（操作在面板里） | 有（保存 / 重置） |
| 完成后发生什么 | 处理完这条继续下一条 | 保存后留在原地 |

混用的后果：把配置页做成 P1，用户会以为配置项会被「处理掉」；把集合页做成 P3，用户找不到「下一条」。

### 4.2 页型 × 外壳部件矩阵

| 部件 | P1 列表 | P2 向导 | P3 表单 | P4 概览 |
|---|---|---|---|---|
| `nav`（含三段） | ✅ | ✅ | ✅ | ✅ |
| `main.pagehead` | ✅ | ✅ | ✅ | ✅ |
| `main.filters` | ✅ | ❌ | ❌ | ❌ |
| `main.bulkbar` | 有选中时 | ❌ | ❌ | ❌ |
| `main.table` | ✅ | ❌ | ❌ | ❌ |
| `main.pager` | ✅ | ❌ | ❌ | ❌ |
| `main.steps` / `.step-body` / `.step-foot` | ❌ | ✅ | ❌ | ❌ |
| `main.form` | ❌ | ❌ | ✅ | ❌ |
| `main.grid` | ❌ | ❌ | ❌ | ✅ |
| `inspector` | ✅（可关闭） | **❌ 硬禁止** | ❌ | ❌ |
| `overlay` | 可开 | 可开 | 可开 | 可开 |

### 4.3 「向导页没有属性面板」是硬规则，不是「暂时没有」

这条由类型系统把关：`wireframe/src/wire.tsx` 里 `PageWithInspector` 只包含 `'list'`，向导页想渲染 `InspectorSlot` 会直接类型报错。

理由：向导页的结构承诺是「当前这一步就是全部上下文」。一旦允许侧边放帮助说明，它就会慢慢长出参考数据、历史记录、字段字典，最后向导变成一个带侧栏的工作台，「一次性流程」的性质丢失。

需要在导入过程中查已有内容 → 开 `overlay`（临时）或让用户另开一页（长期）。

### 4.4 P4 概览页的网格（本轮为推断，见 [`adr/layout/0010`](docs/ui-contract/adr/layout/0010-four-page-types-and-p4-grid.md)）

- `main.grid` 是 **12 列网格**。卡片只能占 **3 / 4 / 6 / 12** 格四种宽度，禁止其它占格数——否则半年后会出现 5 格、7 格卡，网格线彻底失效。
- 新指标卡放哪、占几格属本文档；卡片内的图表长什么样属 `design.md`。
- 概览页**不放筛选条**。需要筛选就说明用户其实要的是 P1 列表页。

### 4.5 `overlay`（正交于页型）

| 项 | 规则 |
|---|---|
| 盖住范围 | `stage` 全部（主区 + 属性面板），**不盖 `nav`** ——导航必须始终可用，否则用户被困在覆盖层里 |
| 自带头部 | **必须自带标题与关闭入口**。它盖住了 `main.pagehead`，不自带头部用户就不知道自己在哪 |
| 触发 | 用户明确动作。**禁止系统自动弹出**（会打断正在进行的操作） |
| 关闭 | Esc + 显式关闭按钮；关闭后主区状态（滚动位置、选中行、面板 tab）必须原样还原 |
| 叠层 | **禁止**。第二层覆盖层意味着信息架构没理清，走 §9 |
| 什么该从 overlay 升格成独立页 | 用户会反复回来的、需要能被链接分享的、需要多个 tab 的 → 升格为一个去处，走 §7 |

### 4.6 表格列优先级（属性面板挤窄时谁先让位）

从左到右固定为：`选择框 → 标识列 → 状态列 → 文本列 → 元信息列`。宽度不足时**从最右侧开始横向滚出**，标识列与选择框**永不滚出**（滚出后用户认不出这是哪一行，选中操作就变成盲操作）。

## §5 聚焦槽：属性面板

`inspector` 是本产品**唯一**的拓展槽。它的准入门槛是这份规范最主要的价值——没有门槛，半年后它会变成一栏无限滚动的杂物。

### 5.1 类型枚举

| 类型 | 承载对象 | 初始切面分组（tab） |
|---|---|---|
| `content-item` | 内容条目（表格行点开的那个对象） | 概要 / 关联 / 变更历史 |

**枚举现在只有 1 型，这是刻意的**（见 [`adr/layout/0007`](docs/ui-contract/adr/layout/0007-enum-opens-one-type-only.md)）：一等对象的枚举由本产品决定，不由参考产品或 Agent 的记忆决定。系统组下的用户/角色需要面板时，走 §5.4 门槛新增第 2 型，**不要**复用 `content-item` 硬塞。

上限 5 型。到 5 型还要加，说明该考虑「这些对象是不是应该合并」而不是继续加。

### 5.2 内部结构（所有类型共用的分段）

四段，`head` / `body` 必有，`tabs` / `foot` 可选：

| 组合名 | 组成 | 用在什么类型上 |
|---|---|---|
| **完整型** | head + tabs + body + foot | 有多个切面、又有操作的对象。`content-item` 用这个 |
| **单面型** | head + body + foot | 只有一个切面但有操作的对象 |
| **只读型** | head + body | 纯查看，一个操作都没有（`foot` 不渲染，不是渲染一个空条） |

后面所有讨论用这三个名字，不要再描述「带 tab 那种」。

### 5.3 准入规则

能进 `inspector` 的只有：**枚举内某个一等对象的一个切面**。

典型的不满足项，以及它们该去哪：

| 想进面板的东西 | 为什么不行 | 该去哪 |
|---|---|---|
| 「本页筛选出的 128 条的统计」 | 是集合的属性，不是单个对象的切面 | P4 概览页的 `main.grid`，或 `main.filters` 旁的结果数量 |
| 「操作帮助 / 字段说明」 | 不是对象的切面 | 字段旁的说明，或独立文档 |
| 「最近访问过的条目」 | 是用户的历史，不是当前对象的切面 | 走 §7 判断是否是一个新去处 |
| 「待审核队列」 | 队列是集合 | P1 列表页 + `nav.groups` 上的数量角标 |
| 「导入进度」 | 是流程状态，**流程状态不是对象** | P2 向导页的 `main.step-body` |

### 5.4 新增一型的门槛

必须同时满足一等对象三条判据：

1. **有独立身份**——能被引用、能被链接（有自己的 id/URL）。
2. **能被单独打开**——不依附于另一个对象才有意义。
3. **有跨会话的生命周期**——关掉浏览器再回来它还在，不是这次会话的临时产物。

并明确写死：**流程状态不是对象**（「待审核」「已过期」「导入中」是对象的状态，不是新对象）；**视图不是对象**（「报表页」是页面）。少了这两句，枚举会随流程节点数量膨胀。

### 5.5 切换规则

| 项 | 规则 | 理由 |
|---|---|---|
| 进入 P1 时的初始状态 | **关闭**（没有选中行，主区全宽）。第一次点行才出现 | 建线框时发现的冲突：如果初始就打开并显示一句「选一行查看属性」，等于常驻占掉 360 宽只为放一句话；而且和下面「切换去处时重置为关闭」自相矛盾。见附录 B-5 |
| 谁决定显示哪个对象 | **用户最后一次明确点击的那一行** | 不会在用户阅读时被抢走 |
| 什么时候重置 | **切换导航去处时重置为关闭**。同一页内换筛选条件，若选中行已不在结果里也关闭 | 否则会出现「已经切到别处了，面板还停在上一个对象上」 |
| 系统能不能抢 | **不能。** 后台有事发生时不许自动切换面板内容 | 多个并行事件会让面板自己乱跳 |
| **补偿规则（必须有）** | 因为不抢面板，「有事发生」必须在别处出信号：`nav.groups` 对应项上的数量角标 + 表格行上的状态标签变化 | 缺了补偿，「不抢」就变成「静默丢事」 |
| 切换成本 | 从表格任意行到它的面板必须**一步到达**（点行即换，不需要先关再开） | — |
| 同时几个 | **一次一个对象。** 禁止并排两个面板、禁止面板内嵌第二个对象的面板 | 360 宽装不下两个，且「当前对象」会变得有歧义 |
| 自给自足 | 每个类型必须自带上下文（`inspector.head` 说清「你在看谁」），不能依赖用户记得自己点了哪一行 | 挤窄/覆盖两种形态下用户视线位置不同 |

### 5.6 键盘与焦点

| 键 | 语义（逐层） |
|---|---|
| Esc | 有 `overlay` → 关 overlay；否则有面板 → 关面板；否则清空表格选中。**一次只关一层** |
| 面板打开后焦点落在 | `inspector.head`（可读出「你在看谁」），不落在 `inspector.foot` 的操作按钮上——否则误敲空格会执行操作 |
| 预留组合键 | 全局搜索的组合键预留，**但全局搜索目前没有落位区域**（`nav.brand` 明确禁止），要做先走 §9 |

## §6 主内容区的内容分流

### 6.1 内容 → 落位

| 内容 | 落位 | 形态 | 为什么 |
|---|---|---|---|
| 缩小结果范围的条件 | `main.filters` | 搜索框 / 下拉 / 时间范围 | 与结果集是一对一关系，必须紧贴表格上方 |
| 一批对象的可比较字段 | `main.table` | 表格列 | 可比较 = 需要对齐 = 表格 |
| 单个对象的详细字段 | `inspector.body` | 键值列表 | 不可比较的字段进表格只会撑爆列宽 |
| 单个对象的操作 | `inspector.foot` | 按钮 | 见 §6.3 |
| 多个选中对象的操作 | `main.bulkbar` | 按钮条 | 只在有选中时存在，不占常驻空间 |
| 页级操作（新建、批量导入入口） | `main.pagehead` | 按钮 | 与具体某行无关 |
| 过程性事件（谁在什么时候改了什么） | `inspector.body` 变更历史 tab | 时间线 | 一天几十条，进主区会把主线冲散 |
| 长内容 / 大文件预览 / 全文日志 | `overlay` | 覆盖层 | 需要宽度 |
| 一次性流程 | P2 的 `main.step-body` | 分步 | — |
| 会保存的配置 | P3 的 `main.form` | 分组表单 | — |
| 一屏概览指标 | P4 的 `main.grid` | 卡片 | — |

**兜底：不属于以上任何一类的，停下走 §9。不许自己发明第 N+1 种形态。**

### 6.2 表格列型枚举（故意没有「操作列」）

| 列型 | 放什么 |
|---|---|
| `select` | 选择框，用于批量 |
| `id` | 标识列，点击即在面板打开该对象。**永不滚出**（§4.6） |
| `text` | 可比较的文本字段 |
| `badge` | 状态标签（形状颜色见 `design.md`） |
| `meta` | 时间、人名等元信息，优先级最低 |

代码形态是 `wire.tsx` 的 `TableColumnKind`。**里面没有 `actions` 是刻意的，不是漏了。** 想加操作列会直接类型报错。

### 6.3 「单行操作只在面板」的完整规则

- **表格里没有任何按钮。** 这不是约定，是结构事实——列型枚举里根本没有操作列，写不出来。
- 表格提供的唯一入口是**点行 → 在 `inspector` 打开该对象**，然后在 `inspector.foot` 操作。
- **代价必须补偿**：多一次点击，且「这一行能做什么」在表格上看不见。补偿方式是 `badge` 列如实反映状态（比如「待审核」），让用户不点开也知道下一步大概是什么。
- **不给「轻量操作」破例。** 「多少算轻量」是模糊线，一破例，Agent 会自己发明标准，最后表格里又满是图标。
- 「一份组件多个入口」和「两套实现」的区别：删除操作的**实现**只有一份（一个 `deleteItem`），`inspector.foot` 和 `main.bulkbar` 都调它——这是允许的。不允许的是**在表格里再摆一个删除按钮**，那是第二个宿主。

## §7 导航准入

### 7.1 三段

| 段 | 区域 | 判别特征 | 角标规则 |
|---|---|---|---|
| 工作台 | `nav.groups` | 一屏概览，看完就走 | 不带角标（概览本身不是队列） |
| 内容管理 | `nav.groups` | 对象的集合（库）与队列 | **队列型带数量角标；库型禁止带角标** |
| 系统 | `nav.settings` | 配置，改完保存 | **禁止角标** |

### 7.2 一个新去处属于哪一段：用三条性质测，不要凭直觉分类

1. **它会不会清空到零？** 会 → 它是**队列**，需要数量角标（角标是「还剩多少」的信号）。
2. **点了是「发生一件事」还是「进一个页面」？** 发生一件事 → 它是**动作**，不该做成导航项（导航项的承诺是「点了会到一个地方」）。动作放 `main.pagehead`。
3. **它永不清空吗？** 是 → 它是**库**，**不该带未读数**——带了会被误读成待办，用户点进去发现「什么都不用做」，之后所有角标都会被忽略。

三条都不沾的（组织设置、基础配置）→ `nav.settings`。

**放错段的后果**：库带了角标 → 角标整体失去可信度，真正的待办被忽略；动作做成导航项 → 用户点了跳到一个空页面，不知道刚才发生了什么；队列放进系统段 → 待办被藏在配置里，永远没人处理。

### 7.3 「内容管理」段上限 7 条

上限的作用是**逼人做合并决策**。没有硬线时这一段会持续长，最后变成一个 15 条的长清单，用户靠位置记忆而不是靠理解来导航。到第 8 条时必须回答：这两条是不是同一个集合的两个筛选视图？如果是，合并成一条 + 页内 tab。

### 7.4 什么不进导航

| 不进导航 | 该在哪 | 理由 |
|---|---|---|
| **第二个「回收站」** | 只有一个，在系统段，页内用 tab 分对象类型 | 设计稿里出现两次是复制粘贴（附录 B-1）。每类对象各来一条回收站，导航会按对象类型数量膨胀 |
| 「草稿箱」「归档」 | 同上，是回收站页的 tab，或列表页的一个筛选视图 | 它们是同一批对象的不同状态，**状态不是新去处** |
| 「导出」「新建」「同步」 | `main.pagehead` | 是动作，不是去处（§7.2 第 2 条） |
| 「我的待办」如果和某个队列内容重复 | 用已有队列 + 角标 | 两个入口指向同一批数据，用户会怀疑两边不一致 |

## §8 非常态落位

只定规则，不画每一页。

### 8.1 四态 × 区域

| 区域 | 空 | 加载 | 局部失败 | 整区失败 |
|---|---|---|---|---|
| `main.table` | 表格区内居中一句说明 + 一个动作（区分「一条都没有」和「筛选后没有」——后者的动作是「清除筛选」） | **表头保留可见，行区显示加载**（表头是结构，先出来能减少跳动）。禁止整区骨架屏 | 出错的那一行原地标出，其它行照常可用 | 表格区内一句原因 + 「重试」；筛选条保持可用 |
| `inspector.body` | **不适用**：没有选中行时整个 `inspector` 不渲染，主区全宽（见 §5.5）。**不要常驻一个写着「选一行查看属性」的空面板**——它白占 360 宽，而这句话用户看一次就够了 | 面板内加载，`inspector.head` 的对象标识先出（用户已经知道点的是谁） | 出错的那个 tab 内提示，其它 tab 可切 | 面板内一句原因 + 「重试」；**禁止自动关闭面板** |
| `main.grid` | 每张卡各自空态（一张卡没数据不影响别的卡） | 每张卡各自加载 | 单卡内提示 | 单卡内提示 + 重试 |
| `main.form` | 不存在空态（配置项固定，空了说明出错，按整区失败处理） | 表单区加载 | 字段级错误在字段下方 | 表单区一句原因 + 「重试」，**禁止把已填内容清掉** |
| `main.step-body` | 不存在空态 | 当前步内加载 | 预检失败在当前步内列出，`main.step-foot` 的「下一步」禁用 | 当前步内提示，允许「上一步」返回 |
| `nav` | 不存在空态 | 导航项骨架**不做**，直接显示项、角标数字后到 | 单个角标取不到就不显示角标，不显示 0，不显示错误 | 导航本身失败按整页失败处理 |

### 8.2 通用禁止

| 禁止 | 原因 | 替代 |
|---|---|---|
| 整页白屏加载 | 用户不知道是在加载还是坏了，且外壳每次重画会闪 | 外壳（`nav` + `main.pagehead`）立即渲染，只在数据区内加载 |
| 用瞬时提示（toast）报告需要用户处理的失败 | 会被错过，且错过后无法找回 | 失败信息留在它发生的区域里，直到被解决 |
| 加载时区域高度塌陷再弹回 | 布局跳动，用户会点错 | 加载态占位高度与常态一致 |
| 用「无数据」一句话打发所有空态 | 空态是最好的引导位置 | 每个空态都要说清「为什么空 + 下一步做什么」 |

### 8.3 特殊情况 → 落位

| 情况 | 落位 |
|---|---|
| 业务层面的失败（导入 3 条成功 2 条失败） | P2 最后一步的 `main.step-body`，逐条列出可下载/可重试，**不用 toast** |
| 需要人介入的异常（有条目被锁定） | 该行的 `badge` 列 + `inspector.body` 里说明原因 |
| 成功确认 | 就地反映结果（列表刷新、状态标签变化）。**破坏性操作的确认走 `overlay`**，不用 toast 代替确认 |
| 权限不足 | 不渲染该导航项（不是渲染成禁用——禁用项会泄露组织结构） |

### 8.4 新增页型时填这张空模板

| 区域 | 空 | 加载 | 局部失败 | 整区失败 |
|---|---|---|---|---|
| （新区域） | | | | |

## §9 变更流程

### 9.1 落位成功

直接实现，不用改本文档。区域名用白名单里的原名。

### 9.2 落位失败

**停下。** 不许挑一个最像的区域，不许新开区域/栏/浮层/页型。

### 9.3 提「区域申请」，回答五问

1. 它是**哪个一等对象的哪个切面**？（答不出说明它可能不该进 `inspector`）
2. **现有区域为什么放不下**？具体到是哪个区域、哪条禁止项拦住了它。
3. 它**会不会清空到零**？（决定它是队列还是库，决定角标规则）
4. 它**需要多宽**才能读？（决定进 360 面板、进主区、还是进 `overlay`）
5. **不给新区域的情况下，最接近的妥协方案是什么**？

**五问答不出来，说明需求本身没想清楚，不是布局问题。** 先把需求想清楚再回来。

### 9.4 同步顺序（写死，顺序不能反）

**改 `layout.md` §2 白名单 → 改 `src/ui/region.tsx` 的 `RegionId` 与 `REGION_META` → 写代码。**

反过来（先写代码再补文档）会让规范退化成「给已有代码补的说明书」，不再是约束。

文档与代码冲突时**改代码**。

### 9.5 推翻旧结论

**不要删。** 移到附录 B 并写清理由。被推翻的判断比现行判断更容易重复踩坑——下一个 Agent 很可能把已经否掉的方案再实现一遍，因为它看起来很合理（当初你也觉得合理）。

## §10 反模式清单

| # | 禁止 | 原因 | 替代 |
|---|---|---|---|
| 1 | 表格行尾的操作列 / 「更多」菜单 | 无底洞。今天两个图标，半年后六个图标加一个「更多」，还在和数据列抢宽度；同时操作出现在两个宿主，两边逻辑会漂 | 点行 → `inspector.foot` 操作。列型枚举里没有 `actions`，写不出来 |
| 2 | 往 `main.filters` 里放导出 / 新建 / 批量删除 / 统计数字 | 筛选条的承诺是「这里的东西只改变我看到哪些」。混入动作后用户不敢点，怕误触发 | 页级动作 → `main.pagehead`；批量 → `main.bulkbar`；统计 → P4 概览页 |
| 3 | 给向导页加侧边说明面板 | 它会一路长成「带侧栏的工作台」，一次性流程的性质就丢了 | `overlay` 临时查看。`PageWithInspector` 类型直接拦住 |
| 4 | 新建一条跨栏的顶栏 | 跨栏栏是拓展规则的黑洞：所有「不知道放哪」的东西都会堆进去，半年后它是一条 12 个图标的杂物栏 | 页级东西进 `main.pagehead`；真需要全局条走 §9 |
| 5 | 属性面板做成可堆叠卡片流（新功能=加一张卡） | 没有准入门槛，这栏会变成无限滚动的杂物栏 | 单槽 + 类型枚举 + §5.4 门槛 |
| 6 | 系统事件自动切换属性面板内容 | 用户正在读的东西被抢走；多个并行事件时面板自己乱跳 | 面板跟用户点击；用 `nav` 角标和 `badge` 列出信号（§5.5 补偿规则） |
| 7 | 属性面板宽度可拖拽 | 每个人的界面不一样，截图沟通和「第三列在哪」的口头交流全部失效 | 固定 360；不够宽的内容走 `overlay` |
| 8 | 用视口断点写降级 | 断点不知道其它栏的状态，会在空间其实够的时候误收 | 主区实测宽度触发（§3.4） |
| 9 | 导航收起时收成 0 宽 | 「有 12 条待审核」这类信号被彻底埋掉，用户不知道自己错过了什么 | 收成 56 图标条，角标保留 |
| 10 | 给库型导航项加未读数角标 | 库永不清空，角标永远不为 0，用户学会忽略所有角标，真待办随之被忽略 | 只有队列型带角标 |
| 11 | 为「草稿箱 / 归档 / 回收站」各加一条导航项 | 它们是同一批对象的不同状态，**状态不是去处**；照这个逻辑导航会按状态数膨胀 | 一条导航项 + 页内 tab / 筛选视图 |
| 12 | 用 toast 报告需要用户处理的失败 | toast 会消失，错过就找不回，而这类信息必须留到被解决 | 留在发生的区域里（§8.2） |
| 13 | 整页骨架屏 | 外壳每次重画会闪；且用户分不清「在加载」和「坏了」 | 外壳立即渲染，只在数据区内加载 |
| 14 | 概览页加筛选条 | 需要筛选说明用户要的是集合视图，不是概览；加了之后概览页会慢慢变成一个更差的列表页 | 用 P1 列表页 |
| 15 | 叠第二层 `overlay` | 需要叠层说明信息架构没理清；用户不知道 Esc 会关掉哪一层 | 走 §9 重新落位 |
| 16 | 在 `overlay` 里放常驻功能 | 覆盖层随时会被关掉，常驻功能会因此不可达 | 升格成一个去处（§7） |

这一章会随迭代持续变长，这是健康的。来源：每一条「不要这样」的结论 + 每一次被推翻的方案 + 每一次差点写错的地方。

### C.3 这次追踪的结论

九条输入里 **两条把树走穿了**，而这两个洞在追踪之前都不可见：`layout.md` 通篇读起来完全正常，§1 有决策树、有显式的「停」、有反向自查清单——**「有一棵树」和「这棵树是全的」是两件事，只有拿输入去撞才能分开**。
