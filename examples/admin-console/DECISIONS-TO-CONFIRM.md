# 待你拍板的决策点

> **`layout.md` 是权威。** 这份文件只记录「为什么这么定」和「什么被推翻过」，不是第二份规范来源。两边对不上时以 `layout.md` 为准；你核对完这张表，它就可以删掉。

这份表本来应该是一轮**一次一问**的访谈。你说了「赶时间，先按推荐做」，所以我把每一问的推荐答案直接落进了 `layout.md` / `design.md` / `wireframe/`，并把问题原样留在这里。

**怎么用这张表**：从上往下扫「我的选择」，觉得不对的把编号告诉我。每条都写了「推翻它会牵动哪里」，改一条我知道要跟着改哪几节，不会漏。

- 🔴 = 影响整棵区域树或拓展规则，**建议你今天就看一眼**，改晚了返工大
- 🟡 = 影响某一页型或某条规则，随时能改
- ⚪ = 我按机械规则定的，图上有答案或纯约定，基本不用管

起点判断：**你有设计稿（两张截图的口述）、没有任何已有文档和代码**。所以下面这些结论里，凡是标「推断」的，都不是从图上量出来的，是我从后台管理系统的结构约束推的——它们最需要你确认。
