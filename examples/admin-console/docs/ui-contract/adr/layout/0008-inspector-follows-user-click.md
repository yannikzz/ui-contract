## 背景

单槽意味着同一时刻只能显示一个对象（[0006](0006-inspector-single-slot-enum.md)）。于是「谁决定显示哪一个」必须写死：用户的点击，还是系统的事件（后台完成了一个任务、来了一条待审核）？

## 决策

跟用户最后一次明确点击；切换导航去处时重置为关闭。**系统不抢面板。**

## 排除的备选

**系统事件可以抢占面板**，例如导入完成时自动把面板切到导入结果。它换来的是重要事件不会被错过。排除的理由是它把面板变成一个会自己跳的区域：多个并行事件时它会连续跳，而用户正在读某一行的属性——**阅读被打断的代价是确定的，事件被错过的代价是可以用别的手段补的**。

关键是这条决策**必须配一条补偿规则**，否则「不抢」就等于「静默丢事」。补偿写在 §5.5 与 §7.1：`nav.groups` 对应项上的数量角标 + 表格行上的状态标签变化。**没有补偿的「不抢」是缺陷，不是克制。**

## 明知接受的代价

- 「有事发生」时面板不会自动跳过去，用户必须自己注意到角标
- 因此角标与状态标签**不是可选的装饰**，它们是这条决策的一部分；删掉角标等于把这条决策改成静默丢事

## 复议条件

- 出现一类**必须立即处理、错过有实际损失**的事件（例如风控拦截），且角标被证明不足以触发及时响应——那时要考虑的是新增一个专门的通知落位，而不是让它抢面板
