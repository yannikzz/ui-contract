# 0003 筛选条属于主区内部，不跨栏到属性面板上方

## 背景

筛选条可以是主区的一个子区（`main.filters`，与表格同宽），也可以是一条横跨主区与属性面板的栏。前者让筛选条随面板开合变窄，后者让它始终占满整屏宽。

## 决策

属于主区内部（`main.filters`）；属性面板与主区同级，不在筛选条的管辖范围内。

## 排除的备选

**跨栏，横跨到属性面板上方。** 它换来的是筛选条永远拥有整屏宽度，筛选项多时不易换行。排除的理由是它切断了一条本可以由结构保证的对应关系：**筛选的范围就是我看到的表格**。跨栏之后这句话只能靠人记住和靠实现自觉——筛选条在视觉上覆盖了属性面板，而属性面板里的对象并不受筛选影响。同宽是这件事的结构证明，不是排版偏好。

跨栏的栏还有 `layout.md` §10-4 记录的那个更大的问题（见 [0005](0005-pagehead-in-main-not-a-top-bar.md)）。

## 明知接受的代价

筛选条的可用宽度从整屏变成「整屏 − 360」，筛选项多的时候会先换行。

## 复议条件

- 实际筛选条的条件数量多到在「整屏 − 360」下必然换行两行以上，且换行造成了表格首屏行数不可接受的损失
