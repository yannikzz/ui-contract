## 背景

两张设计稿的侧栏里，「回收站」各出现两次。设计稿是探索稿，不是规格：重复元素既可能是「两个不同的去处」这一结构事实，也可能是同一个组件被复制了两次的假信息。两张图都重复，更像后者。

这必须在写白名单之前判断，因为它决定 `nav` 下面有一条还是两条。

## 决策

判定为复制粘贴的假信息，**只保留一个**。

## 排除的备选

**保留两个，理解为「内容管理有自己的回收站 + 系统有个全局回收站」。** 排除的理由不是它不合理——它完全合理，而是它把一个无法证实的读图结果固化成了规范条款。规范写「必须有两个回收站」之后，后来的人不会再去问「当初为什么是两个」，他们只会照做。**假信息固化的代价远高于漏掉一个真需求的代价**：真需求会有人再提，固化的假规则没人会主动质疑。

## 明知接受的代价

如果设计原意真的是两个不同层级的回收站，这条合并掉了一个真需求。

## 复议条件

- 两个「回收站」在设计稿里的**上下文不同**（例如一个带数字角标、一个不带；或分属不同的分组标题下）——这会把「复制粘贴」的判断直接推翻
- 产品明确提出「内容管理的回收站」与「系统回收站」在权限、保留期或可恢复对象上是两套规则
