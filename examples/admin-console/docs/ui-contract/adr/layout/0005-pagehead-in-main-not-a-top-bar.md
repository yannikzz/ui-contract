## 背景

页标题 + 页级主操作需要一个宿主。两个候选：一条横跨 `main` 与 `inspector` 的顶栏，或主区顶部的 `main.pagehead`。

## 决策

放 `main.pagehead`，**不新增跨栏顶栏**。

## 排除的备选

**加一条跨栏顶栏。** 它换来的是页标题不随面板开合变窄，并且天然给全局搜索、账号菜单留了位置。排除的理由是跨栏的栏是**拓展规则的黑洞**：它是外壳里唯一一个「什么都装得下」的区域，于是所有走不通落位决策树的东西最后都会往那儿堆。半年后它是一条挂着十几个图标的杂物栏，而每一次往里加东西当时看都很合理。

不设这条栏，是让「不知道放哪」这件事没有出口——只能走 `layout.md` §9 的区域申请，回答那五问。**门槛的价值就在于没有旁路。**

## 明知接受的代价

- 属性面板打开时页标题也跟着变窄
- 以后若要一条常驻的全局搜索 / 账号条，那是一次真正的结构变更，必须走 §9，不能顺手加

## 复议条件

- 出现一个确实**不属于任何单页**、又必须常驻可见的功能（全局搜索、租户切换、全局告警条），且它通过了 §9 五问
