# 0004 属性面板挤窄表格，而不是覆盖在表格上

| | |
|---|---|
| 状态 | 接受 |

| 取代 | — |

## 背景

属性面板滑出时，表格可以被**挤窄**（面板在文档流内占 360），也可以被**盖住**（抽屉式浮在表格上）。抽屉式实现更简单，也不会影响表格列宽。

## 决策

宽屏时挤窄，面板在文档流内；仅在窄屏降级后才改为覆盖。

## 排除的备选

**始终覆盖（抽屉式）。** 排除的理由来自后台系统的核心往返：**点一行看属性 → 点下一行看属性**。抽屉式每次都遮住表格右侧，用户被迫「关面板 → 找下一行 → 开面板」，一次比对要多两次操作。挤窄之后表格始终可见可点，这个往返退化成单次点击。

代价（表格变窄）是可以被另一条规则消化的——列优先级（`layout.md` §4.6）保证主标识列永不隐藏；而抽屉式的代价（往返被打断）没有任何规则能消化。

## 明知接受的代价

- 表格列会真的变窄，末尾几列可能被挤出可视区，需要横向滚动
- 因此**必须**同时定死列优先级，否则这条决策会退化成「面板一开就认不出这是哪一行」

## 复议条件

- 表格的必要列多到即使按 §4.6 让位，主标识列 + 一列关键信息也放不进「整屏 − 360」
- 产品形态变为以窄屏为主——那时降级形态成为常态，这条决策的适用范围自动收缩
