## 背景

`inspector` 是这个产品外壳里唯一的拓展槽。它的模型有两种取法：一个**可堆叠的卡片区**（谁都能往里加一块），或一个**单槽 + 有限类型枚举**（进来的必须是枚举内某个一等对象的切面）。

前者实现简单、没人会被拦住。这正是问题所在。

## 决策

单槽 + 有限类型枚举，每一型必须是某个一等对象的切面；新增一型必须通过 §5.4 的一等对象三条判据。

## 排除的备选

**可堆叠卡片区。** 排除的理由：它对「什么能进来」没有任何判据，于是它会变成第二个杂物栏——和 [0005](0005-pagehead-in-main-not-a-top-bar.md) 拒绝的跨栏顶栏是同一个失效模式，只是换了个位置。半年后它是一栏无限滚动的卡片，每一块当初加进去时都有理由。

**这道门槛是整份规范最主要的价值。** 规范的作用不是描述现在长什么样，而是让「往里加东西」这件事有成本。

## 明知接受的代价

- 实现比可堆叠卡片区麻烦：需要一个类型联合 + 每型自己的渲染
- 新功能想进面板只有两条路：进已有类型的一个 tab，或证明自己是一等对象。**会有人被拦住，这是设计意图，不是缺陷**

## 复议条件

- 枚举逼近 §5.1 写的 5 型上限，且新增的候选确实都通过了三条判据——那说明「一等对象」这个概念在本产品里划得太宽，该重新划，而不是继续加
