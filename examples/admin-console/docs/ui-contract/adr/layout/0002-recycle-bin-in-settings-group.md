## 背景

[0001](0001-single-recycle-bin.md) 定下只保留一个回收站之后，它归哪一组仍未定：「内容管理」组（离要删的东西近）还是「系统」组（一个全局设施）。

这不是排版问题。它决定的是：**未来出现第二类可回收对象时，导航长不长第二条**。

## 决策

放「系统」组，作为一个全局回收站；页内用 tab 区分对象类型。

## 排除的备选

**放「内容管理」组，就近可达。** 排除的理由是它把导航的增长绑在了对象类型的数量上：第二类、第三类可回收对象出现时，就近原则要求各自再来一条回收站，导航会按对象类型数量膨胀。放系统组之后，新增一类可回收对象只是页内多一个 tab——**增长被限制在页面内部，不外溢到导航**。

`layout.md` §7.2 的三条性质测也指向同一结论：回收站是配置/维护类设施，三条都不沾。

## 明知接受的代价

只想删内容的人要多走一步：去「系统」组找，而不是在「内容管理」组就近点到。

## 复议条件

- 使用数据显示回收站的绝大多数进入路径来自内容管理场景，且多出的那一步造成了可测量的放弃
- 产品决定不同对象类型的回收站在权限模型上必须分开——那时它们就不再是一个去处的两个 tab
