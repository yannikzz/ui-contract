# design.md — 视觉规范

> **与 `layout.md` 的分工**
> 本文档管**视觉**：字体、颜色、间距刻度、圆角、阴影、交互态样式、动效、组件变体。判据是「换一套品牌视觉时**会变**的东西」。
> `layout.md` 管**结构**：区域树、栏宽、页型、拓展位枚举、内容落位、降级规则。判据是「换品牌视觉时**不会变**」。
> **切线只有一条：换品牌视觉时会不会变。** 同一个数值只住一个地方——出现在两处就是漂移源。
> 真正互相牵动的少数耦合点在两侧都标 ⚠，不笼统宣称两份文档零重叠。
> **本文档不出现区域树与栏宽。** 需要引用结构时写「见 `layout.md` §X」。区域名（`main.filters` 这类）一律用 `layout.md` §2 白名单里的原名，不要另起组件式名字——两套词汇会让白名单机制失效。

## §1 设计哲学与方向

### 1.0 这套值从哪来 🌡

用户在**属性**上选，不在颜色上选。三个点从**这份工作本身**取，不从「后台系统」这个品类取——
这个产品的实质是：有人一坐几小时往下过一个队列，每一行只需要回答一件事，**这条要不要我管**。

| | 密实↔舒展 | 锐利↔柔和 | 克制↔表现 | 代价（本产品里的具体后果） |
|---|---|---|---|---|
| **A 过账台**<br>像对账：一列到底，眼睛只走左边 | 密实 | 锐利 | 克制 | 需要用户学会「看左边那条」。**第一次用的人会先去读状态文字**，习惯建立之前反而更慢 |
| B 阅卷台<br>一次一件，当前那件占住视野 | 舒展 | 柔和 | 克制 | 一屏只剩 8–10 行，**「第 3 页第 5 行」这个坐标塌掉**；批量处理时滚动量翻倍 |
| C 值班台（偏门）<br>整行按状态染底 | 密实 | 柔和 | 表现 | 20 行里有 6 行带色底，**用户读不出主次，且会以为那 6 行「出事了」**——§2.3 硬规则 2 明令禁止的形态，选它等于推翻那条规则 |

**选定 A —— 过账台。**

⚠ **这个选择是 agent 替示例做的**，因为示例没有真实用户。真实项目里这三个点要一次一问地
摆给用户，由他选——ADR-0001 原则 3。C 是刻意放进去的偏门选项，它的代价大到会推翻一条现有硬规则，
所以它是真选项不是陪衬；被否掉是机制在工作。

**接受的代价是具体的**：新用户在建立「看左缘」这个习惯之前，比读文字更慢。

坐标怎么落到值（**每个值都必须能回指到一条坐标**，回指不到的就是默认值）：

| 轴 | 坐标 | 它定死了什么 |
|---|---|---|
| 密实 | 密实端 | 间距步进比、行高、控件高（§4）。眼睛要**扫**不要**读**，所以行高压到刚好不粘连 |
| 锐利 | 锐利端 | 圆角刻度小、**无阴影**、描边只有 1px（§6b、§7） |
| 克制 | 克制端 | 颜色数量少、饱和度低、强调色覆盖面积小（§2.3） |

### 1.1 Signature：状态类由**行左缘的实心色块**承载 🌡

一套值可以完全连贯，同时是这个品类里每个产品都有的那一套。连贯是三条轴买来的；
**可辨识是另一件事，上面任何一条都不产出它。**

这个产品的签名只有一个，而且是一个会**重复出现**的处理——系统的签名是处理，不是高光时刻：

> **每一行的左缘有一道 3px 实心色块，颜色是这一行的状态语义类**（§2.3b）。
> `neutral` 类没有语义色，因此没有色块——**左缘一扫，剩下的就是要你管的**。

它能指回坐标，这是它不是装饰的判据：

| 指回哪条坐标 | 怎么指的 |
|---|---|
| 密实 | 密实的意思是眼睛扫不读。**色块不需要读**，chip 需要 |
| 锐利 | 实心块与直角，不是渐变、不是发光 |
| 克制 | 3px 的边缘，**不是整行染底**——整行染底是 C 方案，已被否掉 |

⚠ **它是填充，不是边框。** §6b 规定边框只有 1px 一种宽度；这道色块**不算边框**，
它是一个填充块。这个区分必须写在这里，否则下一个人会把它当成第四档边框，
然后「需要更强的分隔」时去加宽边框——那正是 §6b 硬规则 2 挡的事。

### 1.1c 色相基准 🌡

**基准：领域惯例，刻意逆反 + 邻接回避。**

三条属性轴管颜色的**数量**与**饱和度**，**没有一条管色相**——那是整套值里唯一没有约束源的
一格，也正是框架默认色进来的地方。字体族是同一个形状的槽位，见 §3.1。

这个类目的惯例色相被内部工具用滥了：用户的浏览器里同时开着几个同类后台，一排标签页里
认不出哪个是这个。所以刻意不取那个色相。

方向按功能描述，**不点名色相、不写值**（本文档不出现色值，解释也不是豁免）：
取一个在同类内部工具里不常见、且在低饱和下仍能与四个语义色各自拉开距离的方向，压暗、压低饱和度。
「克制」那条坐标要求强调色只出现在主操作与当前选中项上，太亮的方向会在这两处之外也抢注意力。

⚠ **色相是这套值里最弱的一个**，Step 3 调校时先动它。具体值住 `src/tokens.css`。

### 1.1b 自查：这套值是不是这个品类的通用答案

派生完把它反过来推一遍：**换一个同品类的产品（比如监控台、工单台），这套值会不会原样落出来？**

- **色阶与刻度：会。** 密实 + 锐利 + 克制在任何一个高密度后台上都成立，这部分是品类的答案，不是这个产品的。**这一点不修**——刻度本来就该由品类的工效学决定，不该为了独特而故意做怪。
- **Signature：不会。** 左缘色块只在「每一行都要回答『要不要我管』」的产品上说得通。
  监控台要的是趋势不是分诊，工单台的第一问是「归谁」不是「要不要我管」。

结论：**独特性集中在 signature 上，其余保持安静。** 这是刻意的分配——三处签名等于没有签名，
而周围的克制正是让那一处读得出来的原因。

### 1.2 三条原则

**一、界面的层级靠「表面 + 间距」表达，不靠线和阴影堆。**
后台系统信息密度高，每加一条边框、一层阴影，噪声就多一层。同一屏里能用背景色差和留白区分的，就不要用边框；能用一条 hairline 的，就不要用阴影。判断新组件时问：这个容器如果去掉边框，用户还认得出它的边界吗？认得出就去掉。

**二、彩色是信号，不是装饰。**
主色只出现在「可点的主操作」和「当前选中项」上；语义色只出现在状态上。一旦主色被用来「让这块好看点」，用户就无法再靠颜色判断哪里可点——这是后台系统最常见的可用性衰减方式。判断新组件时问：这里的颜色在告诉用户什么事？答不出就用灰阶。

**三、同类元素必须逐像素一致，不同类元素必须一眼可辨。**
表格里 200 行状态标签，任何一处几何不一致都会被看见（密度会放大不一致）。反过来，形状相近但语义不同的两类元素（方角标签 vs 胶囊、图标 vs 头像）必须在形状上就分开，不能靠颜色区分。判断新组件时问：它和现有哪个组件最像？像到会被误认就改形状，不够像就复用现有的。

## §2 颜色

### 2.1 表面与层级（定义空间层级）

| Token | 用途 | 关系（**值住 `src/tokens.css`**） |
|---|---|---|
| `--color-surface-page` | 页面底色（`main` 的底） | 极浅灰，**不用纯白**——纯白底上卡片浮不起来 |
| `--color-surface-raised` | 卡面、表格底、面板底 | 纯白，比 page 亮一档 |
| `--color-surface-sunken` | 导航底、表头底 | 比 page 深一档 |
| `--color-border-hairline` | 表格行分隔、卡片边界 | 极浅。密度高时它出现的次数最多，重一点整屏就脏 |
| `--color-border-strong` | 输入框边界、需要明确边界的容器 | 比 hairline 深两档，能在白底上单独成立 |
| `--color-fill-subtle` | hover 底色 | 比 page 深一点点，不足以被误认为选中 |
| `--color-fill-selected` | 选中行/选中导航项底色 | 比 subtle 深一档，见 §5 |
| `--color-fill-disabled` | 禁用底 | 与 sunken 同档，靠文字色区分 |

**`nav` 与 `main` 必须有可见的底色差**，否则两者会连成一片，用户失去「左边是去处、右边是内容」的空间感。（两者各多宽是结构参数，见 `layout.md` §3.2——本文档不写。）

### 2.2 文字层级（4 级，禁止新增第 5 级）

| 级 | Token | 用途 | 与相邻级的差别 |
|---|---|---|---|
| 1 主要 | `--color-text-primary` | 表格标识列、页标题、面板对象名、表单值 | 最深。凡是「用户要读的内容」都是这级 |
| 2 次要 | `--color-text-secondary` | 普通文本列、字段说明、面板里的字段值 | 比 1 浅一档。可读但不抢视线 |
| 3 弱 | `--color-text-tertiary` | 表头、字段名（键）、元信息列（时间/人名）、导航分组小标题 | **它标注的是「这是什么」，不是「内容本身」** |
| 4 禁用 | `--color-text-disabled` | 禁用控件文字、占位符 | 明显不可读，用户一眼知道不能点 |

**禁止新增第 5 级。** 每多一级，前四级之间的差别就要压缩，最后所有灰度看起来都一样，层级失效。
**2 和 3 最容易用反**：表格里的「更新时间」是 3 级（元信息），「标题」是 1 级（内容）。把时间写成 2 级，整张表格会显得没有主次。

### 2.3 品牌色与语义色

| Token | 含义 | 使用场景枚举（只有这几处） |
|---|---|---|
| `--color-brand` | 可点的主动作 / 当前所在位置 | ① 每屏唯一的主操作按钮底色（`main.pagehead` 或 `main.step-foot` 或 `inspector.foot` 里那一个）② 导航当前项的标识 ③ 输入框聚焦边框 ④ 链接文字 |
| `--color-brand-ink` | 用在**浅底上的品牌色文字/图标** | 只用于文字与图标。**与 `--color-brand` 不可互换**——`--color-brand` 是色块底色，直接拿来当正文颜色会因对比度不足而不可读 |
| `--color-danger` | 破坏性 / 失败 | 破坏性操作按钮的文字或边框、失败状态标签、字段级错误文字 |
| `--color-warning` | 需要注意但可继续 | 状态标签、预检警告 |
| `--color-success` | 完成 | 状态标签、向导完成态 |
| `--color-info` | 中性提示 | 状态标签（如「处理中」） |

### 2.3b 语义类 → token（**类归 `layout.md` §6.4，颜色归这里**）

线框和产品代码都只认**类**，不认颜色。这张表是这两层之间唯一的连接点。

| 语义类 | Token | 为什么是它 |
|---|---|---|
| `neutral` | **不用语义色** | 用 `--color-text-tertiary` + `--color-border-hairline`。一屏 20 行里大多数是中性态，给它上色等于全屏都在喊 |
| `progress` | `--color-info` | 系统在跑，用户不需要动手——所以要看得见但不该催人 |
| `attention` | `--color-warning` | 需要有人动手 |
| `blocked` | `--color-danger` | 被挡住了。和 `attention` 用不同的色，因为用户动作不同：一个是去做，一个是先解决 |
| `done` | `--color-success` | — |

**面积仍然受 §2.3 硬规则 2 约束**：小标签、状态点、低透明度浅底提示条。
一张 20 行的表格里有 6 行是彩色底，用户读不出主次。

⚠ **这张表和 `layout.md` §6.4 的那张是一对。** 加一个语义类要同时改两处，
顺序是 `layout.md` §6.4 → `src/ui/region.tsx` 的 `StatusKind` → 这里 → 代码。

**硬规则：**

1. **主色只出现在上面枚举的四处。** 这条是「克制」坐标的直接后果（§1.0）——强调色覆盖面积一大，主操作就不再是唯一显眼的东西。
1b. **正文与其背景的对比度不低于 4.5:1**，大字号标题不低于 3:1。调色器具与体检脚本都读这个数，两边都不自带阈值。 一旦用于装饰（分割线、图标底、卡片顶条），「可点」的信号就失效了。
2. **语义色只用于状态**，面积限制在：小标签、状态点、低透明度浅底提示条。**禁止把整行、整卡、大面积按钮染成语义色**——一张 20 行的表格里有 6 行是彩色底，用户读不出主次，而且会以为那 6 行「出事了」。
3. `--color-brand` 与 `--color-brand-ink` **不可互换**（理由见表内）。
4. **状态标签一律是「浅底 + 深字」，不是实色底 + 白字。** 实色标签在 20 行表格里会像 20 个按钮。

### 2.4 暗色模式：not used ✏

推导原则（不是简单反转）：**保留同样的空间层级关系**——`surface-sunken` 在亮色下比 page 深，在暗色下应比 page **浅**（因为暗色下「抬升」= 更亮）。文字四级的**相对差距**保持不变。语义色在暗色下需要降饱和、提亮度，不能直接复用亮色值。

## §3 字体

### 3.1 家族

| 用途 | 家族 |
|---|---|
| 正文 / UI | `--font-sans`：系统字体栈。**中英文回退都写全**——缺中文回退会让中文回落到宋体，而宋体在密实方向的行高下几乎不可读 |
| 等宽 | `--font-mono`：系统等宽栈。**只用于 ID、时间戳、代码、导入错误行号**——不用于普通数字 |

如果设计稿里混进了第三种字体，那是遗漏，一律回改。

### 3.2 字号（5 档，禁止任意像素字号）

| 档 | 角色 | 使用场景 | 限制 |
|---|---|---|---|
| `xs` | 元信息 | 状态标签、导航分组小标题、表格元信息列、角标数字 | — |
| `sm` | UI 默认 | **表格正文、面板字段、按钮、筛选控件——界面里绝大多数文字** | — |
| `base` | 强调正文 | 面板对象名、表单区块标题 | — |
| `lg` | 页标题 | `main.pagehead` 的页标题 | **每屏最多 1 处** |
| `xl` | 概览数字 | P4 概览页指标卡的数字 | 只在 P4 出现；**每张卡最多 1 处** |

**新增字号前必须先写进本表。** 禁止在业务代码里临时写像素字号——一旦破例，半年后会有 13px / 13.5px / 15px 同时存在，而没人知道哪个是对的。

### 3.3 字重（3 档）

| 档 | 用途 |
|---|---|
| regular | 绝大多数文字 |
| medium | 表格标识列、选中的导航项、tab 当前项、按钮文字 |
| semibold | 页标题、概览数字、面板对象名 |

**指定唯一字重的元素：**

- 状态标签**只能用 medium**（xs 字号靠字重撑可读性，regular 在小字号下会糊）。
- 表头**只能用 regular**（表头是 3 级文字，加粗会与标识列抢视线）。

## §4 间距

**基础网格 4px。** 允许的值：`4 / 8 / 12 / 16 / 24 / 32 / 48`。允许的半档只有 `2`（仅用于状态标签内边距与角标）。**其余一律禁止**，包括 6 / 10 / 14 / 20。

### 4.1 间距语义（每档对应一种关系，不是随手调的）

| 值 | 表达的关系 | 典型用处 |
|---|---|---|
| 2 | 紧贴 | 标签内边距、角标 |
| 4 | 同一个东西的两部分 | 图标与它的文字、数字与单位 |
| 8 | 同组不同项 | 筛选控件之间、按钮之间、字段名与字段值 |
| 12 | 小节内的行距 | 面板里字段行之间、表单字段之间 |
| 16 | 区块内边距 | 卡片内边距、面板内边距 |
| 24 | 组间分隔 | 表单的分组之间、概览卡之间 |
| 32 / 48 | 区块边距 / 空态留白 | 主区外边距、空态上下留白 |

**间距传递信息**：字段名与字段值之间用 8、两个字段之间用 12，用户就能看出哪两行是一组。如果两者都用 10，分组关系消失。

### 4.2 待收敛（设计稿实际值待填）

拿到设计稿后，把所有非网格值（`9 / 13 / 18 / 22` 这类）填进附录的收敛表，统一回改到最近的合法档。

**本节只写取值。** 各区域的结构关系（谁在谁里面、谁多宽）见 `layout.md` §3。

## §5 交互状态

状态层级：默认 → hover → pressed → 选中 → 聚焦 → 禁用。

| 元素 | hover | pressed | 选中 | 聚焦（键盘） | 禁用 |
|---|---|---|---|---|---|
| 表格行 | `--color-fill-subtle` 底 | 无（点击即选中，不需要中间反馈） | `--color-fill-selected` 底 + 标识列 medium | 聚焦环 | — |
| 导航项 | `--color-fill-subtle` 底 | 无 | `--color-fill-selected` 底 + medium + `--brand` 标识 | 聚焦环 | 不渲染（见 `layout.md` §8.3：无权限不渲染而非禁用） |
| 按钮 | 底色深一档 | 缩放 0.98 | — | 聚焦环 | `--color-fill-disabled` + `--color-text-disabled`，无 hover |
| tab | 文字转 2 级 | 无 | medium + 下方指示条 | 聚焦环 | — |
| 输入框 | `--color-border-strong` | — | — | `--brand` 边框 | `--color-fill-disabled` |
| 筛选 chip | 底色深一档 | 缩放 0.98 | 深底 + 反色文字 | 聚焦环 | — |

**关键规则：**

1. **hover 永远比选中态更淡。** 反了的话，鼠标经过时用户会以为选中项变了。
2. **选中态必须比 hover 多一个视觉维度**（底色 + 字重，或底色 + 主色标识）。只靠底色深浅区分，在表格 hover 时会分不清「我选中的是哪行」。
3. **pressed 只用轻微缩小（0.98），禁止放大类反馈。** 放大会让相邻元素看起来在被推开。大元素（整行、整卡）不做缩放——缩放整行会带动整张表格视觉抖动。

### 5.1 「选中 + hover」复合态必须显式处理

这是最常见的实现 bug：hover 到已选中的行上，hover 样式覆盖了选中底色，选中态「闪回」降级，用户以为选择丢了。

| | 正例 | 反例 |
|---|---|---|
| CSS 写法 | 选中态的选择器优先级高于 hover，或选中行的 hover 用**比选中底色更深一档**的值 | `.row:hover { background: subtle }` 无条件覆盖 `.row.selected` |
| 视觉结果 | 选中行 hover 时**更深**，选中感增强 | 选中行 hover 时变淡，看起来像被取消选中 |

表格行、导航项、tab 三处都要显式处理。

### 5.2 聚焦环只在键盘导航时出现

用 `:focus-visible` 这类「只在键盘操作时命中」的机制。鼠标点击也出现聚焦环会让界面看起来一直有个框在乱跳，用户会以为是 bug，然后所有人都学会忽略聚焦环——键盘可达性随之失效。

## §6 图标与头像

- **图标库指定一个，禁止混用。** 线性风格、1.5 描边——「锐利」那条坐标要求描边而非填充。具体库名 ✏ 未定，进附录 A，不进正文。两套图标库混用时，同一个「删除」在不同页面长得不一样，用户无法建立图标记忆。
- **图标尺寸 3 档**：`14`（表格内、标签内）/ `16`（按钮内、导航项、筛选控件）/ `20`（空态、覆盖层头部）。
- **头像/身份标识是另一套刻度**：`20`（表格元信息列内）/ `28`（面板头部）/ `32`（导航底部账号，若有）。**不要和图标刻度混用**——16 的头像会糊到认不出。
- 图标圆角：无（图标本身不带容器）。头像圆角：全圆。身份色块圆角见 §7。
- **身份标识之间的区分靠图形（首字母 / 形状），不靠底色。** 按功能给每个身份染不同颜色是最快让界面变花的做法，而且颜色一多就与语义色冲突——用户分不清「这个蓝色是身份还是状态」。

## §6b 边框（**一种宽度，三档**）

这一节原来不存在，而线框在没有它的情况下长出了 **6 档**边框——其中 3 档从没被任何 token
映射过，换肤打开后它们保持线框灰，界面变成半坏的主题。**没有规范的地方，实现会自己发明一套。**

### 宽度：只有 1px

「锐利」坐标要的是描边而不是阴影（§1.0）。**第二种宽度就是第二个信号**，而没有人定义过
2px 边框意味着什么——它只会被当成「更重要一点」，然后在半年里蔓延到所有想强调的地方。

需要更强的分隔时，往下走这三档，**不要加宽**。

### 三档，各自的使用场景是枚举的

| Token | 用在哪 | 为什么是它 |
|---|---|---|
| `--color-border-hairline` | 表格行分隔、卡片边界、分组分隔 | **这一档出现的次数最多**——一屏 20 行就是 20 条。重一点整屏就脏，所以它必须安静到几乎看不见边界、只看得见分组 |
| `--color-border-strong` | 输入框、下拉、需要在白底上单独成立的容器 | 它的职责是「这是一个可以交互的框」。用 hairline 画输入框，用户看不出哪里可以点 |
| `--color-border-contrast` | 画在**填充面上**的边框（选中行、批量条、深色控件） | hairline 在填充面上会消失。这一档存在的唯一理由是它的背景不是白的 |

**硬规则：**

1. **不许有第四档。** 想要第四档时，先问要表达的是不是「层级」——层级归表面色差（§1.2 一），不归边框。
2. **不许加宽。** 见上。
3. **`contrast` 只用在填充面上。** 用在白底上会变成一条突兀的深线，那是 `strong` 的活。
4. **阴影仍然是 not used**（命名声明表）。「用一条 hairline 能解决的就不要用阴影」——反过来也成立：**hairline 解决不了的，答案是换一档边框或换表面，不是加阴影。**

⚠ 线框的角色数必须等于这里的档数。多出来的角色 = 线框在发明规范，`check-colours.sh` 会报。

## §7 圆角

| 档 | 用途 |
|---|---|
| `2` | 状态标签、角标 |
| `4` | 输入框、按钮、表格内的小控件 |
| `8` | 卡片、面板内的区块、下拉菜单 |
| `12` | 覆盖层（`overlay`）—— **只给它，内部区块不许用** |
| `full` | 头像、筛选 chip |

**原则：容器越大，圆角越大。** 最大那档只给顶层容器；在卡片内部用 12 会让内层看起来比外层更「软」，层级关系倒挂。

**任意圆角值必须先进本表。** 禁止在业务代码里临时写表外的值。

**注意**：`2`（方角标签）与 `full`（胶囊）是**两类语义不同的元素**，见 §9.4，不可混用。

## §8 动效

**原则：快、克制、可预测。** 后台系统用户一天点几百次，任何超过 200ms 的过渡都会累积成「这系统好慢」。

| 场景 | 时长 |
|---|---|
| hover / 底色变化 | 100ms |
| 按钮 pressed | 80ms |
| 属性面板滑入/滑出 | 200ms（结构上它是挤窄还是覆盖，见 `layout.md` §3.4） |
| 覆盖层出现 | 200ms（淡入 + 极轻微上移） |
| 下拉展开 | 120ms |
| 状态标签变色 | 200ms |

可用的过渡类：`background-color` / `border-color` / `color` / `opacity` / `transform`。**禁止过渡 `width` / `height` / `top` / `left`**（触发布局重算，在 20 行表格上会掉帧）。面板挤窄用 transform 或 grid 列宽过渡，不要动 width。

**状态跃迁必须走过渡**：状态标签从「处理中」变成「已完成」时，颜色瞬间切换会让用户怀疑自己看错了。200ms 的颜色过渡是「刚刚变了」这个信息的唯一载体。

**禁止**：入场动画（列表逐行淡入）、加载时的花式动画、任何循环动画（除加载指示本身）。

## §9 组件使用规范

### 9.1 来源优先级

1. 查现成组件库里有没有 → 有就用，不要重写。
2. 有但不完全合适 → 用**变体**扩展，不要复制一份改。
3. 都没有 → 自建，并在自建时先看 §1 三条原则。

### 9.2 按钮层级（一个视图里最强那档最多 1 个）

| 变体 | 视觉重量 | 样式 | 使用场景 |
|---|---|---|---|
| `primary` | 最强 | `--brand` 实底 + 白字 | 该视图**唯一**的主动作。`layout.md` 允许它出现在 `main.pagehead` / `main.step-foot` / `inspector.foot` / `main.form`，但**同一屏最多 1 个** |
| `secondary` | 中 | 浅底 + 1 级文字 | 次要动作（取消、上一步、导出） |
| `outline` | 中低 | 白底 + `--color-border-strong` 边 | 与 secondary 同级，用在浅底之上需要边界时 |
| `ghost` | 最弱 | 无底无边 + 2 级文字 | 密集区域里的动作（表头、面板头、覆盖层关闭） |
| `danger` | 特殊 | 白底 + `--color-danger` 文字与边框 | 破坏性动作。**不做实色红底**——实色红底按钮会让人下意识以为「这里出错了」 |

同一屏出现两个 primary，用户不知道该点哪个，主操作的意义就消失了。

### 9.3 状态标签（需要绝对一致，单独写死）

**统一规格**：xs 字号 + medium 字重 + 圆角 2 + 上下内边距 2 / 左右 4 + 浅底 + 深字。

**只有颜色可变**（按 §2.3 的语义色）。**禁止**：改几何（圆角、内边距、高度）、加边框、加图标、改字号、改字重、做实色底。

理由：一张 20 行表格里有 20 个状态标签，任何一处不一致都会被看见。密度会放大不一致。

### 9.4 形状相近、语义不同的两类元素

| | 方角标签（圆角 2） | 胶囊（圆角 full） |
|---|---|---|
| 表达 | **对象的状态**，不可点 | **用户的选择**，可点可关 |
| 用在 | 表格 `badge` 列、面板内的状态 | `main.filters` 的已选筛选条件、`inspector.tabs` 的某些形态 |

**不可混用。** 混用后用户会去点状态标签（以为能筛选），或者不敢点筛选 chip（以为是只读状态）。这是形状承诺的可点性，比任何提示文字都强。
