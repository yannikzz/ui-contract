# ADR-0014 · 投影分两级：文件层任何环境都要产出，运行层跑不了就明说

---

## 背景：一次实测里，agent 一个投影文件都没写，而且它说得出理由

2026-08-28 的 gate 3，`greenfield-mobile` 的 with 臂。判据 `projection-generated` 挂了，
而 agent 在交接时**主动写下了原因**：

> 3. **没有线框，也没看过任何渲染结果。** 密度、3 个金额数字在窄屏会不会换行、一屏能放几行
> 流水 —— 这些只能看不能推，规范里全部标了待定标记。

它不是忘了。`skills/ui-contract-wireframe/SKILL.md` 的完工清单要求 **dev server 起来**、
**`check-colours.sh` 运行并贴出真实输出**、**type-check 运行并贴出输出**——三件都要 `Bash`，
而那次会话没有 `Bash`。于是它做了一个看起来合理的推论：**跑不起来，就不开始。**

**这不是 eval 的人造问题。** 同一个推论会在任何禁用 `Bash` 的 agent、任何没装 Node 的机器、
任何权限受限的环境里重演。而 ADR-0013 决策一说投影是**用户判断结构成不成立的唯一手段**，
「排除的备选」那一节明写：把投影推到第二条链上，交接时交回的就只有一份 Markdown，
用户没有可看的东西。**今天在无 `Bash` 环境里发生的正是那件被排除掉的事**，只是原因不同。

---

## 决策一：投影分两级，文件层不依赖任何工具

| 级 | 内容 | 要什么 | 跑不了时 |
|---|---|---|---|
| **文件层** | 投影的源码、`check-colours.sh`、目录 `CLAUDE.md`、`.gitignore` 那一行、repo-root `CLAUDE.md` 里的重建与启动步骤 | 只要 `Write` | **没有「跑不了」这回事，必须产出** |
| **运行层** | dev server 起来、`check-colours.sh` 真的跑过、type-check 真的跑过、密度用眼睛确认 | `Bash` + Node | **明说哪几项没做，并交出用户自己跑的命令** |

**文件层是完工的下限。** 一份写好但没跑过的投影，用户在自己的终端 `npm i && npm run dev`
就能看；一份没写的投影，谁也变不出来。这两者之间不是程度差别。

## 决策二：「没跑起来」和「灰」是两种不同的不完整，不许混为一谈

ADR-0013 说**灰投影是完整的**——`design.md` 是可选源，没接上时投影照样是一个完整源的完整投影。
本记录不动那句话，但要防一次显然的误读：

> 灰 = **源**没接上，产物是完整的。
> 没跑起来 = **验证**没做，产物是完整的而**读数是缺的**。

前者交接时不必道歉，后者必须点名。把两者说成一回事，等于把「我没验证过」讲成「这是设计如此」。

## 决策三：跑不了时，缺的那项读数要**点名**，不是笼统说一句

`skills/ui-contract/SKILL.md` 已经写着「be explicit about what you verified and what you didn't」，
线框的完工清单最后一条也是「Stated plainly what was verified and what wasn't」。
**这条纪律早就在，缺的是让它机械。** 背景里那次实测其实做对了这一半——它点名了密度、窄屏换行、
一屏行数三件事——它做错的是**因此就不写文件**。

所以规则的两半要一起写进完工清单，否则下一个 agent 还会把「说清楚」当成「可以不做」。

## 决策四：密度是投影独有的读数，它的缺席要计入结构半场的交接

`layout.md` 里标 ⏳ 的数由视觉半场结算（ADR-0013 决策六）。**密度不是 ⏳**：它不等视觉给值，
它等一次真实渲染。跑不起来时它就是没有，而且**没有任何下游会补上它**——视觉访谈不问密度，
体检是几个月后的漂移检测。

所以这一项要出现在交接里，和 ⏳ 清单并列但分开写：⏳ 是「等另一半给值」，
密度是「等有人把它跑起来看一眼」。两者的收件人不同。

## 排除的备选

| 排除的 | 为什么 |
|---|---|
| **给 eval 套件授予 `Bash`** | 它治的是测量，不是产品。真实用户的受限环境不会因为我们的测试拿到 `Bash` 而消失。而且 `testing/evals/README.md` 记着不授予的理由——线框完工清单要装依赖，等于在沙箱里执行任意 postinstall |
| **把 `projection-generated` 降成 with-only 不计分的指示器** | 保住了观测，放弃了分数——而这条判据守的是 ADR-0013 决策一列的达成项。降级等于承认那一项可以不做 |
| **撤掉判据，如实记回「`wireframe` 产物无人守」** | 诚实，但这是最后一条路，不是第一条。判据挂了指向的是一个真缺口，先修缺口 |
| **把「跑起来」整个从完工清单里删掉** | 那样密度、窄屏换行、一屏行数这些**只有渲染能给的读数**就永久没有出处了。ADR-0013 排除「把投影一并推到第二条链」时用的就是这个理由：用户需要可看的东西 |
| **让 agent 在无 `Bash` 时把投影写成静态 HTML，好歹能双击打开** | 换了技术栈就换了投影的性质。ADR-0011 的工作台决定明写线框**留在 React**，理由是丢掉类型系统会把类型形状的禁令降级成注释。为了能双击打开而丢掉那个，代价大过收益 |
| **在完工清单里写一句「没有 `Bash` 就尽力而为」** | 「尽力而为」是散文，agent 读了它仍然要自己判断什么算尽力——背景里那次的判断就是「不写」。分级是可执行的，措辞不是 |

## 知道要付的代价

1. **无 `Bash` 时交回的投影没有被任何东西验证过。** 颜色纪律、类型、渲染三样都没跑。
   `check-colours.sh` 随线框交付，但**交付不等于运行**——模板头部自己写着「它运行的那一刻是
   规则唯一还机械的时刻」。跑不了时那一刻就没有发生，规则退回到人读。
2. **完工清单变长，而且长在最容易被跳过的地方。** 一份写好但没验证的投影，从产物上看和一份
   验证过的完全一样——`testing/evals/README.md` 代价 3 记过同一个形状（正确收尾与撞墙截断
   盘上一样）。所以这一条也只能靠交接话术守，产物类判据分不开。
3. **`projection-generated` 会变绿，而它变绿不代表投影跑得起来。** 判据看的是工作台里有没有
   文件。分级之后无 `Bash` 的跑也会写文件，于是这条判据从「永远红」变成「永远绿」——
   **后者更危险**。它守住的是「有没有产出」，不是「产出对不对」，这一点要写进判据自己的文档，
   否则记分板上它看起来守的是后者。
4. **本记录没有为「运行层做没做」建立任何机械守卫。** 决策三要求点名缺项，而那是行为不是产物，
   和「结构半场有没有正确收尾」同一类。可以挂到 `structural-half-handed-off` 上，但那条判据
   刚刚才因为**问得太宽**而在真实产物上假红过一次，往里再塞一个要点的风险是重演稀释。
   **所以这一条今天无人守，是知情的选择。**

---

## 复议条件

- **实测出现「agent 有 `Bash` 却仍然只交文件层」** → 说明分级被读成了两个可选项，
  而不是一个下限加一个条件项。那时要把运行层写成默认、把文件层写成降级路径，不是反过来。
- **`projection-generated` 在有 `Bash` 的真跑里也绿，但投影其实起不来** → 代价 3 兑现了，
  判据要换成能分辨「写了」与「跑得起来」的形态，或者明说它只守前者。
- **密度这条读数连续多轮拿不到** → 说明受限环境是常态而非例外，那时「投影是判断结构的唯一手段」
  这句话本身要重估：一个多数时候跑不起来的手段，不配叫唯一手段。
