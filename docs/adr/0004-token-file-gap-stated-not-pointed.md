## 背景

ADR-0003 把这条记为**已知缺陷**：0.2.0 的 `design.md` 把值的权威指向 token 文件，而这一版没有任何单元会生成它——`ui-contract-assets` 只产结构组件，token 文件生成推到了 0.3.0。跑完整条链的用户会拿到一份指向磁盘上不存在的路径的规范。

当时给它的兜底只有一条：**没有人在用**。

复查时发现缺口比记的更靠上游。`ui-contract-design` 已经有一节「When there is no token file yet」，要求把缺失说出来——所以这不是完全没处理。真正没处理的是三件事：

1. `config.md` 的 paths 表里「Token file」一行只写了「项目现有 token 源」。**没有源时填什么，没人说**——填进去的会是一个编造的默认路径，而**其余每个单元都读这张表**。断链从这里开始，不是从 `design.md` 开始。
2. 那一节说缺口「必须在规范可用前补上」，语气假定有人会去补。**这一版的链条里没有那个人。**
3. 缺失只要求「说给用户」，没要求它落进产物正文——而读产物的人多半没看过那次对话。

## 决策

> **不写死路径，把缺口写成产物里的一句话；第 2 项由「已知缺陷」降为「已声明的缺失」。**

规则落在四处：paths 表的填法、`design.md` 骨架里分工声明那段、`ui-contract-design` 的缺口一节、以及它的完工清单新增一条。

判据是 ADR-0001 原则「不生产用户的答案」的同一个手法，`ui-contract-assets` 已经在用它处理 `Shell` / `Slot`——**架构里点了名但还不存在的东西，说出来，不要即兴造一个**。一条指向空处的路径读起来像规范过期了；一句写明的缺失读起来是诚实的。

### 重判 0.2.0 的公开性：仍不公开，但**兜底理由换了**

ADR-0003 要求动第 2 项就必须重判这一条。重判结论分两半：

| | 之前 | 现在 |
|---|---|---|
| 这个缺陷需不需要「没人在用」兜住 | 需要——它是一条真断链 | **不需要了**。缺失是产物内容的一部分，用户看得见 |
| 0.2.0 现在能不能公开 | 不能 | **仍然不能，但和这条缺陷无关了** |

**这两条不再是绑定的一对。** 现在挡着公开的是另外两件事，都与 token 文件无关：

- issue #4 的第一条判据（跑完整条链后 `design.md` 里不存在指向空处的路径）**是行为判据，只有实跑 eval 能验**。`tests/run.sh` 不测这个，本次改动没有任何实跑证据。
- issue #9：`decision-tree-total` 在真实产物尺寸上系统性失效，**eval 分数当前整体不可信**。在一个判据已知会误判的记分板上宣布「可以发了」，是拿一个坏尺子量。

所以这条判据并进 issue #6 的欠账清单，下次因为任何原因跑 eval 时一并结清，不为它单独跑。

**这里刻意没有做的推理**：规则文本读起来对 → 机制有效。仓库 `CLAUDE.md` 记着这条推理在此错过两次，两次都表现为「输出看起来完全正常」。

## 排除的方案

**A · 把 token 文件生成从 0.3.0 提到 0.2.0。**
token 文件的形态跟技术栈走，做它就会把 issue #2 第 1 项（资产层多技术栈）整块拖进 0.2.0——而那一项是 ADR-0001 决定 A 的复议条件，一旦启动可能反过来推翻架构。为消一条断链而拉动一个可能触发架构复议的大件，代价和收益完全不成比例。

**C · 什么都不做，继续靠「不公开」兜住。**
兜底不是修复。每次有人想发版都要重新想起这件事，而「想起」是会失效的——ADR-0003 把它写下来正是因为不信任「大家都记得」。

**把缺失只写在给用户的报告里（现状的做法）。**
报告是一次性的，产物是长期的。半年后读 `design.md` 的人没看过那次对话。

## 连带影响

- `ui-contract-design` 的完工清单从 5 条变 6 条；新增那条是可机械核对的（产物里有没有指向不存在文件的路径）。
- `config.md` 的 paths 表新增一种合法填法「none yet」。查过下游：**没有单元把该格当路径解析**。最接近的是 `audit` 脚本的 `TOKENS`，但它只用在一处 `grep -v` 排除项里，且 `ui-contract-audit` 已有一条「没有 token 源就不跑 token 相关检查」。所以「none yet」当前是安全的——**安全靠的是那条规则，不是脚本自身**，下一个要解析这一格的人得先看到这里。
- issue #6 的欠账从三笔变四笔。

## 复议条件

| 决策 | 什么条件下复议 |
|---|---|
| **缺口写明而非生成** | 若实跑显示模型仍然会在 `design.md` 里补出一个具体路径（哪怕缺口那句话也写了），说明「说出来」这个手法压不住模型的自动补全倾向，应改为在 `enforce` 层加一条机械检查 |
| **0.2.0 仍不公开** | 上述两个阻塞（判据 1 实测通过、#9 的判据修好）都解除时立即重判，不必等其他能力做完 |
| **第 2 项不再绑定公开性** | 若后续发现还有别的单元会写出指向 token 文件的死路径，说明缺口不止这四处，绑定关系要重新建立 |
