# ADR-0008 · 测试合并进 `testing/`，并按成本排成四道网关

| | |
|---|---|
| **状态** | **Accepted**（2026-08-21 定案） |
| **日期** | 2026-08-21 |
| **相关** | [ADR-0003](0003-package-boundary-fifteen.md)（包边界）· issue #6 · issue #12（判据的判据）· PR #13 |
| **取代** | ADR-0002 / 0003 / 0004 / 0006 里对 `tests/`、`evals/`、`grader-check/` 的**路径引用**。那些记录的决定一条都没动 |

> 本 ADR 记录**为什么这么选、排除了什么、什么条件下复议**。四道网关各自的命令与判据住各自的 README 与脚本注释，本文件只指向，不复述。

---

## 背景

测试原本散在三个顶层目录：`tests/`（免费的结构断言）、`evals/`（花钱的行为用例）、`grader-check/`（验判据的夹具）。三者是被**依次追加**的——每一个都因为一次真实事故而生，没有一次是照着整体设计放的位置。

这次重看，发现两件事。

**一、分层的依据错了。** 三个目录是按「被测对象」切的：代码 / 效果 / 尺子。但决定一个测试**什么时候跑**的从来不是被测对象，是**成本**。而成本这一维上有一整档是空的：`claude plugin eval --max-cost-usd 0` 会把套件完整加载、校验、并对每条判据做 coherence 检查，然后跳过每一次 run——**$0，不到一秒**。`evals/README.md` 那「十二个坑」里大半是配置类问题，全都可以在这一档免费暴露；坑 4（写文件的工具必须显式授权）尤其典型，那条是花实跑的钱买来的，而 harness 一直在免费打印同一件事。

**二、这些命令的官方文档在仓库外不存在。** `claude plugin eval` 处于 early access，`code.claude.com/docs/en/plugin-evals` 返回 404，`llms.txt` 索引里也没有。官方参考文档只以字符串形式内嵌在 `claude` CLI 二进制里——它自己第一句就写着 *there is no public documentation page for them yet*。这意味着「查文档」这个动作，在这个仓库里必须先有一份**仓库内的**文档才成立。

## 决策

**一、三个目录合并进 `testing/`，按成本排成四道网关。**

| 网关 | 判什么 | 成本 | 落点 |
|---|---|---|---|
| 0 | 磁盘结构；以及每条断言自己能失败 | $0 | `testing/structure/` |
| 1 | eval 套件的 schema；每条判据的 coherence | **$0** | `testing/preflight.sh` |
| 2 | 判据有没有判别力 | ~$0.06/case | `testing/grader-check/` |
| 3 | 插件有没有改变行为 | ~$18 | `testing/evals/` |

`./testing/run.sh` 跑前两道。前一道是后一道的硬前提——这不是纪律，是省钱：网关 1 能免费抓到的东西，没有理由拖到网关 3 花 $18 才发现。

**二、eval 目录写进 manifest，不靠每次带 flag。** `.claude-plugin/plugin.json` 的 `experimental.evals` = `testing/evals`。嵌套路径**实测可用**（`--help` 说只能是单段名，参考文档举的例子是 `quality/evals`，以实测为准）。

**三、`testing/grader-check/` 保持独立目录，不并进 `testing/evals/` 用 tags 区分。** 理由是 results 落点：`--eval-dir` 决定 `results/` 写在哪，两套 results 混在一个目录里，`testing/grader-check/README.md` 那套「从历史 report.html 里提真实产物当夹具」的做法会立刻分不清哪份是哪份——而夹具**必须是真实产物**这一条，本身就是量出来的（手搓的负样本不干净，见该 README）。

**四、把这次改名带来的路径过期做成可见的，而不是回去改历史。** `CLAUDE.md` 写着已接受的记录不编辑。那条规矩防的是悄悄改掉当初的决定，不是让路径永远正确。所以旧 ADR 一个字不动，新增**不变量 27**：ADR 里写到的仓库内路径若已不存在，打 warn。它不判失败——过期不是错误，静默才是。

## 顺带定案的三件，理由不是整理

**`docs/reference/plugin-eval.md`：官方参考文档 vendor 进仓库。** 63KB，逐字提取，未编辑，附 `EXTRACT.md` 记录升级 CLI 后重新提取的步骤。它只随 CLI 分发，所以这份拷贝会过期——但「过期的文档」和「没有文档」不是一回事，而后者是这个仓库过去一直的状态：`testing/evals/README.md` 那十二个坑，是在没有文档的情况下用实跑的钱一条条撞出来的。

**per-skill 断言：从 0 条开始有。** `skill-fired` 判据是 `tool_used: Skill` **不带 `input_match`**——它断言的是「Skill 工具被调用过至少一次」，不问哪一个。15 个包共用这一条，等于行为层对每个包的保障都是零。现在 `ui-contract-layout` / `ui-contract-design` 各有一条点名判据，`existing-admin` 多一条 `tool_order` 守「先量现状再写规范」的时序。

那条时序是**捡回来的**：删掉 `decision-tree-total` 时写的是「拆成两条：机械的部分交给 regex」，而落地的 regex 判的是 `as-built.md` 里引没引到真实组件名——**调用顺序那一半没有被任何判据接住**。`tool_order` 是官方现成类型、免费、一直没用过。

**`runs: 1` 不写进 case。** PR #13 声称给 `greenfield-originate` 加了这一行以压成本，实际没加（见下）。这次也不补：官方明写 *A single run on a non-deterministic agent is noise*。成本该用试跑命令 `--runs 1` 解决，不该把套件永久降级。

## 排除的方案

| 方案 | 为什么不 |
|---|---|
| 保持三个顶层目录，只补网关 1 | 网关 1 的价值在于它站在成本序列里；挂在三个按被测对象切的目录旁边，下一个人不知道该在什么时候跑它 |
| 用 `tags` + `--tag` 把夹具与正经用例合成一个套件 | results 落点会混（见决策三）。而且当前三个用例成本相同，smoke/full 的切分是假的——加一个没人查询的字段 |
| 给每个技能建独立 eval 用例 | 8 个能力包都有前置门（不变量 10），单独扔进空沙箱会**正确地**停下来说缺上游产物，判据必挂且与质量无关——`testing/evals/README.md` 坑 3 的形状。能独立测的只有 5 个原语包与两个入口，那部分记进 issue #6 |
| 回去把旧 ADR 的路径改对 | 与「已接受的记录不编辑」冲突。改路径看起来无害，但一旦开了这个口，「只是改个措辞」和「改掉当初的判断」之间就没有边界了 |

## 这次改的过程中，三条新检查自己中过招

写下来是因为它们全都是这个仓库的招牌失效模式，而且**每一条在被注入之前都是绿的**。

- **网关 1 第一版**只判「`✗` / `cannot pass` / `No eval cases found` 都不出现」。把授权变量清空之后，CLI 报 `error: option '--allow-tools <tools...>' argument missing` 直接退出，三个坏字符串一个都不出现——**网关绿着，而命令根本没跑起来**。「坏东西没出现」和「好事发生了」是两件事，只判前者的检查在最坏的情况下最安静。现在先要求看见 `Plugin under test:` 与 `cost ceiling $0 hit`。
- **不变量 26 第一版**只认「不变量 N」「检查 N」两种措辞。注入三种写法，它抓住两种，漏掉的那一种是把一个不存在的编号跟脚本名写在同一行——**恰好是真实发生过的那一种**（PR #13 正文那句话，就是脚本名加上一个当时并不存在的编号）。现在锚点是「与脚本名同行的任何『第 N 条』」。<br>写这一段时它又响了一次：原稿把那个虚构编号原样引在正文里，检查当场报红。这条 ADR 因此是它自己的第一个用例——**叙述与代码对不上，现在会当场被拦住，而不是等到有人去数**。
- **不变量 22**（线框里颜色的值只在 `NEUTRAL`）原本只判「哨兵块外还剩产品组件吗」。把某个产品组件**整段搬进**哨兵块、在块内写死品牌色，块外还有别的导出，照样 exit 0。存在性代替了完整性。现在块内允许的导出是声明出来的名单，多一个就得改名单，而改名单会出现在 diff 里。

## 仍然守不住的

- **`tool_used` / `tool_order` 没有便宜的验证替身。** 试过用 `context.history_file` 重放一份含真实工具调用的 transcript 让判据判它，**实测重放的历史判据看不见**（`Read called 0x`）——只有新一轮的工具调用算数。这两类判据的正负双向只能在真跑里量。判据旁与两份 README 都写了 `UNVERIFIED:`。
- **`tool_used: Skill` 默认不计分。** 官方规则：不写 `arm` 的 `Skill` 判据在 `with-without` 两个臂里都被排除出分数。`input_match` 打错一个字符 → 静默失配 → 退出码 0。不变量 25 免费判「技能名真实存在」，但判不到「正则本身写错」。
- **13/15 个包在行为层仍无针对自己的断言。** 不变量 25 每次跑都把这个数字打出来，记在 issue #6。
- **「每条断言必须声明自己的锚点」不做机检。** 那样的检查本身就会锚在词上——递归得有终点，终点写在 `CLAUDE.md`，靠评审。

## 复议条件

| 条件 | 怎么处理 |
|---|---|
| `plugin eval` 转正（脱离 early access） | `CLAUDE_CODE_WALNUT_SPIRE` 不再需要，网关 1 的「早期访问没开就跳过」分支可以删掉；同时官方文档页会出现，`docs/reference/` 那份 vendor 拷贝改成指向它 |
| CLI 升级导致 `--max-cost-usd 0` 不再跳过全部 run | 网关 1 的整个前提失效，得重判。它的断言判的是 stdout 上的 `cost ceiling $0 hit`，所以这件事会**当场报红**而不是静默 |
| `experimental.evals` 键随转正改名或移到顶层 | 不变量 24 会当场报红（它直接读这个键） |
| 独立测原语包的成本降到可接受 | issue #6 那一笔可以结，`testing/evals/` 增加 5 个原语用例与 2 个入口用例 |
