# ADR-0006 · 线框加换肤预览，理由从「没有颜色」换成「没有颜色的值」

---

## 背景

issue #11 判过一次这件事，而且判的时候就承认对方更强。原文：

> 线框图保持全灰。**代价是真的**：光看色块判断不了一套配色，能判断的恰恰是真实密度的界面，所以「给线框图加预览模式」**在设计上更有说服力**。
>
> 仍然不加，因为失效模式是沉默的：模式一旦存在，半年后没人记得它默认关闭，agent 打开截图、照着抄，第二个视觉真相源就成立了。

ADR-0005 的器具落地之后，这段话有一半不再成立，另一半反而看得更清楚了。

**不再成立的那半**：器具的样张不是色块，是真实密度的通用控件——三级按钮、表格行（含超长不断行标识符）、卡片、状态标签、空/加载/局部失败三态。「光看色块判断不了配色」这条已经被接住了。

**剩下的差别只有一个，而且是真的**：器具展示**通用控件**，线框展示**这个产品的真实信息架构**。用户能判断「一个表格刷上这套皮好不好看」，判断不了「我的招聘看板刷上这套皮好不好看」。而后者才是他真正要决定的事。

**看得更清楚的那半**：「第二个真相源」这个说法其实不准。如果预览模式**直接读 token 文件**，agent 照抄看到的就是 token 文件里的值——抄的是对的，没有分家。真正起作用的机制是另一件事：

> **全灰是把 agent 逼去 token 文件的那个东西。** 线框一旦有颜色，agent 就没有理由再去找 token 文件，它会把眼前看到的值写死进业务代码。

推论 2 说的「藏起来 + 指路」，起作用的是**指路**，不是藏。

---

## 决策

> **线框加换肤预览，器具保留。判据从「线框里没有颜色」换成「线框里没有颜色的值」。**

两者是不同的约束，而且后者更强：**它是可机检的。**

四条一起才成立，缺一条这个结构就塌：

| # | 约束 | 挡住什么 |
|---|---|---|
| 1 | 所有颜色走 `--wire-*` 自定义属性；**值只在 `NEUTRAL` 一处**，且都是线框自己的灰 | 线框里出现任何品牌值 |
| 2 | 预览**运行时读 token 文件**（import，不是拷贝），自己不带值 | 值分家、规范过期 |
| 3 | **默认关闭且不持久化**，每次重开都是灰的 | 「没人记得它默认关闭」 |
| 4 | 开启时有**不可关闭的横幅**：值来自哪个文件、不要从这里抄 | 「agent 打开截图、照着抄」——截图自己带着这句话 |

第 4 条是专门冲着 ADR-0001 点名的那个失效去的。**默认关闭够不着那个 agent，一张图片够得着。**

⚠ **横幅的颜色必须是固定的,这一条是实跑量出来的。** 第一版用 `--wire-strong` / `--wire-strong-fg` 画它——于是**警告条被它正在警告的那套皮换了肤**。把 `--wire-strong` 映到一个浅色 primary、`-foreground` 是白，横幅当场白底白字消失：守卫恰好在主题让它最难被注意到的时候不见了。**一个警告不许依赖它所警告的东西。**

因此横幅与标注层同属 inspect 装置，一起住在模板的 `INSPECT CHROME` 哨兵块里，带固定色，`structure.sh` 的断言只豁免这一块。

第 1 条落成 `tests/structure.sh` 的一条断言。一条被推翻的决定需要的是机械守卫，不是一句叮嘱——这是本仓库反复吃亏的地方。

**标注层不跟皮肤走。** 提示气泡的深色是写死的：它是 inspect 用的界面装置，不是产品表面。跟着皮肤变，等于把提示框放进它正在描述的那个东西里。

## 排除的方案

| 方案 | 为什么不 |
|---|---|
| **维持全灰**（issue #11 的原判） | 用户看不到自己产品的真实 IA 刷上这套皮的样子，而那正是他要决定的事。issue #11 自己就写了对方更有说服力 |
| **线框加预览，废掉器具** | 线框是一次性产物，结构一变就重生成；把「拧旋钮」挂在一个会被重生成的产物上，用户的输入会跟着蒸发。`tokens.input.json` 的归属也会失去落点 |
| **预览把值拷进线框** | 当场制造第二份值，正是原判担心的那件事——只是这一次担心得对 |
| **预览默认开启** | 灰是默认状态才有「指路」的作用；默认开启等于没有推论 2 |
| **预览状态存进 localStorage** | 「半年后没人记得它默认关闭」会**因此**成真，而不是被防住 |
| **横幅可关闭** | 可关闭的警告在截图里就是不存在的警告 |
| **标注层也跟着换肤** | 提示框会变得和它描述的东西同色，inspect 模式失去对比 |
| **就地改 `implementation.md`** | 已接受的记录不编辑。issue #11 自己写着「要推翻这条需新立 ADR」 |

## 连带影响

- `wire.tsx.template`：中性色从写死的 Tailwind 类收进 `NEUTRAL`；新增 `SKIN`（**出厂全空**，与器具的 `ROLE` 同形，理由也相同）、`useSkinVars`、`SkinBanner`。
- `implementation.md`：视觉纪律那张表的第一行换判据；新增预览模式一节；演示开关条加一项；目录级 `CLAUDE.md` 的刻意取舍清单里「不带品牌视觉」一条要改写——**照原样留着的话，下一个 agent 会把预览模式当成需要「修掉」的东西**。
- `ui-contract-wireframe/SKILL.md`：完工清单新增两条。
- `tests/structure.sh`：新增断言（颜色值只在 `NEUTRAL`，`SKIN` 出厂全空）。
- issue #11「一个我承认有代价的推荐」整节作废，改写为指向本 ADR。

**器具没有变。** 两者分工：器具拧值（通用控件、对比度实时校验、导出 JSON），线框看结果（真实 IA）。同一份 token 文件，两个消费者，零拷贝。

## 什么算这个决定失败了

写清楚，因为推翻一条已定案的决定，举证责任在推翻的一方：

1. 在装了本插件的项目里，业务代码中出现的硬编码色值**与 token 文件里的值相同**——说明有人照着预览抄，而不是去引 token。`audit` 的检查 3 抓得到色值，但它分不出这一种；要判这条得比对值。
2. 线框的 `NEUTRAL` 之外出现颜色值——断言会红。
3. 用户报告「线框看起来就是产品」——说明低保真这件事被换肤稀释了。

**断言抓不到的两种，都是 2026-08-21 在真实线框上跑出来的，不是推理出来的：**

**其一，颜色根本不只在 `wire.tsx`。** 实测 `examples/admin-console`：`wire.tsx` 里 17 处，而 `App.tsx` / `Inspector.tsx` / 四个 `pages/*.tsx` 里另有约 140 处。`structure.sh` 第 22 条只断言随技能发布的那份模板；用户项目里生成的线框不在本仓库，而 `ui-contract-audit` **根本不看线框目录**（它审生产树）。所以规矩 1 在真实项目里只有人评审在守。**绿色的体检报告不等于线框里没漏颜色。**

**其二，控制面也不能跟皮肤走——而这是一条规则，不是三个例外。** 标注层、横幅、以及**演示开关条**都需要这个豁免，共同的理由是同一句话：

> 凡是你用来**控制或解读**线框的界面，都必须在任何皮肤下保持可读，因此都不许跟皮肤走。

开关条那一条是实测撞出来的：`Sw` / `Group` 定义在 `App.tsx` 底部、远在产品标记之后，于是「把产品标记之后的都转掉」会把它们一起转走。后果是**关掉换肤的那个开关自己在换肤里变得看不见，你被困在里面**。

**另一种断言抓不到的**：往 `NEUTRAL` 里直接加一个品牌色。`NEUTRAL` 内本来就允许写值——那是线框自己的灰——所以「新加进去的是不是灰」只能靠人评审。已量过：注入 `'--wire-brand': '#2563eb'` 仍然 exit 0。

写下来是因为这条断言看起来像守住了整件事，实际只守住了「值不许散落」。散落是常见的失效，往一处集中的地方添一笔不是——但它是**存在**的。

## 复议条件

| 决策 | 什么条件下复议 |
|---|---|
| **加预览模式** | 出现上面第 1 条的实例，即退回全灰，并把本 ADR 记为一次失败的推翻——不要再试第三次 |
| **默认关闭 + 横幅** | 若实测显示用户几乎总是开着它用，说明「默认灰」在真实使用里没有发生，指路机制其实已经失效，届时要重判的是推论 2 本身而不是这里 |
| **器具与线框并存** | 若两者长期只有一个被用，说明切早了，应并成一个 |
| **标注层不换肤** | 若换肤后提示气泡在深色皮肤上读不出来，说明它需要的是自适应对比而不是固定深色 |
