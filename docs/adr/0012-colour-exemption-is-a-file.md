# ADR-0012 · 颜色豁免的锚从注释哨兵换成文件，检查随线框生成

## 背景：一条只在半个文件上成立的约束

ADR-0006 把判据从「线框里没有颜色」换成「线框里没有颜色的**值**」，理由写得很清楚：
**后者可机检**。`implementation.md` 还专门加了一节说这覆盖整个目录、不只 `wire.tsx`，
并附了实测数字。

而机械守卫只有一条，只跑一个文件：`invariants.sh` 第 22 条判 `wire.tsx.template`。

**这不是疏忽，是没有对象可判。** 技能的 `assets/` 里只有模板文件；`App.tsx`、`pages/*.tsx`
都是 agent 现场生成的，本仓库里不存在。`implementation.md` 自己也写着那句
「Nothing checks this in a user's project」。所以约束 1 在用户项目里的真实状态是**评审制**，
而 ADR-0006 把「可机检」当成了换判据的理由。两句话之间隔着一整个目录，没有东西在比对。

**撞出这件事的是一个具体的东西**：示例线框 `App.tsx:153,156` 的 `text-amber-300`。
按「控制面不跟皮肤走」，演示条**必须**硬编码，所以它按意图合规。坏掉的是**豁免没有被声明**——
在那个文件里，「刻意固定的装置颜色」和「漏出来的产品颜色」长得一模一样。全目录 172 处
硬编码颜色类里只有 6 处是装置，而这个区分只存在于人的脑子里。

## 决策一：豁免的锚是**文件**，不是注释哨兵

> 颜色值只允许出现在两个地方：`wire.tsx` 的 `NEUTRAL`，和 `inspect.tsx` 整个文件。

`inspect.tsx` 装标注层、换肤横幅、换肤编辑器，**以及演示开关条的全部外观**
（`DemoBar` / `Group` / `Sw` / `Readout` / `Alert`）。`wire.tsx` 只剩 `NEUTRAL` / `SKIN` /
`useSkin` 与中性零件。

三条理由，前两条是实测过的：

| # | 理由 |
|---|---|
| 1 | **哨兵能挪，文件不能悄悄挪。** 第 22 条的用例里已经记着两种穿透：把 `END` 推到文件尾等于全文豁免；把产品组件整段搬进块内就能在里面写死颜色。两次都靠往断言里补一层来堵。文件边界把「搬进豁免区」变成一次 diff 里看得见的文件移动，而挪两行注释在 review 里长得像格式调整 |
| 2 | **随线框交付的检查必须简单到能被信任。** 哨兵方案要在 shell 里逐文件解析 `BEGIN`/`END` 配对，并把第 22 条那几层守卫全部重实现一遍。文件边界方案是两条 grep |
| 3 | **它顺手灭掉一个已知的坑。** `implementation.md` 记着：`Sw` / `Group` 坐在 `App.tsx` 末尾、产品标记之后，所以「把产品标记以下全部转成 `var()`」的一遍会连它们一起转掉。那条现在是一句提醒；装置搬进 `inspect.tsx` 之后它不再可能发生 |

豁免变成一个文件，于是**这个文件的导出是一份声明出来的封闭名单**——沿用旧断言
`INSPECT_EXPORTS` 的做法，只是锚从注释换成了路径。往里加一个名字要改名单，改名单出现在 diff 里。

## 决策二：颜色检查**随线框生成**，不是 CI 那一层

新增 `assets/check-colours.sh.template`，生成线框时一并落地。

**它进不了 CI，这一点必须写在它自己的头部注释里。** ADR-0011 把线框放进了不提交的工作台，
所以在多数项目上这个脚本根本不会在 CI 里跑。它的读者是**此刻正在改线框的那个 agent**——
也正是这条规则还能被廉价执行的唯一时刻。把它描述成 CI 层是一句会被相信的假话。

`invariants.sh` 这一侧同时改两条：第 22 条的锚换成文件；**第 23 条改成读两个模板**。
后者不是可选的连带改动——拆分之后它只读 `wire.tsx.template`，落后数从 7 掉到 4，
**看起来像示例追上了一截，其实是搬走的那批符号不再被比对**。断言的覆盖面缩小时它不会变红，
只会安静地少判。

## 排除的方案

| 方案 | 为什么不 |
|---|---|
| **维持现状（只判模板，用户项目靠评审）** | ADR-0006 拿「可机检」当换判据的理由，而它在用户项目里从来没成立过。留着就是让那句理由继续赊账 |
| **哨兵推广到每个文件** | 见决策一的三条。额外一条：哨兵写在一个 agent 现场生成的文件里，第一件会被漏掉的事就是把它写上——而漏掉哨兵的后果是整个文件被判违规，**噪音落在正确的代码上** |
| **颜色检查并进 `ui-contract-audit`** | 体检审生产树，线框是一次性产物；把一次性产物的规矩塞进发布前体检，会让「线框里漏了个颜色」有资格拦住一次发布 |
| **靠 ESLint 规则而不是 shell** | 要求用户项目有 ESLint 且配置得进去。`audit.sh` 选 shell 是同一个理由，保持一致 |
| **装置也跟皮肤走** | ADR-0006 已经判过并实测过：警告条被它警告的那套皮换肤，浅色主题下白底白字消失。**一个警告不许依赖它所警告的东西**。这条不动 |

## 代价，写下来而不是藏着

- **示例的落差又大了一项。** 按 `examples/README.md` 的规矩不手改示例——落后可以，隐瞒不行。
  `DemoBar` / `Group` / `Sw` / `Readout` / `Alert` 五个新符号已经逐个写进那张表。
- **shell 判颜色抓不到的东西，和旧断言一样多**，而且必须写在脚本注释里：往 `NEUTRAL` 里塞
  品牌色仍然合规（那是线框自己的灰，「加进去的是不是灰」永远是评审问题）；`inspect.tsx` 里
  写什么都合规（那正是豁免的意思）；具名颜色只在颜色属性的值位置上被认出来，写进 Tailwind
  类名或模板字符串里的抓不到。
- **多一个要跑的命令。** 理由必须写进生成的 `CLAUDE.md`，否则它会在第一次嫌慢时被删掉。
- **模板从一个文件变成两个**，目录说明、完成清单、第 22/23 条都要跟着改。这次全部改了；
  下一次拆分时这份清单就是提醒。

## 复议条件

- 若线框的技术选型改变（例如换成与框架无关的单页 HTML），**这条要重判**：单文件产物没有
  文件边界可用，那时哨兵或运行时断言会重新变成更好的选项。2026-08-25 讨论过一次并决定
  **保留 React**。
- 若实测显示 agent 生成线框时系统性地不跑 `check-colours.sh`，说明「随线框交付」这个形态
  不成立，应当把它挪进完成判据之外的某个更硬的位置。
