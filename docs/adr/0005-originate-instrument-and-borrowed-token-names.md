## 背景

本文件同时记两件事，它们在 issue #11 里合流。

**第一件是执行。** ADR-0003 的「issue #1 推出去的清单」里，第 3 项（`design` 的第二条完工判据：品牌属性选项成组给出且每项标代价）与第 4 项（`originate` 分支，ADR-0001 决定 B）一直挂着。它们不是新决定，是两条**已定但未执行**的定案。ADR-0003 为第 9 项写过这段话，同样适用于这里：一条自己消失的定案比一条没做的定案更贵。

清单第 2 项（token 文件断链）**已由 ADR-0004 结清**，不在本文件范围内。issue #11 正文起草时把本文件写成「ADR-0004」，是在实际的 0004 落盘之前写的，编号与「同时关掉第 2 项」那段都已按此更正。

**第二件是新决定。** 决定 B 把选择给在品牌属性维度上，用户选定后才推导具体值——但它没说推导出来的那些值**叫什么名字**。这个空缺一直存在，没有被当成问题，直到把它和三个已有事实放在一起：

1. `design.md` 是名字的实际来源（它写 token 名），但**从来没有任何一处文本声明过这件事**。
2. issue #11 让器具「从 `design.md` 的引用反推旋钮集合」——这一步**预设了** `design.md` 是名字来源，而那个预设当时没有依据。
3. ADR-0001 决定 A 的复议条件写着：若资产层难以适配 React 之外的技术栈，退回 A′ 并承认人肉翻译。**每个项目各自发明一套 token 名，正是让那条复议条件更容易被触发的做法**——同一套概念在 React 项目叫 `muted`、在 Svelte 项目叫 `subtle`，映射层就非写不可。

## 决策

### 一、`originate` 分支与值层器具落地

按 issue #11 执行：三条正交轴（密度↔呼吸感 / 锐利↔柔和 / 克制↔表现力）、三个互斥的点、每点标本项目的具体代价；模板资产 `theme-studio.html.template`；状态以 `tokens.input.json` 落盘（输入记录，**不是值权威**）。

这一段全部是 ADR-0001 决定 B 的执行，不含新决定。细节住 issue #11 与 `originate.md`。

### 二、借用一套外部 token 命名，但只借名字，不借权威

> **`design.md` 是名字权威。外部规范是写它时的输入，不是它的上级。**

四段式，缺一段这个结构就塌：

| 名单在哪 | 身份 |
|---|---|
| `design-md-outline.md` | **起草底稿**。agent 写 `design.md` 时照着来 |
| `design.md` 的 Opening 段 | **权威**。一张可解析的声明表：遵循哪套 / 项目自扩的 / 故意偏离的 |
| `tokens.input.json` | 键 = 声明表里的名字。**跨技术栈同名真正的承载体** |
| `theme-studio.html.template` | **仍然没有名单**。器具照旧从 `design.md` 反推 |

第四行不是遗漏。名单一旦存在，把它顺手复制进器具的诱惑才真正出现，`structure.sh` 那条断言因此比原来更重要，不是更不重要。

**借的是 shadcn 的命名，减去两类**：

```
留（19 个）  radius
             background / foreground
             card(+fg)  popover(+fg)  primary(+fg)  secondary(+fg)
             muted(+fg)  accent(+fg)  destructive
             border  input  ring

砍（13 个）  sidebar-* ×8       IA 载体
             chart-1..5 ×5      图表色
```

`sidebar-*` 必须砍，理由是本仓库已有一条成文判据在禁这个词：`no-desktop-skeleton` 的正文写着「**无论是在采纳还是在否定它**，都说明作者的参照系是别人的产品」。同一个仓库不能同时禁止和引入同一个词。`chart-*` 砍掉是因为 `design.md` 的 11 章里没有一章讲图表。

**为什么是这一套而不是别的**：shadcn/ui 与 shadcn-svelte 的变量名**逐字相同**（已核对两边文档）。跨技术栈同名的收益全部来自这一点，不来自 shadcn 本身的品味。

**bits-ui 不在候选里**：它是 Svelte 的 headless 组件库，明确「most components arrive completely unstyled」，**不发任何 token、CSS 变量或主题约定**。它与 shadcn 不是同类物，无法作为命名规范的来源。

### 三、名单只覆盖 1.5 章，其余章只带构词法

把这份名单对 `design-md-outline.md` 的 11 章逐章比过：

| 章 | 覆盖 |
|---|---|
| §7 圆角 | ✅ 完整（单基数 + 派生） |
| §2 色彩 · surfaces 表 | ✅ 对得上，少一个 `disabled` |
| §2 色彩 · 文字层级 | ⚠️ 大纲要 4–5 级，名单只有 2 级 |
| §2 色彩 · 语义色 | ⚠️ 只有 `destructive`，无 success / warning / info |
| §3 字号 · §4 间距 · §5 交互态 · §6 图标 · §8 动效 | ❌ 全无词汇 |

**11 章里覆盖 1.5 章。** 因此这条规范的正确表述是「一章半的命名约定」，**不是 `design.md` 的骨架**。其余各章明写「本规范不带词汇，名字由项目自定，但必须遵守成对构词法（有 surface 就配 `-foreground`）」。

这是名单与规则的分工，不是妥协：**有跨栈同名收益的地方用名单，没有的地方用规则。**

### 四、冻结度 🌡 试行

这套名单是从一个外部项目抄来的**假设**，不是从本项目结构推导出来的事实——与 ADR-0001 决定 B 给 0-1 生成品牌标 🌡 是同一条理由。

落地形态：`audit` 报 **warn 不报 drift**，`exit code` 不变。照抄 `structure.sh` 检查 13 的形状（`warn()` 不设 `FAIL`）。

⚠ **这里有一个刻意接受的代价**：加了 warn 之后，「有 warn 且 exit 0」在 CI 里就是一片绿。缓解手段是收尾打印 warn 总数，让它在终端里看得见；但 CI 不会因它而红，这是真的。选它是因为把一个外部项目的命名选择升格成用户仓库的硬约束更坏——shadcn 一改名，所有装了插件的项目 CI 同时变红。

### 五、`align` 只记录，不改名

治熵线的既有纪律是「**do not rewrite it**」。规范符合性对 `align` 的唯一产出是往声明表里写一行「本项目用的是自定命名」。

改名会把一次边界对齐变成一次全仓重命名，连带改动所有消费方代码——那是 `spec-before-code` 管的范围，与这个 issue 要解决的问题无关。现有 `existing-admin` eval 的 fixture 用的是 `surface.sunken` 这类点分命名，选这一项它**不用改**。

## 排除的方案

| 方案 | 为什么不 |
|---|---|
| 只采纳构词法，不带名单 | 成对规则不管那个 surface 叫 `muted` 还是 `subtle`——两个都合规，跨栈同名当场落空。**这是「跨技术栈同名」这个目的直接排除的** |
| shadcn 原样全量 30 个 | 要先推翻 `no-desktop-skeleton` 的理由，以及 issue #11 要加的 `structure.sh` 断言 |
| 只取最小核心集（6–7 个） | `card` / `popover` / `muted` / `accent` 正是写界面时天天用、且最容易各叫各名的，砍掉它们等于砍掉收益本身 |
| 名字权威 = 外部规范 | 把命名决定权交给上游项目。shadcn 改名或弃用某个 token，用户项目的规范当场过期——而本 plugin 承诺的是「三个月后仍在起作用」 |
| 名字权威 = token 文件 | token 文件尚不存在时（ADR-0004 那个已声明的缺口）`design.md` 就无名可引，整条链断在起点 |
| 间距 / 字号借 Tailwind 的刻度名 | 引入第二个外部权威；且 `spacing-4` 是**值**不是**角色**，与 §4 要的「间距语义表」不同构 |
| 声明只写成散文一句 | eval 抓得到，audit 拿不到白名单——它需要的是「哪些名字合法」，一句散文给不了 |
| 声明表放进新附录 | 大纲里附录的性质是「记录事实，不是规范」，声明表是规范的一部分 |
| `tokens.input.json` 另起一套键 + 映射表 | 名字权威会滑到映射表里；且发多栈映射表是 ADR-0003 推出去清单第 7 项 |
| 🔒 已冻结 | 见上，会让所有装了插件的项目跟着 shadcn 的改名一起红 |
| 命名规范单开一个 issue / 单开 ADR-0006 | 与器具共用同一份 `design-md-outline.md` 与同一条 JSON 接口，拆开后两头的追溯对不上 |
| 建根级 `CONTEXT.md` 收纳新术语 | 本仓库的开发词汇（切线、冻结度、推出去清单）全部住在 ADR 里，没有一个住在词汇表里。另开一份是这个仓库最不想要的形状 |

## 连带影响

- **`design.md` 的完工清单从 6 条变 7 条**；新增那条可机械核对（Opening 段有没有可解析的声明表）。
- **`audit` 新增第四种输出 `warn()`**，`ui-contract-audit/SKILL.md` 的 exit code 表要加一行说明 warn 不改 exit code。
- **`audit` 检查 3 与 4 的色值正则必须补 `oklch(`。** 两条现在都只认 `#hex` 与 `rgba?(`，而借来的这套命名当前就是 OKLCH。不补的话「符合外部规范」与「查得出硬编码色值」互斥——这一条与选哪套规范无关，是现在就漏着的。
- **新增一个 eval 用例 `greenfield-originate`**（4 条判据），补的是 0-1 线对 `design.md` **零判据**的空白：治熵线有 `existing-spec-slimmed-not-rewritten`，0-1 线此前一条都没有。

  起草时写的是「往 `greenfield-mobile` 加一条 grader」，落地时改了：那个用例的 prompt 只要「界面结构的规范」，产不产 `design.md` 不在它的射程内，判据挂上去必挂，而挂的原因与插件质量无关。**它从未实跑过**，四条判据都是推理出来的不是量出来的，欠账记在 issue #6。
- **issue #11 那条「器具内无内置 token 名清单」的判据要重写成四段式**，否则并进同一个 issue 之后会读成自相矛盾。
- ADR-0003 推出去清单**第 3、4 项由本文件关闭**；第 2 项此前已由 ADR-0004 关闭。已接受的记录不编辑，ADR-0003 的清单表不动。

### 新登记的待建

**暗色主题。** 它不是「同一套值的另一种渲染」，是**第二套完整的值**：一旦支持，token 文件从扁平映射变成映射的映射，`design.md` 的引用语法、audit 的断链检查、声明表格式、器具布局四处连锁。「由亮色推导」最有诱惑力也最坏——推导出的暗色几乎必然要人工修，一修「推导」的前提就废了，留下一套半推导半手改、没人知道哪些是哪些的值。按 ADR-0003 的纪律：待建能力登记，不顺手做。

## 仍然守不住的

**成对构词法只靠文档守。** 「每个 surface 名都有对应 `-foreground`」这条没有断言在守，因为它在借来的名单上就会报假阳——`destructive` 在 shadcn 自己的清单里就没有配对项。于是决定三里的构词法是**这份 ADR 里唯一一条没有机检的规则**。

写下来是因为本仓库的信条是「注释拦不住第三次，断言能」。这里确实没有那条断言，不能装作有。

**「这套名单适不适合这个项目」判不了。** 机检只能核对名字在不在表里，核不了这套词汇对这个产品是否合适。靠 eval 或人看，判不了就说判不了。

**跨技术栈同名这件事本身没有测试。** 这是采用外部命名的**唯一理由**，而没有任何一条判据在验它。起草时以为 `greenfield-mobile`（React Native）能当试金石——查了产物才发现那个用例根本不产 `design.md`，也不产 token。新的 `greenfield-originate` 用的是 React，也就是这套命名的原生环境，验不出跨栈。要真验它，需要一个非 React 的 0-1 用例；而 `ui-contract-assets` 这一版明写「React 之外的技术栈」不在范围内，所以那个用例现在会因为无关的原因失败。**先记下来，不硬凑。**

## 复议条件

| 决策 | 什么条件下复议 |
|---|---|
| **借用外部命名** | 若实测多数项目在声明表里写了大量「故意偏离」，说明这套名单不适配本 plugin 的用户群，应退回「只带构词法」 |
| **借 shadcn 而非别家** | 若 shadcn 改名或弃用清单中的 token，声明表的「遵循哪套」一栏需要带版本号；改动频繁到需要跟版本，说明不该借活跃演进中的项目 |
| **冻结度 🌡** | 若实测显示 warn 档完全没有人看（声明表长期与实际引用不符而无人修），说明 warn 不足以承载它，届时才考虑升 🔒 |
| **跨技术栈同名的收益** | 目前**无人验证**（见上）。等资产层支持第二个技术栈时，第一件事就是量它：若同名传不到值上，触发的不是本条的复议，而是 **ADR-0001 决定 A 的复议条件** |
| **`align` 只记录** | 若实测显示治熵线项目的自定命名与借来的名单差异大到声明表失去意义（整张表都是「故意偏离」），说明声明表对 `align` 分支不成立 |
