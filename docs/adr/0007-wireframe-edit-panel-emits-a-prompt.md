# ADR-0007 · 线框的换肤预览可编辑，并以自然语言提示词交出改动

> 本 ADR 记录**为什么这么选、排除了什么、什么条件下复议**。规则落地后住 `ui-contract-wireframe`，本文件只指向，不复述。

---

## 背景

ADR-0006 给线框加了换肤预览，**只读**。看完立刻出现的问题是：看到不对的地方，改不了——得回到器具，而器具里看不见这个产品的真实 IA，正是 ADR-0006 认定只有线框能给的那件事。于是「发现问题」和「调整」被切在两个工具里，中间隔着一次上下文切换。

**器具不能因此被删。** 这一条是查出来的，不是权衡出来的：编排层的 0-1 线是 `layout → design → assets → wireframe`，`originate` 跑在 **design** 那一步，**那时线框还不存在**。删掉器具，`originate` 就没有可拧的东西，而「先选方向再拧值」是 ADR-0001 决定 B 的顺序。

所以这不是取代，是**同一个编辑动作出现在两个时点**。

---

## 决策

> **线框的换肤预览可编辑；改动以「自然语言提示词 + 精确旧值→新值」交出，线框不写任何文件。**

| | 器具（design 阶段） | 线框（wireframe 阶段） |
|---|---|---|
| 那时存在吗 | 是（线框还没建） | 是 |
| 看到的 | 通用控件样张 | **这个产品的真实 IA** |
| 编辑 | 是 | 是 |
| 产物 | `tokens.input.json`（**JSON 的唯一写者**） | 一段提示词，交给 agent |
| 存值 | 否 | 否 |

**`tokens.input.json` 只有器具一个写者**，所以两个编辑器同时开着也不会互相覆盖——不需要为写冲突定规矩，因为不存在写冲突。这是本决定的一个副产品，不是它的理由。

### 提示词必须带精确的旧值→新值

不是「把 primary 调深一点」，而是：

```
primary   oklch(0.47 0.15 258)  →  oklch(0.40 0.15 258)
radius    0.75rem               →  0.5rem
```

仍然是自然语言、仍然交给 agent，但 agent 应用它是**确定性的**，产出的 JSON diff 依然有意义。这半步把下面那条已知代价压到最小。

提示词里的名字是 **token 名**（来自 `design.md` 的声明表），不是线框内部的 `--wire-*` 角色名——agent 要改的是 `tokens.input.json`，它的键是 token 名。

### 提示词不许捏造改动

**同一个颜色的不同记法不算改动。** 这条是实测撞出来的：原生颜色选择器只要被打开再关上，就会把 `oklch(0.47 0.15 258)` 重写成 `#1a57ad`——**同一个颜色，不同记法**。不判这一条的话，提示词会报一处用户从没做过的改动，而 agent 照做的后果是**把整个项目的色彩空间悄悄换成十六进制**。

判据是「解析成同一个颜色就算没改」，非颜色（圆角、长度）退回字符串比较。面板上的 dirty 标记和提示词里的清单**共用同一个判断**——两处各判一次，迟早会出现「面板说改了、提示词说没改」。

**一份会捏造改动的提示词比没有提示词更坏。** 这是本决定唯一一个不能出错的地方：整条链上，提示词是用户意图的全部载体。

### 编辑面板是控制面，不跟皮肤走

按 ADR-0006 已经定下的那条规则：凡是用来控制或解读线框的界面，都必须在任何皮肤下可读。面板住在模板的 `INSPECT CHROME` 块里，带固定色。

---

## 已知代价，接受了

**改动无法用 diff 验证。** issue #11 排除这条方案时给的理由是「在单一值权威前面加一层歧义，结果无法用 diff 验证」。那条理由**没有消失**，只是被压小了：

- 当时排除的是**用提示词取代 JSON**（器具的输出）。现在 JSON 仍然存在、仍归器具，提示词是另一个工具的另一种输出。
- 带上精确旧值→新值之后，agent 的应用是确定性的，`tokens.input.json` 的两次修订之间仍然可以 diff。

**剩下的真损失**：从「线框里拧」到「JSON 变了」之间多了一个 agent，那一跳没有记录。ADR-0001 决定 B 挂的复议条件是「实测生成品牌被用户推翻的比例」，数据源是 v1↔最终版的 diff；**经由提示词的那部分改动，在这份 diff 里看不出是用户拧的还是 agent 理解偏了**。

这是用户在代价被摆明之后仍然选的路径，记在这里，不是为了将来翻旧账，是为了复议时知道该去量什么。

## 排除的方案

| 方案 | 为什么不 |
|---|---|
| **线框只读，回器具改**（ADR-0006 的现状） | 「发现问题」和「调整」切在两个工具里，而只有线框看得见真实 IA |
| **线框直接写 `tokens.input.json`** | 两个写者，后写者赢，且没人知道哪份是当前的。要写就得定冲突规则，而不定规则这件事本仓库已经不信任 |
| **线框直接写 token 文件** | token 文件是值权威，写它是 `ui-contract-assets` 的职责；让一次性产物改值权威，等于拆掉 ADR-0001 决定 A 的分层 |
| **dev server 插件写盘** | 线框从只读消费者变成会写产品树的东西，且只在 dev 下有效、build 后静默失效 |
| **废掉器具** | `originate` 跑在 design 步，那时线框不存在（见背景） |
| **器具用 iframe 内嵌线框** | design 阶段又回到没样张可看；且检查 6 禁止跨包引用 |
| **提示词不带精确值，只写意图** | 应用不确定，JSON 的 diff 随之失去意义 |

---

## 仍然守不住的

**面板里改了什么，没有任何东西记得。** 线框不存值、不写盘，重开即失。用户拧完不复制提示词就走，改动没了，且没有痕迹。

这是「不存值」的直接后果，接受它是因为反面更坏：一个会存值的线框就是第二个值权威。

**颜色转换的代码在器具和线框各有一份。** 两者一个是 HTML 模板、一个是 tsx 模板，分属两个包，而检查 6 禁止跨包引用——**在代码层面根本无法共享**。与对比度阈值同一个形状：能共享的只有磁盘上那份 `design.md`。两份实现若行为分家，症状是同一套值在两个工具里显示不同，且不会有任何东西报错。

## 复议条件

| 决策 | 什么条件下复议 |
|---|---|
| **以提示词交出改动** | 若实测显示 agent 误解提示词的比例不可忽略（应用后的 JSON 与面板里显示的值对不上），说明这一跳的歧义不是理论问题，应改回导出 JSON 并为写冲突定规则 |
| **器具与线框并存** | 沿用 ADR-0006 该行：若长期只有一个被用，并成一个 |
| **线框不写盘** | 若「拧完忘记复制」成为常见抱怨，说明不存值的代价落在了用户身上，届时考虑 dev-only 的写回，并接受它 build 后失效 |
| **两份颜色转换** | 若两边对同一个值给出不同结果被实际观察到，说明这份重复必须靠夹具对账，而不是靠两边各自写对 |
