> 本 ADR 记录**为什么这么选、排除了什么、什么条件下复议**。派生规则住 `originate.md` Step 2，本文件只指向，不复述。

## 背景

ADR-0001 把品牌生成推给了 `frontend-design`，理由是「品牌生成是本 plugin **唯一需要产生审美**的地方，也是最容易退化成『又一套 Tailwind 默认蓝』的地方」。这个理由今天依然成立 —— 变的是对代价的认识。

**那个技能不在本插件里**（`ls skills/ | grep frontend-design` = 0），住在 `claude-plugins-official`。装 `ui-contract` 不会带上它。这件事写在 `originate.md` 正文一句话里，不在任何前置门、不在 `plugin.json`，**十五个月里没有任何机制在看它**。

2026-08-22 查 `tokens.input.json` 落地率时撞上了它。从 `--keep-temp` 保留的沙箱量到，缺失时的行为**不是失败，是分叉**：

| 沙箱 | 调不到之后做了什么 | 产物 |
|---|---|---|
| `32EmmT` | 自己把值派生了出来 | `tokens.input.json` ✓ |
| `W46Nj9` | 推到「下一轮」，并把这个决定写进交付物的 caveat 表 | ✗ |

两次都在 trace 里提到了那个技能、都没调到，应对完全相反。失败那次还宣布了完工：「两份规范和配置文件都已写完，干净无字面数值」。**两份产物从外面看都像正常完整的交付物。**

issue #6 第 10 笔追了两轮、花了约 $11 想量清楚 `tokens.input.json` 的落地率在 40% 到 87% 之间到底是多少。**那个比例不是一个待测的常数，是这次分叉的投影。**

## 决策

**`originate` Step 2 自己派生值。移除对 `frontend-design` 的调用。**

不是「拷一份进来」，是**不再需要那一步**：本插件写自己的派生规则，不 fork 别人的技能。

### 派生规则的形状：可追溯，不是有品味

这一条是本 ADR 的实质。**「产生审美」这件事被换成了「产生可追溯的值」**，因为后者是这个插件擅长的形状，也是唯一能被检查的形状。

Step 1 的访谈已经产出了三条轴上的坐标，而轴表本来就写明每条轴管哪一组 token。派生就是**反着读那张表**：每个值必须能回指到一个坐标。

**判据是它的否定式**：默认值不是「不好看的值」，是**没有理由就出现的值**。同一个点派生两次应当落得很近，不同的点派生出来必须不一样。

### 色相：轴不管的那一格，也正是默认蓝的入口

这是移除依赖时才看清的东西，写下来因为它比依赖本身更根本。

三条轴里第三条管的是颜色的**数量**与**饱和度**，**没有一条管色相**。Step 1 又明确规定用户只在属性上选、不在颜色上选，所以访谈也不会给出色相。

**色相是整套值里唯一没有约束源的那个** —— 默认蓝不是模型偷懒，是它在填一个本来就空着的格子。`frontend-design` 顶的正是这一格。

补法是**给出依据，而不是给出偏好**：色相必须从这个产品身上某件说得出名字的事推出来（已有资产 / 顺着行业惯例 / 刻意逆着行业惯例 / 避开身边产品的同色），并把依据写进 `design.md` §1。四条都不适用时，**明说没有依据、并把色相标成整套值里最弱的一个** —— 那是诚实的，而且它告诉用户 Step 3 该先动哪个旋钮。

### 加一条机检的黑名单

`originate.md` 列出常见框架的默认色值（Tailwind blue/indigo/sky、Bootstrap primary、Material blue）。派生真落在上面时要挪开。

⚠ **这条只能拦已知的那几个值**，拦不住「换个色号的默认感」。它的作用不是保证好看，是**让『坐标没走到值』这件事留下痕迹**。

## 排除的方案

| 方案 | 为什么不 |
|---|---|
| 保持现状，只在 README 写明软依赖 | 用户被告知了，**agent 的行为没变**。那个沉默的分叉原样留着，而它正是这次要修的东西 |
| 把 `frontend-design` 拷进 `skills/` | 那不是复用也不是自造，是 fork 一个别人还在维护的东西。它会过期，而本仓库对「会说谎的第二份拷贝」的立场是全篇最硬的一条 |
| 写进 `plugin.json` 的 `dependencies` | **官方机制在这里不通**：跨 marketplace 依赖默认被禁，开关 `allowCrossMarketplaceDependenciesOn` 在**根 marketplace** 手里，不是插件作者能设的。而且 15 个包里 14 个不碰它，硬依赖会为一个多数 run 用不到的步骤卡住整个插件 |
| 在 `originate.md` 里写「有就调，没有就自己派生」两条分支 | 比现状好，但留着两条路就留着两种产物。而且首选那条路对多数用户从不发生——写一条大多数人走不到的分支，是把复杂度留给读文档的人 |
| 保留调用，但加前置门「没装就停」 | 把一个多数用户装不到的东西变成硬门槛。ADR-0003 的拆包理由之一是「能力可复用」，绑在别人的插件上与之相悖 |

## 已知代价，接受了

**本插件现在会产生审美了。** ADR-0001 那句「唯一需要产生审美的地方」不再是被推出去的，是被留下来的。这是真代价，不假装它不存在。

抵消它的是三件，全部可检查而不是承诺：

1. **可追溯** —— 值必须回指到坐标，「好看」不是理由。
2. **色相依据要写进产物** —— 这一格最弱，而它被明确标成最弱。
3. **一个已知默认值的黑名单** —— 拦不住全部，但拦得住原样照抄。

这三件都进了 `## Before you call this document done` 清单。同一批 run 里量到过：**进清单的落地 5/5，只在正文被描述的落地 2/5**（n 很小，这个相关性本身也还没被验证，记在 issue #6）。

**仍然守不住的**：换个色号的「默认感」。机检拦不了，Step 3 的用户调校是唯一的兜底 —— 而那正是 `originate` 把器具放在派生之后的原因。

## 连带影响

- **不变量 28**：`Call the Skill tool with "X"` 里的 X 必须是 `skills/` 下真实存在的包。判据是闭集，锚点是磁盘（与不变量 1、25 同源）。它守的不是这一次的改动，是**下一次有人再写一句这样的散文**。两条 effectiveness 用例，其中一条就是真实发生过的那种写法。
- **README 删掉了软依赖那一节**（2026-08-22 加的，同日删）。依赖不存在了，那节就成了假话。
- **issue #6 第 10 笔（落地率）要重估**：此前测的是分叉的投影，不是一个常数。修复之后再量才有意义，此前的 2/5、7/8 都作废。
- **`greenfield-originate` 的判据**没动。`tokens-input-written` 已双向验过，它照常能测这次改动有没有用。

## 定案当天实跑两轮，改了两处（$6.19 / 6 次 run）

本 ADR 的三条替代措施——可追溯、色相依据、默认色黑名单——定案时**全是文本，一次没跑过**。
当天跑了两轮，结果是：**主张成立，配套的两件事错了，各自被数据改掉。**

### 一、`tokens.input.json` 的落点：从「可配置」改成「钉死」

第一轮量到三次 run 把文件写在两个不同位置（仓库根 / `docs/ui-contract/`），
**三次都讲得通，因为产品从未说过**。当时的修法是「把落点写进 `config.md` 的路径表」。

第二轮量到：**没用。** 仍然两次 `docs/ui-contract/`、一次根目录。
**写下选择让它可见，不让它变成同一个选择。**

所以钉死在 `docs/ui-contract/tokens.input.json`。这是全插件唯一不走可配置路径表的产物，
理由是它不是规范而是**工作记录**，和 `config.md` 同一个抽屉。`ui-contract-assets` 之后
要读它，判据现在要读它，两边都需要一个答案而不是一个记录。

### 二、色相依据撞上了「`design.md` 里不许有字面值」

第一轮 2/3 挂在 `no-literal-values-in-design`——一条此前稳定通过的判据。成因是本 ADR 加的
「色相依据必须写进 `design.md` §1」：**说明依据几乎必然要提到具体颜色**。其中一份写的是
「比 Tailwind blue-500（`#3b82f6`）更深更钝」——**它在认真执行黑名单，方式是点名那个默认色
说自己没用**，于是撞上了另一条规矩。

两条规矩互相打架，而加第二条时没查第一条。改成「用词语或 token 名说明，值留在
`tokens.input.json`」，第二轮 3/3 通过，产物里真的照做了。

### 三、`hue-basis-stated` 判据当天加、当天删

为验色相依据加的 llm 判据，两轮各 1/3，而**六份产物人工核对全部合格**。
它区分不开合格与不合格，只是随文件长度（9k–17k 字）随机翻面。
按 `testing/evals/README.md` 第 13 条删掉，与 `decision-tree-total` 同一处理。

**后果写明**：色相依据从此没有机检守着，与追踪质量同档。本 ADR 的三条措施里，
现在只有黑名单和「值必须落盘」有判据在守，**可追溯与色相依据两条靠评审**。

## 复议条件

| 条件 | 怎么处理 |
|---|---|
| `frontend-design` 进了 Claude Code 内建技能集（沙箱可见技能里出现它） | 依赖不再需要用户单独安装，可以重新考虑委托——但要**先量**再改：分叉的成本已经付过一次 |
| 跨 marketplace 依赖不再默认被禁 | 同上，`plugin.json` 的 `dependencies` 那条路才真正可用 |
| 实跑显示自己派生的值系统性地退化成默认感 | 说明「可追溯」这个替代方案不够。方向不是加回依赖，是**把色相依据从「写下来」升级成「必须在访谈里被问」**——那要改 Step 1，且违反「用户不在颜色上选」，是更大的一次翻案 |
| 色相依据那四条被发现总是落到同一条 | 说明那不是四个选项而是一个借口。要么砍到实际在用的那几条，要么承认色相就是要问用户 |
