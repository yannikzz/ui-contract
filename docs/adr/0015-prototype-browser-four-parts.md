## 背景：装置层没有落位规则，而这个方法的全部内容就是落位规则

线框的装置——区域标注、换肤横幅、编辑器、演示开关——在 ADR-0012 之后有了**颜色**的规则
（豁免是一个文件，导出是封闭名单），但一直没有**落位**的规则。`implementation.md` 对面板
只写了一张「至少要有」的清单：页型开关、状态开关、宽度档、标注、换肤、方向、编辑器、读数行。
清单是下界，不是判据：**第十个开关往哪放、七个 Group 按什么顺序排，由 agent 现场决定。**
示例产物里它自排了 7 个 Group；换一个项目就是另一种排法。

2026-09-15 的一次评审把这件事摆到了台面上：开源推广需要一份「看起来不错」的呈现，第一反应是
把控制台做精致。但精致解决不了不一致——**不一致的来源是每次都有人在挑，不是挑得不好看。**
而这个插件对产品界面开的方子正是治这个的：区域名单、每个区域写明禁止放什么、一棵全函数的
落位决策树。这次把同一张方子用在它自己的装置上。

评审里还带出一个更大的请求：一个无限画布，把所有页面铺开、用箭头连成流程图。
这一条撞在 ADR-0013 最承重的那句话上——**线框不许含有任何在 `layout.md` 里没有条款的东西**——
而 `layout.md` 里没有「屏与屏之间怎么走」这个概念（它回答的是「一个功能放哪」）。
箭头就是没有条款的东西。这个请求怎么落，是本记录的决策四。

## 决策一：浏览器分四个部位，落位判据只有一条

| 部位 | 是什么 | 放什么 |
|---|---|---|
| **视口** | 浅灰圆角的那块；原型和样张墙都在它里面 | 被观察的东西 |
| **角落** | 视口内的左下、右下 | **作用在视口上**的控制：视图切换、镜头缩放、适应窗口、画布底色 |
| **面板** | 视口右侧、在视口**外面**、白底 | **作用在原型上**的控制：页型、宽度档、状态、标注、换肤、方向、编辑器；以及读数块 |
| **墙** | 视口内的第二种视图 | 页型 × 状态 × 宽度档的样张，见决策四 |

判据：**它改变的是「怎么看」→ 角落；它改变的是「看什么」→ 面板。** 全函数，每个新控件都能落到
唯一一处。**唯一的、封闭的例外**是面板自身的收起/展开：它是操作，但它必须常驻可见，否则没有入口。

**没有顶部条。** 评审中曾选定「顶部只读薄条 + 侧边面板」，做出预览后被否决：一条只展示信息的
常驻条，换不来它吃掉的垂直空间。原规则「面板不固定在顶部」的理由——线框的职责之一是展示真实
密度，顶上常驻一条会扭曲「一屏放几行」——**原样保留**，只是从「禁止顶栏」变成了「没有顶栏」。
读数进面板，成为固定在四区之上的读数块。

## 决策二：面板分四区，按「它改变什么」，顺序固定，空区不渲染

| 区 | 改变的是 | 例 |
|---|---|---|
| 选屏 | 看哪一页 | 页型、向导步 |
| 条件 | 在什么环境下看 | 宽度档、导航偏好、数据态、面板态、覆盖层 |
| 视图 | 怎么看（但作用在原型上，不是视口上） | 区域标注、换肤预览 |
| 输出 | **唯一会流回项目的** | 方向切换、token 编辑器（ADR-0007） |

顺序由容器排，不由 agent 排：`Zone` 必须声明自己属于哪个区，区是封闭联合类型，`Panel` 按固定
顺序摆放。**agent 连排错的机会都没有。** 输出区在视觉上隔开，因为它和其余三区性质不同——其余
全是纯观察，刷新即失；它的产出会去改 `tokens.input.json`。

区标题只有两个字，没有副标题。评审要求信息降噪。

## 决策三：选择器的形状是数据的函数，agent 不选

布尔 → 开关；≤ 4 个互斥项 → 分段控件；≥ 5 项 → 下拉。一个 `Choice` 组件，agent 只给数据。
理由和决策二相同：**可以挑，就是不一致的入口。** 页型有十种时它会变成下拉，把其它页藏起来——
这是知道的代价，见下；而且十种页型本身就是 `layout.md` §5.4 明文要防的膨胀。

## 决策四：样张墙投影 §4 × §8 × §3.4，不画箭头

墙上是每个页型 × 每种非常态 × 每档宽度，一次铺开。**三个维度今天都在 `layout.md` 里**——
页型模板、非常态落位、降级的宽度档——所以墙是那三节的投影，零发明。它回答的问题是逐页切换
给不了的：**结构在所有页面上同时成立吗**；打开换肤或切换方向时，**这个决定在每个页型上长什么样**。

**箭头没有源，所以没有箭头。** 要画流程图，先给 `layout.md` 加一节导航流程——那是扩大结构规范
的边界，要复议 ADR-0003，不是本记录的事。在那之前，墙上任何一条连线都是线框在发明结构，
下一个 agent 会照着它改代码，那时画布就成了事实上的规范。

墙模式下，选屏和条件两区不渲染——它们成了墙的坐标轴；视图和输出作用在所有样张上；读数块隐藏，
因为没有「当前」一屏。

## 决策五：镜头不是宽度

视口有一个镜头：触控板捏合与 ⌘+滚轮**在两种视图里都以光标为锚**缩放画布（拦下浏览器的页面缩放），
角落按钮以视口中心为锚；墙模式下按住拖动平移；画布不显示滚动条。**静止时原型两轴居中**——
手机宽度档的原型落在视口正中而不是顶上，放大到超出视口后从左上角起可滚动，锚点按元素重绘后的
实际位置修正，所以从居中退成顶对齐那一刻不跳。评审第二次看预览时提的：视口中心与原型中心重叠，
缩放才有一个自然的准心。镜头在原型模式也开放，理由是 1440 的笔记本减去面板
放不下 1280 档，不缩放只能截断。

由此一条硬规则：**实测宽只从布局读（`offsetWidth` / `ResizeObserver` 的 `contentRect`），
永远不从视觉矩形除以倍率反推；镜头不做过渡动画。** 这是评审里实测出来的：第一版给镜头加了
0.15s 过渡，读数从 `getBoundingClientRect().width / zoom` 反推，于是每次捏合都在上一次动画
走到一半时量，「外壳实测」跟着抖，降级判定跟着翻。它和「降级按实测宽不按视口断点」是同一个
原则的两面：**被量的是布局，不是像素。**

## 决策六：白页、灰视口、白原型；控制台浅色，豁免一字不改

页面白底 → 视口浅灰圆角 → 原型白色；面板在视口外的白底上，和视口之间不画线，分界由灰底给出。
控制台从深色换成浅色，但**固定色的规则不变**：装置不跟随皮肤，豁免仍是 `inspect.tsx` 这一个文件。
换肤横幅仍在面板之外、不可折叠——它现在横在视口上方。

## 排除的备选

| 排除的 | 为什么 |
|---|---|
| **顶部只读薄条**（评审中一度选定） | 只展示信息的常驻条不值它吃掉的垂直空间；所有控制放右侧后，顶部没有存在理由。预览做出来看过一眼就撤了 |
| **带箭头的流程图，`layout.md` 先加一节** | 方法上正确，但它扩大的是结构规范的边界（ADR-0003 的包边界要复议），访谈单元、判据、示例全部要跟。本轮不做，路留着 |
| **带箭头，箭头写在输入记录里**（fixtures 那一层） | 流程是结构不是内容。放进「输掉每一次与源的分歧」那一层，等于承认它没有源；而下一个 agent 不会去读那行免责声明 |
| **按使用频率分派角落/面板** | 「高频」没法用类型锁住，每个 agent 估得不一样，一致性回到靠自觉 |
| **给 agent 一套控件库自己挑** | 散文对 agent 的约束力在本仓库被实测证伪过（ADR-0013 背景）；「可以挑」本身就是不一致的入口 |
| **原型本身的深色版** | 那是第二套 NEUTRAL 灰阶，属于被观察的东西。「明暗」本轮只指画布底色 |
| **跨页点击跳转** | 和箭头同一个根：流程没有源。「clicking does nothing」留在刻意取舍清单里 |
| **示例整体按新决策树重排** | `examples/README.md` 唯一的规则是 never edit this to *look* right。装置层跟进有先例（`inspect.tsx` 已在 Regenerated 那一栏），排布重排没有——它是原始运行的产物 |

## 知道要付的代价

1. **墙要求外壳是一个纯组件，宽度是它的 prop。** 原型视图喂它 `ResizeObserver` 的读数，墙喂它
   列的宽度。示例的外壳还内联在 `App.tsx` 里带着 hooks，所以**示例没有接墙**——记在
   `examples/README.md` 的落后表里。它和 `structure.ts` 借住线框的那个倒挂同源：
   `Shell` 落进资产层的那天，两件一起搬。
2. **角落是封闭集。** 一个项目要加视口级的控制，得改豁免文件并加进 `APPARATUS:` 名单。
   这是刻意的：角落里多一个东西，diff 里就有一行。
3. **≥ 5 项变下拉，会把其它选项藏起来。** 页型是最常切的开关，十种页型时要两次点击。
   接受，因为「少即是多」是这次评审的明确要求，而十种页型本身是个警报。
4. **三件事没有机械守卫，今天是知情的选择：**
   - 「实测宽只从布局读」——它是一行代码的写法，类型抓不到，`check-colours.sh` 不管这个。
   - 「墙不画箭头」——没有任何东西比对墙上的东西和 `layout.md` 的条款。
   - `Panel` 只接受 `Zone`——TypeScript 的 JSX children 判不了组件身份，这一条在运行时抛错，
     不在编译期。
   三条都是 review 项，写在这里而不是暗示。

## 复议条件

- **页型 ≥ 5 成为常态**（连续几个项目都是）→ 决策三里「≥ 5 → 下拉」换成「≥ 5 → 竖排列表」，
  仍是数据的函数，只是不藏选项。
- **有人要在墙上画箭头** → 从 `layout.md` 开始，不从线框开始：先复议 ADR-0003，给结构规范
  加导航流程一节，访谈单元跟上，然后墙才能投影它。
- **`Shell` 落进资产层** → 代价 1 兑现，墙的样张渲染跟着搬，示例的落后行同时销掉。
- **实测出「实测宽从视觉矩形反推」再次出现在产物里** → 代价 4 第一条要从 review 项升级为
  `check-colours.sh` 的一条检查（锚：`getBoundingClientRect` 与 `zoom` 同行）。
