## 背景：仓库要以 MIT 公开，而这份文件不是我们的

PR #24 给仓库挂上了 MIT。`docs/reference/plugin-eval.md` 是从 `claude` CLI 二进制里**逐字提取**的
Anthropic 文档——ADR-0008 当时刻意选了逐字、不编辑，这正是它可信的原因，也正是现在的问题：
版权在 Anthropic，本仓库无权用 MIT 把它授权出去，而公开仓库本身就是分发。

私有阶段这件事不显形，因为没有任何东西离开过仓库。

## 决策一：同一路径，本地生成，不提交

`docs/reference/plugin-eval.md` 进 `.gitignore`，`EXTRACT.md` 改为直接写到这个路径。
所有指向它的地方——`CLAUDE.md`、`README.md`、`testing/preflight.sh`、`testing/evals/README.md`——
**路径不变**，只多一句「本地没有就先提取」。本机开发的体验和以前一样；新 clone 多一步，
且需要 Python 3.14+（标准库 `compression.zstd`）。

**落地时发现提取步骤早就坏了。** `EXTRACT.md` 按 2.1.238 写，而最晚到 2.1.288 文档已经改成 zstd
压缩的内嵌文件，`strings` 搜不到——`N` 为空，脚本却照样写出一个 182 字节的垃圾文件。仓库里
躺着一份能用的拷贝，所以没有人需要去跑它，坏了也没人知道。不提交之后它成了唯一的来源，于是
重写为解压 zstd 帧，并且找不到恰好一份时直接失败。这正是 `CLAUDE.md` 说的那类失效：输出看起来
没问题（文件就在那），机制早就不工作了。

代价：fresh clone 上不变量 27 会对 ADR-0008 与本文件里的这个路径打 warn。这是预期内的——
那个路径在提取之前确实不存在，而 warn 本来就是为「过期要看得见」设计的，不判失败。

## 决策二：公开仓库用清理过的历史新建，原仓库留作私有存档

只把文件从 HEAD 删掉不够：它从 2026-08-21（`Consolidate the tests into testing/…`）起一直在历史里。

| | 怎么做 | 为什么 |
|---|---|---|
| 原仓库 | 改名 `ui-contract-private`，保持私有 | PR #1–#24 的讨论、#24 里协议的书面同意都在这里，不丢 |
| 公开仓库 | 新建 `ui-contract`，推入用 `git filter-repo` 删掉这一个文件后的历史 | 新仓库**从来没有过**这份文件 |

所有提交、作者与日期保留——共同作者的署名（PR #24）靠的正是这份历史。提交哈希全部改变；
动手前查过，仓库里的文档没有写死任何提交哈希。

## 排除的方案

| 方案 | 为什么不 |
|---|---|
| 原仓库改写历史 + 强推，然后直接公开 | GitHub 为每个 PR 永久保留 `refs/pull/N/head`，强推覆盖不到；14 个 PR 的快照里仍有这份文件，只能等 GitHub 客服人工清理。新建仓库一步到位 |
| 只从 HEAD 删除，不动历史 | 历史随仓库一起公开，等于照样分发 |
| 改写成自己的摘要提交进来 | 等于自己维护第二份文档，CLI 一升级就悄悄过期——ADR-0008 选逐字提取，正是为了不靠猜 |
| 整个历史压成一个提交再公开 | 丢掉每一行是谁写的，共同作者的署名失去依据 |

## 后果：公开仓库里的 `#N` 指向私有存档

提交标题里的 `(#N)`、ADR 里的「PR #13」「issue #6」，在公开仓库里会被 GitHub 自动链接到**新仓库的**
同号 issue/PR——它们要么不存在，要么是将来某个无关的条目。**本仓库 2026-10-11 之前文档与提交里
出现的 `#N`，一律指 `ui-contract-private` 里的同号条目。** 已接受的记录不编辑，这句话就是更正。

## 复议条件

- Anthropic 为 `plugin eval` 发布公开文档页 → `EXTRACT.md` 换成一个链接，本地提取退役
- 这份文档出现允许再分发的许可 → 可以重新 vendor，同时撤销本文件决策一
