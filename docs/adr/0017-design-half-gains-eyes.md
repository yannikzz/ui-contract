## 决定

设计半场此前只验证**决策一致性**（值溯源到坐标、hue 有 basis、框架默认黑名单、对比度实时判），
渲染出来的面从未被看过。补四件事，全部落在 `ui-contract-design`：

1. **视觉基线**：调校会话收尾时，从穿着最终皮肤的原型浏览器（复用 ADR-0006/0015 的渲染，
   不新造渲染机器）固定截取一组证据——原型墙整帧、480px 缩略、两个最密控件的 200% 局部——
   路径记进 `design.md` §1。
2. **三秒检验**：主 agent 对着自己的 480px 截图看三秒，写两句话（像哪一年的哪类产品；
   第一眼落在什么、是否本品类通用）。
3. **一回合无上下文评审**：一个评审者只看基线和 §1 的方向句 + 签名处理，回报幸存或漂移；
   结论写回 §1。🌡 因此有了验证步——但一轮评审是证据，不是真实用户， Survived 不升 🔒。
4. **拆标杆进访谈**：三点给出前，拆两三份**真实**品类参照（6–10 条可见要素，各带为什么），
   记进 §1 的标杆与取舍行；换产品检验与撞脸检查改对着它跑，不再跑思想实验。

随行的两条规则级补充（复用既有模式，不另立机制）：**模糊词翻译表**（美学形容词必须翻译成
它移动的 token 组和一个可观察决定，落点是器具现成的滑杆——costs 表的用户侧对偶）；**§8 动效
的 basis 机制**（动效值无坐标，必须写明来源——产品状态机节奏 / 宿主平台惯例 / 从签名处理派生 /
显式弃权标注最弱值——这是 hue 的模式搬到第三个 token 组，不是第四轴）。

## 为什么

这套方法的心跳是「每个值都被某个东西强制」；但心跳只覆盖推导侧。渲染面是链条上唯一没有
instrument 的一环：调校会话只动滑杆，没有人回头看结果是否还是 §1 那个方向，也没有任何
输出能暴露这一点——正是本 plugin 到处猎杀的「输出上看不出来」的失效形态，出现在自己的
设计半场。同品类对标（oil-oil/oil-ui，1400★）的整个产品就建立在这条证据链上，其评审手册的
三秒测试 / 遮字 / 200% 检验是可直接借用的判据形态；而本 plugin 的决策可溯源、值权威、
编译期强制是对面没有的，两个半场互补，不构成方向变更。

## 排除了什么

- **渲染完整产品页**：基线只截原型浏览器。整页渲染发生在用户项目里，不是本 plugin 的交付物。
- **audit 新增编号检查**：体检脚本加视觉检查要动 check 编号和模板，本轮不做；基线先作为
  参照物存在于 §1，audit 何时消费它见复议条件。
- **动效第四轴**：`originate.md` 写死「Do not add a fourth axis」。动效缺口用 basis 机制闭合
  （hue 的模式），坐标化动效的提案才是需要新 ADR 的那件事。
- **器具/模板里造截图功能**：截屏由宿主的看图/截图能力完成，`theme-studio` 与 wireframe
  模板零依赖的约束不动。
- **评审不打分**：oil-ui 的 10 分制锚点没搬。这里只要「幸存/漂移 + 点名位置」，分数留给
  未来的 gate 3 量具去发明，不进用户交付物。

## 代价

每个 originate 会话多一次 sub-agent 运行（评审回合）和三张截图的取证成本；三个方向的
访谈多一份拆标杆的前置工作。粗看省掉这些的诱惑是真实的——所以「跳过一次并写明
not reviewed」是合法出口，静默跳过不是。

## 复议条件

- gate 3 若为评审回合造出固定量具（无上下文评审者的判据能区分幸存/漂移），评审回合从
  skill 规则升格为带 grader 的强制步；
- audit 若开始消费视觉基线（比对当前实现截图与 §1 基线），本轮「基线只是参照物」的定位
  由新 ADR 取代；
- 模糊词翻译表与 §8 的 basis 机制若在实测中频繁指向同一个缺失 token 组（动效），就是
  重新讨论动效坐标化的时机——带着新 ADR 来。
